# BrickAtlas 下一阶段计划与 Constructibility-1 实施报告

日期：2026-09-15。版本：`brickatlas-constructibility-1`。

## 1. 从调研得到的核心判断

双源调研列出的多数空白并不适合并列堆成更多任务。对 BrickAtlas 最重要、最可形成
统一论文问题的空白是：

> **从合法终态转向可恢复的施工过程：模型能否在有限观测和有限资源下，给出每个前缀
> 都满足离散几何、支撑和工具净空约束的计划，并在计划受阻后以最小代价恢复和继续？**

现有工作已经充分覆盖零件识别、定性空间关系、最终碰撞/连通、下一步预测和静态终态
稳定性。仅仅增加这些题目的数量不能形成新的 benchmark 贡献。以下五项共同构成更关键
且相对欠覆盖的能力链：

1. **Prefix Support**：不是只看最终结构，而是逐步验证每个施工前缀。
2. **Accessibility**：砖体能到目标位姿还不够，释放工具也必须有净空。
3. **Recoverability**：检测首个失败，最小回滚，恢复后继续，而非推倒重来。
4. **Resource Adaptation**：施工中缺货时，用有限库存保持目标占据和后续可执行性。
5. **Calibrated Clarification**：证据不足时保留可行集、正确弃答，并选择高信息量检查。

因此本阶段不把功能/运动学、真实承重、磨损和机器人抓取硬塞入当前网格引擎。它们很
关键，但若无机构件库、标定物理和连续运动规划，加入标签只会制造不可信的“能力覆盖”。

## 2. 核心定义

本版本把过程可搭性定义为一个可诊断向量，而不是容易掩盖失败的加权总分：

`C = (G, P, A, R, U)`

- `G`：目标和动作的离散几何合法性；
- `P`：每个已执行前缀的直接支撑有效性；
- `A`：砖体竖直通道和一侧一 stud 工具释放净空；
- `R`：失败检测、最小合法回滚和恢复后继续；
- `U`：有限候选世界下的后验、弃答和下一检查决策。

端到端 `Constructible Success` 只作合取事件：任何必要条件失败即失败。论文和榜单必须
分别报告五项及四个任务族，不能把它们平均成一个看似平滑的分数。

这里的 `P` 与 `A` 是**明确的离散代理**。它们不等于力平衡、真实抓取或人体工效。

## 3. 已实现任务

### T1 候选序列审计

- 数量：18 条，6 个源结构各含 valid、unsupported-first、clearance-dead-end。
- 输入：完整目标结构和不可改写的候选施工序列。
- 输出：首个失败下标、失败原因、合法前缀长度、是否完整可搭。
- 能力：长程序列跟踪、支撑因果、工具可达性、失败定位。
- 指标：failure-index exact、reason exact、prefix-length exact、decision exact。
- 关键对照：6 个 clearance dead-end 在旧砖体通道规则下合法，在新工具净空规则下失败。

### T2 受阻后的最小恢复并继续

- 数量：18 条，6 个源结构各 3 个位置。
- 输入：合法当前前缀、失败步骤、完整目标、后续 12 个待装 ID。
- 输出：失败诊断、带方向的 remove/place 恢复动作、恢复后的续建序列。
- 能力：错误检测、因果定位、局部返工、动作可执行性、任务续接。
- 指标：diagnosis exact、recovery exact、minimum recovery、continuation exact、联合成功。
- 约束：恢复动作必须守恒实例库存；未知、重复、不可达动作立即失败。

### T3 施工中缺货替代并继续

- 数量：6 条，每个源结构 1 条。
- 输入：当前前缀、缺货零件、有限替代库存、目标和后续施工窗口。
- 输出：替代零件及其安装方向、续建序列。
- 能力：库存约束、组合覆盖、最少件数、替代后的过程一致性。
- 指标：stock valid、region exact、minimum pieces、process exact。
- 关键对照：继续使用缺货原件不能得分；只覆盖区域但无法继续施工也不能通过。

### T4 校准式澄清或提交

- 数量：36 条，18 条仍有多解，18 条已由附加观测唯一确定。
- 输入：有限候选世界、带成本的几何扫描、已有观测、均匀先验。
- 输出：完整可行集、每个世界的后验、提交或弃答、下一查询。
- 能力：不确定性表示、避免虚假确定、主动检查、成本敏感决策。
- 指标：possible-set exact、posterior L1、decision exact、query exact、Brier、
  false certainty、unnecessary abstention。
- 查询规则：未确定时选择单位成本期望熵减最大的未观察查询；并列最优均接受。

合计 78 条条件，共用 6 个已公开 Frontier 源结构。它们是开发集，不是 78 个独立对象，
也不是独立确认集。

## 5. 发布与评分合同

- `public.json`：模型可见输入，不含 oracle 和私有世界 ID。
- `oracle-private.json`：参考答案，仅供离线评分和审计。
- `algorithm-results.json`：公开信息算法的可解性上界，不冒充学习模型结果。
- `audit.json`：数量、过程证书、捷径基线和主张边界。
- `frozen-protocol.json`：主指标、分组统计、成本和未完成实验。
- `manifest.json` / `source-manifest.json`：数据与实现哈希。

缺答、格式错误、截断、重复 ID 和未知 ID 都保留在分母。原始模型输出必须与 parser、
planner 或工具辅助结果分开保存。四个任务族分别出表；统计单位是 6 个源结构，而不是
78 个派生条件。

## 6. CVPR 对齐与硬门槛

CVPR 2027 官方规则截至本报告日期尚未发布，因此格式暂按已核验的 CVPR 2026 官方要求：
8 页正文、参考文献不限页；双盲；补充材料应自洽且不能借外链绕过评审；数据集若作为
贡献，应最迟在 camera-ready 可用；鼓励代码复现、诚实限制与计算资源报告。目标届次
发布规则后必须重新核验，不能把 2026 日期直接沿用。

对本项目，真正影响主会质量的门槛是：

| 门槛 | 当前状态 | 通过条件 |
|---|---|---|
| 清楚且重要的新问题 | 已完成 | 论文围绕过程可搭性，不再围绕任务数量 |
| 可验证任务与指标 | 已完成开发版 | oracle、反例、缺答分母和哈希全部通过 |
| 视觉相关性 | 部分完成 | 现有层图任务保留；过程任务需增加自然/遮挡多视图条件 |
| 数据代表性 | 未完成 | 新的、未参与设计的授权结构来源与冻结确认集 |
| 模型区分度 | 未完成 | 同预算的代表性 VLM/LLM、专用规划器和多 seed 实测 |
| 人类有效性 | 未完成 | 至少两名独立审核者与难度/误判校准 |
| 真实物理外推 | 未完成 | 物理求解器或实体验证；完成前只称 nominal proxy |
| 统计充分性 | 未完成 | 源对象级区间、预冻结分析和独立确认 |
| 可复现发布 | 开发版完成 | 第二环境无密钥复算收据仍需外部执行 |

CVPR 评审看重技术可靠性、知识增量、潜在影响和可复现性，不要求机械地超过某个样本数
或所有 SOTA。当前版本提高了研究问题与测量合同，但**尚未达到投稿完成状态**。

## 7. 下一阶段顺序

1. **P0 已完成：过程核心。** 冻结 T1--T4、公开求解器、评分器、捷径审计和复现命令。
2. **P0 待完成：独立数据。** 从有再分发许可的人类设计 LDraw 来源建立 100--300 个
   试生产对象；按来源/作者/套装分组去重，冻结开发、验证和确认集合。
3. **P0 待完成：视觉过程条件。** 为同一 T1--T3 生成普通多视图、遮挡和执行中间帧；
   保持符号 oracle 轨独立，做 image-swap、no-image 和坐标归一化控制。
4. **P0 待完成：基线实验。** 图搜索/约束规划器、随机/复制/固定答案、4--6 个代表性
   VLM/LLM；固定模型版本、预算和输出上限，至少 3 个种子。
5. **P0 待完成：人类与指标校准。** 双人盲审、分歧仲裁、false accept/reject、
   完成时间和主观难度；不得用模型标签代替真人。
6. **P1 待完成：物理升级。** 接入经验证的力平衡/负载求解器，报告 Prefix Stability
   和扰动生存曲线；与当前 Prefix Support 分栏，不回填旧指标。
7. **P1 待完成：功能与运动学。** 引入 hinge/axle/gear 小型受控机构集，分别评几何
   正确和功能正确；在求解器与实体验证前不进入主榜。
8. **P0 待完成：论文重写。** 主文只保留一个研究问题、三个关键发现和必要消融；
   历史 11 万条件及工程细节移至补充材料。正式实验完成后再填结果，空表不能写成零分。
