# 动态 Arena：输入、动作、观察与评估

## 2026-10-30：版本 4 的统一接口

静态与动态现在共用主动观察接口。默认 0 张图；当前＋目标合为一张双面板图，每边 800×600，外层画布 1600×636；再加指定一页库存，单轮最多 2 张。库存及候选每页最多 12 项，库存可用状态也只发所看的一页。说明书、其他角度和历史图均按需请求。旧版整包观察仅用于显式指定的历史复查。

新增“同故障现场、不同执行历史”比较：事故刚发生时复制现场，持续分支保留历史，静态接手分支不带历史；状态、目标、库存、相机、工具、剩余预算逐项核验。它与下文正常／干扰两次独立运行的对照是不同实验，也不是无事故因果反事实。见 [完整协议](../../../deliverables/brick-atlas-reliability-v1/INPUT-AND-PAIRED-PROTOCOL.zh-CN.md) 与 [可独立安装的运行包](../../../deliverables/brick-atlas-reliability-v1/RUN.zh-CN.md)。

入口：[本机动态题库](http://127.0.0.1:8810/library)。`catalogue.json` 是当前动态题的统一清单；旧数据保留用于追溯，运行入口统一为 `dynamic_arena.run`。

## 一道题怎样进行

1. 模型进入同一个持续存在的环境。从白色凸点底板开始拼完整物件，或接手已经拼好的主体，完成指定模块。起点不再被统一写成“空白底板”。
2. 第一轮提供任务、匿名零件／位置编号、工具说明和预算，不自动发图。
3. 模型调用 `observe` 看当前、目标或库存；可以转 90°、切俯视、看模块近景或整个物件。当前和目标同时请求时放在同一张对照图中，两边各为 800 × 600，相机与几何尺度相同。
4. 模型自己决定装、拆、观察、查位置、看说明书，直到 `finish`。一次拆装只移动一个实体零件；合法顺序不必与参考答案一致。
5. 干扰只修改当前环境；不给模型发“发生错误”的提示。之后模型自己查看、发现、返工、继续拼。

## 两个分支

| 分支 | 做什么 | 如何解释 |
| --- | --- | --- |
| 正常拼装 | 同一道题，只关闭外部干扰 | 检查模型是否有能力完成原任务 |
| 干扰修复 | 保留原题事件，其他条件相同 | 先要求同一模型在正常分支成功；没有触发事件时，修复成绩为不适用 |

`--condition pair` 自动先做正常分支，成功才启动干扰分支。两个独立运行没有共同的模型决策前缀，不能据此声称严格的因果恢复率。论文中的严格配对指标仍需共同前缀证据。

## 模型可调用的工具

```json
{"tool":"observe","args":{"view":"angled","rotateDegrees":90,"show":["current","target"]}}
{"tool":"observe","args":{"view":"top","rotateDegrees":0,"show":["inventory"],"inventoryPage":2}}
{"tool":"observe","args":{"view":"angled","rotateDegrees":0,"show":["current","target"],"focus":"whole"}}
{"tool":"inspect","args":{"partId":"A001","page":1}}
{"tool":"inspect","args":{"manualStep":3}}
{"tool":"attach","args":{"partId":"A001","candidate":"C00001"}}
{"tool":"detach","args":{"partId":"A001"}}
{"tool":"recall","args":{"decision":2}}
{"tool":"finish","args":{}}
```

- 每次只返回一个工具调用。编号必须使用当前题提供的编号，示例编号不适用于所有题。
- `rotateDegrees` 可为 −90、0、90、180，表示相对上一次相机转动。
- `show` 是 current／target／inventory 的非空组合；默认看库存第一页，输入会告知总页数。
- `inspect partId` 给出该零件所有注册位置的分页图片。所有位置按中性方式呈现，不标正确、错误或能否安装。
- 说明书仅按需提供，且只在原题有说明书时开放。说明书中的顺序不是评分标准。
- 库存观察同时返回每个零件的 available／installed／unavailable 状态。库存变化题因此有可观察证据，不需要猜隐藏库存。
- `recall` 返回已经主动观察过的历史图片，不代表现在的状态。
- 操作后只返回操作反馈。下一轮不会自动附当前图。

## 哪些信息不会给模型

事件种类、触发时间、受影响零件、参考修复动作、评分、正确候选位置标签，都不进入模型输入。网页中的三视角、干扰时间线和最终指标属于观看者界面。

物理动作遵循原题引擎：连接、碰撞、直线拆装通路和有限库存。夹具可以托住子结构；不声称模拟重力、摩擦、卡扣力度或机械关节运动。完整物件的白色凸点底板保留实际碰撞规则；已装主体的模块题保留原场景与支撑规则。

## 记录与指标

每次运行保存：

- `spectator.json`：每轮操作后的当前／目标三视角、时间线和观看者事件标记。
- `log.json`：每轮输入 JSON、模型原始输出、解析动作、环境返回、图像路径与 SHA-256。
- `api/*.request.json.gz`、`api/*.private.json`：真实 API 的完整请求（包括图片）与服务响应。程序动作检查没有 API 请求。
- `record.private.json.gz`：用于复核状态、动作合法性和干扰的私有记录。
- `result.json`：最终结构正确性、F1、合法动作率、格式错误、观察次数、触发事件数、逐事件恢复窗口、正常分支前提与 API 用量。

无干扰题不计修复率；事件未触发不能计漏检或修复失败；服务错误与模型失败分开。没有显式检测报告时，不从“最后拼对了”反推检测准确率。参考序列仅用于可解性和相对动作量，不当作唯一顺序或全局最短路线。
