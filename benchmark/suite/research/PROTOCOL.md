# 结构能力研究协议 v1

## 研究主张

研究对象是跨模态、可组合结构建模：识别/关系、重建/补全、生成/编辑、装拆规划/修复。
不宣称新增八个标签就是新的能力，也不把程序化模型数量当人工设计规模。
相比生成主导的BrickGPT/BrickNet，本研究应提供同对象的跨任务对应、视觉与符号条件、
多解/对称性鲁棒的验证以及工具与模型贡献的分离。当前证据不足以宣称首次或超越。

## 待检验问题

- H1：给同一组对象不同任务，重建成绩能否预测编辑/规划成绩？
- H2：在相同信息量和目录权限下，坐标与连接程序有何影响？
- H3：同等训练步数、上下文与监督token预算下，多任务训练能否改善留出对象/结构组合？
- H4：固定首个模型回答后，额外采样与目标无关的合法性反馈分别贡献多少？

已经公开的70-case smoke不能用来作上述假设的确认性检验，它是开发回归集。
研究协议冻结后创建的新样本才可用于下一轮评估；仍需披露模板与训练资产共享程度。

## 条件矩阵

| 条件 | 输入 | 工具 | 比较规则 |
| --- | --- | --- | --- |
| symbolic | 结构程序/文字约束 | 无 | 单次提交，非视觉基准 |
| RGB+BOM | 普通斜视/正交RGB和零件清单 | 无 | 不提供隐藏位姿 |
| layer-oracle | 逐层检查图/真值结构 | 无 | 额外信息上界，单列 |
| fixed-feedback | 与主条件相同 | 固定一次合法性检查 | 不暴露目标差分 |
| autonomous-tools | 与主条件相同 | 模型选择公开目录、观察、验证 | 调用与费用限额，单列系统榜 |

## 指标合同

- 单次响应正确率是模型在固定Harness下的表现，不是与提示词和格式无关的内在能力。
- QA字段正确、结构集合正确、规划路径正确分别评分。
- 结构集合不因输出顺序而失败；计划则按原始顺序执行，不由系统偷偷修正。
- 语义约束生成接受不同合法结构；不能套用唯一目标Part-F1。
- 图像不足以辨识隐藏结构时，标明可观测性与多解，不能拿不存在的视觉证据问责模型。
- Format failures和拒答计为模型失败；基础设施故障单列且不从覆盖率消失。
- 报告每任务n、来源组数、准确率、宏平均、各指标、tokens、耗时和费用。
- 按源对象/生成组进行配对bootstrap，不将配色变体当独立样本。
- n很小或同模板重复时不宣称显著性；计划至少三个seed检查关键设置稳定性。

## 基线

空输出、复制输入、检索、传统连接图算法仅是相应任务的基线。
训练模型须存真实权重、基础模型revision、训练配置、数据hash、优化步骤及验证日志。
本地小规模语言模型训练只能声称符号/文本条件基线；不能把没看图的模型叫多模态模型。
如果只做短训练试验，必须标记pilot，不冒充充分收敛的统一模型或大规模消融。

## 审核与发布

代码oracle、独立算法checker和独立人类审核分开报告。
公开模板的几何组holdout不等于隐藏真实数据；大规模人工数据必须逐项核验授权。
不改变已发表的旧实验结果以适配新评分器。新版本报告旧协议变化及两者不可直接横比之处。
