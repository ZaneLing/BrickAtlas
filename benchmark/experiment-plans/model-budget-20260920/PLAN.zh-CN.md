# BrickAtlas 模型覆盖与实验预算建议

最新缩量方案见 [全模型 MVP](mvp/PLAN.zh-CN.md)：配置内全部 15 个模型
（包括另列的 Sol）各一轮，保留两个模式时 2,718 次请求，
2K 计费输出情景约 ¥751，建议预留 ¥800–1,000。
其中 12 个模型在 OpenRouter 目录中列出，3 个暂按自部署。
下文仍是较大规模研究预算，MVP 参数位于 `config.json` 的 `mvp` 字段。

估价日期：2026-09-20。状态：方案与离线测算，未调用付费模型、租用 GPU 或发出人审邀请。

建议采用 **12 个视觉语言模型 + 2 个纯文本图推理模型 + 2 个额外推理模式配置**。
每个配置预先安排三轮完整调用，按当前题量共 **39,660 次正式请求**。
在每次 API 调用平均产生 2,048 个计费输出 token 的假设下，
含 GPU、存储和 30% 预备金的预算约 **¥9,368**；建议预留 **¥10,000–12,000**。
若所有 API 调用都接近 8,192 个输出 token，压力情景约 **¥30,646**，
GPU 工时再翻倍时约 **¥32,128**。

这是新增研究方案。已封存 evidence-v3 的三个模型、九次单轮运行保持原状；
正式采用本方案时另建完整 study 版本，不向旧 roster 中临时添加或替换模型。
本预算不包含原 v3 独立研究的额外采集，也不包含模型训练。

## 1. 主实验要回答的比较问题

| 比较轴 | 设计 | 能支持的分析 |
|---|---|---|
| 强模型的剩余失败 | 三家高能力闭源模型 | 当前属性/指代干预是否仍能区分行为 |
| 服务能力与成本档位 | 每家再加入一个较便宜模型 | AAcc、Both、无图像依赖和费用是否一起变化 |
| 可复现的开放权重 | Qwen、InternVL、Gemma，各两个规模 | 不同训练/视觉处理方案与模型规模下的表现 |
| 推理投入 | 两个既定模型增加思考模式配置 | 增加推理是否改善 Both，或者只增加消耗 |
| 文本结构推理 | 两个纯文本模型只测图任务 | 显式图输入下的结构推理行为 |
| 浅层规则 | 固定选项、生成规则、图特征规则、BFS/union-find | 学习模型表现是否超出已知可解释基线 |

规模比较不等于只改变参数量的严格因果实验；训练数据、视觉编码器等也可能变化。
InternVL 的语言骨干与 Qwen 有关联，不能把这些名称视为独立训练分布的统计重复。

## 2. 推荐候选清单

以下是候选服务/权重名称，尚不是通过实际账号验证的不可变运行清单。
当前代际闭源模型用于能力比较；开放模型选择已有明确大小配对的版本。
这并不宣称列出了每个厂商截至今天的所有最新模型。

| 类别 | 模型 | 数量 | 用途 |
|---|---|---:|---|
| 高能力闭源 VLM | GPT-6 Astra；Claude Fable 5.1；Gemini 3.1 Pro Preview | 3 | 跨提供商高能力参照 |
| 较便宜闭源 VLM | GPT-5.6 Luna；Claude Sonnet 5；Gemini 3.8 Flash | 3 | 各服务家族的成本/能力对照 |
| 开放 VLM：Qwen | Qwen3.5-9B；Qwen3.5-27B | 2 | 规模配对，并做 thinking 消融 |
| 开放 VLM：InternVL | InternVL3.5-8B；InternVL3.5-38B | 2 | 另一视觉处理方案及规模配对 |
| 开放 VLM：Gemma | Gemma 3 4B IT；Gemma 3 27B IT | 2 | 独立开放模型家族参照；不是最新代际声明 |
| 纯文本结构模型 | Qwen3-32B；DeepSeek-R1-Distill-Qwen-32B | 2 | 只参加 219 条文本图任务 |

两个额外配置：

1. Qwen3.5-27B：thinking off / on，复用同一权重和相同观察。
2. Gemini 3.1 Pro：较低 / 较高 thinking effort，复用同一输入。

它们增加的是两个配置，不是两个独立模型。API 是否支持精确 thinking
控制、最终输出上限与推理预算须先在独立开发题上验证。
可选增强是 Qwen3.8-27B 的代际对照或其他开放家族，另行增加配置与预算；
不能在看完主结果后只加入“有趣”的模型。

3D 点云、LDraw 生成和 VLA 模型需要各自兼容的输入/输出任务，
不能直接因为无法返回 choiceId 而在当前视觉表中记零。
工具 Agent 可做单独扩展轨，但它的多轮调用、裁图/OCR、额外视角和
源记录访问必须单独计费与报告，不混入单次原生 VLM 主实验。

## 4. 公平性与采集约定

- 所有 VLM 接收同样的原始 1280×800 PNG 与问题语义。保留各家的
  图像处理/detail/分块设置；相同像素不等于各家内部图像 token 相同。
- A/B 独立调用，不向 B 提供 A 图、A 答案或对话历史。
- 保留 Color、Part-type、位置面板和文本图的独立结果。
- 既有固定选项和 oracle-A 捷径必须继续报告；oracle-A 得到正确 A，
  空间规则还使用 A 侧源几何，这些是特权审计，不是普通模型输入。
- 建议增加廉价的 Color 前景颜色统计基线。若建立 OCR+视觉相似度
  pipeline，定位失败必须保留；用源 mask/type 辅助时标为特权基线。
- 开放权重优先 BF16/FP16。4-bit/8-bit 单独列配置，记录权重 commit、
  tokenizer、视觉处理器、推理框架、量化和生成设置。
- 根据服务支持能力设定温度/采样；不要把所有模型都强制设为 temperature=0。
  部分推理模型没有关闭思考或任意采样参数的接口。
- 最终文本要求短 JSON，但**计费输出包含推理 token**。旧 v3 的
  128-token 设置不能直接照搬到需要内部推理的新模型。新适配器分别记录
  最终文本、推理使用量、终止原因与合计费用；截断仍计失败。
- R1 可作为单次评测主表，R2/R3 为事先承诺的完整复核，报告每轮结果、
  均值/范围和方向变化。不能挑最好的一轮，也不能把 24 个来源算成 72 个。
  三轮只能提供有限的调用波动证据，不支持精确的服务方差估计。
- 保留 source-macro、author/contributor sensitivity、完整与
  both-decidable 子集；所有失败都留在原定分母。
- 对 Google Preview 等无法证明后台版本完全固定的服务，记录实际
  modelVersion、请求时间和采集窗口限制，不制造不存在的快照 ID。

正式采集前必须冻结全部模型/配置/轮次、适配器、可纳入服务版本和失败规则。
现有 analyzer 需要扩展到新 roster、多提供商和重复运行；本方案没有宣称
这些适配已经实现。

## 5. 预算的输入依据

离线读取当前 913 个请求，只对文本采用 `o200k_base` 编码，加每请求
12 个消息开销 token 的代理值：

| 条件 | 次数 | 文本 token 代理合计 | 平均 |
|---|---:|---:|---:|
| 看图 | 347 | 64,405 | 185.61 |
| 无图像 | 347 | 64,405 | 185.61 |
| 文本图 | 219 | 44,352 | 202.52 |
| 合计 | 913 | **173,162** | |

这不是任何新模型的实际账单。预算向上取每轮 **260,000 文本 token**，
再按每张图 **2,000 图像 token** 估算：

`输入预算 = 260,000 + 347 × 2,000 = 954,000 token / VLM / 轮`。

图像代理的参照是：Claude 当前 28×28 patch 规则下，1280×800 图约
`46 × 29 = 1,334` 个视觉 token；Gemini 3 的 high 设置约 1,120。
OpenAI 按模型/detail 使用不同 patch/倍率规则。正式冻结前应核对各模型
实际 image token，用 provider usage 或官方计数接口校准；2,000 不是普遍上界。

单模型一轮费用：

`C = 0.954 × 输入单价 + 913 × 平均计费输出token ÷ 1,000,000 × 输出单价`。

预算按 **1 USD = 7 CNY** 折算，这只是汇率假设。标准调用，不使用缓存、
Batch、赠送额度或工具调用折扣。30% 预备金覆盖独立开发题试跑、算量偏差、
小额额外存储与汇率/地区差异；不授权重复挑选正式结果。

不能把部分模型结果发布成完整比较。

## 9. 执行顺序与另列成本

1. 用正式集合之外的开发题，对每个候选做约 30 次格式/图像/计费试跑。
   检查可用模型版本、服务返回字段、推理 token、P50/P95 延迟和截断。
   这一步不按主实验答题分数选模型。少量费用放在预备金中。
2. 根据实际 tokenizer/image usage 和吞吐，更新本预算代理值。
   任何替换模型都在主实验开始前说明理由并冻结完整清单。
3. 实现多提供商适配、开放权重服务与重复运行的分析/纳入校验，
   冻结新版研究协议。工程适配粗估 5–10 人日，工资不在上述算力预算。
4. 完成人审 gate 后，按预先安排的轮次、交错的模型/条件顺序采集。
   保留全部请求、原始输出、usage 和失败，不做自动重试或 best-of。
5. 先报告分族完整结果和限定，再做 case analysis；不按看到的排名改变配置。

按用户“bench 已做好”的前提，主预算不包含真人 QA。
若把尚未完成的 694 份初审也纳入：
每份 2–4 分钟约 23–46 人时，另加六人培训约 3 人时、
协调/裁决约 5–10 人时，总计约 31–59 人时。
按 ¥60–100/人时预算，额外约 **¥2,000–6,000**。
这只是劳务规划，实际应按任务复杂度与评审者条件支付。

## 10. 可复算文件

- `config.json`：模型单价、工时、汇率、轮次及假设。
- `workload-audit.json`：实际冻结请求文本的离线 token 代理统计。
- `budget.json`：逐模型、逐方案、输出长度与 GPU 工时情景。
- `api-costs.csv`：可直接导入电子表格。
- `calculate.py`：不调用模型的计算器。

从仓库根目录运行：

```sh
python3 benchmark/experiment-plans/model-budget-20260920/calculate.py
```

可选重算文本 token 需要安装 `tiktoken`，并加 `--audit-workload`；
本次用隔离在 `/tmp/brickatlas-budget-tiktoken` 的包完成统计，
没有改变 benchmark 的冻结代码或已验收发布文件。
