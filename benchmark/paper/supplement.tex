\section{Scope and Version}
This supplement indexes the current Hierarchy-3 release: 48 layouts,
48 families per layout, and 2,304 questions. It accompanies the
machine-readable public inputs, answers, quality records, and original
website 3D interface. It replaces the previous manuscript's appendix
as the current entry point. Older Mechanism-1, Hierarchy-1, Hierarchy-2 and retired
grid experiments remain in their versioned data directories and Git
history; their scores are not pooled into this release.

\section{Reading the Contracts}
Each task has a source ID, difficulty stratum, task layer, family,
capability, output format, evidence class, and public input.
Single choices return \texttt{choiceId}; set-valued choices return
\texttt{choiceIds}; operations return \texttt{actionIds};
schedules return a job-to-start-time map; policies return a query and
observation-to-action map. Choice values are shuffled deterministically
per task. Empty feasible sets are accepted when appropriate.

The full companion \texttt{QUESTION\_BANK.zh-CN.md} includes every
question, every option, every input, and every reference answer.
The following family table describes all contracts, and the per-object
pages index all 2,304 task instances with four actual website renders
per object. No page implies an independent human annotation.

\section{Atomic Operations}
Identification maps an image-highlighted service module to its ID.
Counting groups visible parts by module. Color and position questions
read explicit attributes and world bounding-box centers. Joint type,
parents, roots, and incident-degree questions inspect the declared
attachment graph.

Recoloring changes exactly one part's color. Addition chooses an exact
missing part descriptor. Removal identifies leaf modules. Replacement
maximizes stiffness under a cost limit. Translation inverts an observed
offset; rotation selects a shortest signed yaw correction.
Next-module questions test predecessor completion. Inventory checks
conserve piece count; boundary questions identify every incident joint;
no-operation questions reward preserving an already-correct state.
Local-frame, orthographic projection, relative-order and joint
freedom tasks extend the atomic coverage.

These are controlled contracts, and several public inputs disclose
the exact attributes needed for a solution. They are not all image-only
perception tasks. One must report the information condition alongside
accuracy and run ablations before assigning a visual interpretation.

\section{Meta and Physical Tasks}
Prefix tasks detect the first violated predecessor.
Accessibility reads actual continuous cuboid shape-cast records.
Counterfactual tasks remove a specified node and recompute undirected
reachability to anchored roots; the explicitly removed node is excluded
from the answer. Dynamics asks for the largest sampled translational
displacement from eleven actual Rapier measurements.

Kinematic questions use declared joint axes and limits, not empirical
actuation success. Diagnosis matches constraint type and observed
endpoints, accepting all matching interfaces. Inspection optimizes
entropy reduction per unit query cost. Abstention checks agreement
of actions across possible worlds. Posterior inference conditions
a finite uniform prior on an observation. Pareto enumeration retains
all non-dominated cost/mass/stiffness alternatives. New families
cover clearance margins, cross-product moments, weighted posteriors,
expected losses, and sampled threshold exceedance.

\section{Action State Machine}
The initial fact set, action catalog, preconditions, forbidden facts,
add/delete effects, costs, budget, and goals are public.
Assembly/disassembly changes module presence. A service intervention
requires support before access, access before removal or modification,
replacement before verification, closure before support release.
Guarded repair and rollback expose invalid shortcuts, while shared-tool
repair enforces exclusive access through a resource fact.
Actions on independent modules may be interleaved. The evaluator never
sorts or repairs a submitted program.

For every action, the replay records accepted status, first error,
current facts, visible modules, color overrides, and cumulative cost.
Reference and submitted model JSON use the same interpreter in the
original webpage. A visible explosion is a display transformation only.
Neither symbolic acceptance nor rendered motion is claimed to certify
clutch forces or robot insertion.

\section{Integration}
Multi-fault programs combine several targets with one budget and final
goal. Scheduling checks integer starts, predecessor finishes, resource
exclusion, and makespan. Policies must map all observations to actions
correct in every compatible world; success on one sampled branch is
insufficient. Unknown actions, repeated completed actions, omitted
terminal actions, conflicts, and missing policy branches are tested
with negative controls.

\section{Simulator and Quality Boundaries}
Rapier 0.20.0 runs at 120 Hz and 64 solver iterations.
Modules are compound stud-inclusive cuboid bodies. Bases are fixed. ForceBased holding motors
use stiffness 60000, damping 1500, and maximum force 20000 in scene units.
Three access casts use a 0.18-unit half-extent probe and exclude the
service module. The static query world is independent of settling.

After 120 nominal steps, an impulse $(10,1.8,3.5)$ is applied one unit
above the target geometric representative point. The same attached
point supplies the displacement measurements. The next 120 steps produce eleven
samples. Nominal state is evaluated before the impulse. All 48 layouts
satisfy representative-point displacement below 0.35, angular displacement
below 0.15 rad and non-spring joint residual below 0.02. Initial anchor
pairs coincide. No module pair has oriented-cuboid
penetration greater than 0.005. Direct joint interfaces participate
in the collision gate and retain contacts; module interiors are compound rigid bodies.
Revolute limits are explicitly enabled on instantiated joints and read
back. A driven motor is stopped at its declared bound, and changing
only the local coordinate origin preserves the sampled physical response.
Geometry, anchors, some layouts, moorings and motor parameters changed
together, so comparisons with Hierarchy-2 require the new protocol label.
This does not certify commercial connector fit or arbitrary robot motion.

\section{Corrections and Historical Scoring}
Hierarchy-2 had eleven next-module questions with semantically equal
set options in different orders. The corrected generator normalizes
sets only; vectors and programs remain ordered. Historical affected
choice IDs are recorded in \texttt{historical-ambiguities.json}; either
equivalent answer is accepted under a separately labeled semantic
rescoring. Historical raw scores are retained.

The Mechanism-1 conditional-entropy sign was corrected. An
uninformative four-world query now has information gain zero rather
than four; the six historical optimal query labels did not change.
All primitive dimensions now agree with the renderer and stud-inclusive
envelopes. Paused replay selection and isolation cannot resurrect
absent modules. Six old constant-answer families now vary actual
parameters, and all 48 semantic answer distributions are published.

\section{Pilot and Reproduction}
The GPT-4.1 mini pilot contains 16 fixed questions, one per level/layer
cell. Families are local-frame, expected-loss, guarded-repair, and
resource-repair. \PilotSuccess{} of \PilotN{} responses succeed at a total cost of \$\PilotCost.
Each cell has one response, so no stable accuracy estimate or model
ranking follows. Input hashes, generation IDs, provider receipts, and
raw predictions are archived separately from the reference answers.

The 2,304 oracle checks validate the evaluator; 384 public-precondition
solutions validate action execution. A constant-choice/empty-answer
control passes \ControlSuccess{} cases. These controls do not establish task novelty
or human difficulty. The figures use original-site canvas captures,
and byte-identical model records are shipped to the website and offline
release.

From the repository root:
\begin{verbatim}
npm --prefix benchmark run h3:release
npm run start:local
npm --prefix benchmark run h3:render
npm --prefix benchmark run h3:docs
npm --prefix benchmark test
npm run build
\end{verbatim}
Model inference is a separate paid command and is not required for
offline score replay. The release manifest binds data and generator
hashes. Public-input files exclude the answer; the review website
intentionally includes a reference-answer control.
