\section{Benchmark Reference}
This supplement separates three types of evidence: measured full-casebank
audits, measured adaptive model studies, and explicitly unmeasured
future experiments. The latter have blank result cells and must not be
interpreted as zero accuracy. All new figures are generated from archived
renders or machine-readable evidence, not illustrative model outputs.

\subsection{Retired Procedural Mechanism Layer}
The earlier 5,120 random-growth structures and 117,910 derived conditions
are no longer primary benchmark data and are excluded from current object
scale. They remain available solely for scorer regression, shortcut
censuses and reproduction of historical model runs. Their construction
is documented below so old results remain auditable.

For each policy, candidate seeds are deterministic. The pipeline is:
\begin{enumerate}
\item Generate a valid insertion sequence from the common root plate
under the policy-specific attachment rule.
\item Normalize horizontal origin; reject invalid sizes and exact
colorless translation/yaw-equivalent duplicates, including old releases.
\item Run the independent integer-cell geometry check. Accept until
640 unique geometries are available per policy.
\item Assign the source split from the geometry hash, except for the
two entirely held-out policies.
\item Derive task variants and reference conditions; attach the source
group to every derivative; build the public input and evaluator record
separately.
\item Validate oracle success, empty-output failure, metric applicability,
render recipes, and hashes before materializing compressed shards.
\end{enumerate}
The release contains 14 shards and 476,760 serialized rows across
source, input, ground-truth, render, and case-index records. Those
storage rows are not extra samples.

\subsection{Input and Answer Schemas}
The public exporter emits \texttt{caseId}, a fixed \texttt{system}
prompt, the public \texttt{input} task, and relative \texttt{images}
paths. The task contains a question, public structure/constraints where
applicable, and a response schema. The full evaluator index is public
for reproducibility; ordinary-input isolation is a benchmark protocol,
not a security guarantee against consulting the answers.

The following is a minimal \emph{schema example}, not a model result:
\begin{verbatim}
{"version":1,"parts":[
 {"id":"p0","partId":"3005",
  "color":"blue","x":0,"y":0,
  "z":0,"turn":0}
]}
\end{verbatim}
Recognition returns \texttt{partId}, \texttt{color}, \texttt{studs}.
Relations return \texttt{connected}, \texttt{above},
\texttt{contactStuds}, \texttt{shortestPath}.
Plans return \texttt{order}, an array of all target IDs exactly once.
Repair wraps a full program as \texttt{structure} and adds
\texttt{faultIds}; no-fault answers use an empty array. Normal
reconstruction, generation, completion, and editing return a structure.

Relative nodes may instead specify an earlier \texttt{parent},
an \texttt{offset} in global grid axes, and absolute \texttt{turn}.
This encoding is reversible but does not assert a stud connection;
it is not BrickNet's typed connector language.
Square footprints admit all quarter-turns, while other rectangular
footprints admit half-turn symmetry. Scoring ignores instance IDs for
multiset recovery but does not globally align translations or rotations
unless the task explicitly requests a transformation.

\subsection{Render and Coordinate Contract}
The released views are 640-by-480 PNGs. $X,Z$ are stud coordinates;
$Y$ is bottom plate height. The front camera looks from positive
$Z$, with image-right $+X$ and image-up $+Y$. The side camera looks
from positive $X$, with image-right $-Z$ and image-up $+Y$.
Top looks from positive $Y$ with a small positive-$Z$ offset,
image-right $+X$ and image-down $+Z$. Cameras fit each structure;
apparent pixel scale is not a fixed metric calibration.
Layer views remove every part not starting at the selected bottom $Y$.
They are additional observations, not ordinary views through an opaque object.

\subsection{Full No-Operation Audit}
\texttt{study/paper-audit.ts} first verifies frozen casebank source
hashes and the compressed structure shard digest, computes a per-source
inventory, and evaluates the copy predictor on 35,840 selected cases.
The predictor receives only the public task and copies \texttt{current};
repair adds an empty fault list. Prediction production does not inspect
the evaluator target, changed IDs, or oracle. Its fixed output is then
scored with the versioned strict evaluator.

Seven endpoints each contain one case per source: ordinary suffix
completion, three default symbolic edits, and ordinary no-fault/color/shift
repair. Raw case-level scores, IDs, policies, and splits are retained
in \texttt{copy-controls.jsonl.gz}; selection and artifact hashes are
recorded in \texttt{audit.json}. Summary code rejects duplicate cases
or repeated sources within an endpoint and records metric-specific
denominators. These are descriptive census values on the public release,
not sampling intervals or held-out model performance.

\section{Evidence Boundaries}
The six-work-package research contract separates positioning, data,
measurement, model experiments, independent review, and delivery.
Same-machine runtime-free replay is not independent reproduction.
Review packets contain no completed human judgments until real reviewers
submit version-matched labels; disagreement is not silently adjudicated.
No human-designed dataset is treated as imported merely because a paper
or connector annotation is publicly accessible. Permission, assets and
redistribution rights are separate gates.

\section{Retired V2 Training And Verification}
All 117,910 historical strict-decoder oracle answers pass, 5,120 malformed
primitive-type examples are rejected, and scores on 118,640 existing
baseline/API records agree with their historical values.
Independent implementations agree on 138,240 structural metric
comparisons, all 10,240 relation queries, and connector counts on
5,120 structures. An additional 107,520 mutation/invariance checks
cover missing, duplicate, unknown, and reversed plan actions, no-op
edits, faulty localization, IDs, and yaw symmetry. Finite tests are
not a proof over arbitrary malformed submissions, and shared catalog
assumptions limit algorithmic independence.

The local pilot uses SmolVLM-256M-Instruct revision \texttt{7e3e67ed},
unquantized. Ninety-six training and 24 disjoint validation objects
provide seven task families (672/168 examples) and actual PNG views.
Language-side query/value rank-8 LoRA has 460,800 trainable parameters.
Single-reconstruction, multi-task and leave-edit use seeds 17, 29 and 43.
Every trained run uses 120 updates, exactly 512 supervised answer tokens
per update, AdamW at $2\times10^{-4}$, and gradient clipping at 1.
Full prompts and answers are retained; deterministic answer-token
subsampling matches supervision, not input/image tokens, time or compute.

Validation NLL uses two fixed examples per task. Training uses PyTorch/MPS;
formal inference uses MLX with a 2,200-token cap on the same 337 cases.
Token, pixel and mask digests agree across preprocessing backends,
but floating-point kernels need not produce identical outputs.
All 840 training/validation prompt prefixes retain token identity when
answers are appended; maximum complete length is 5,176 tokens.
Compact test-oracle answers use at most 1,793 tokens. Oracle lengths
are private diagnostics, never appended to model inputs.
The completed matrix retains 3,370 predictions, 1,080 updates and
552,960 supervised tokens. Each of nine adapters has 60 adapted
matrices and 411 unchanged tensors independently checked under the
actual bfloat16 cast-before-add merge semantics.

The calibration pool contains 468 questions from 36 validation objects
excluded from the original study and training/validation bundle.
Selection cycles through available size bins within each of six policies;
missing bins remain explicit. Portable inputs contain 720 image uses
and 144 PNGs checked against public input, hashes and nonblank rendering.
The earlier train/validation/test render audit checks 1,177 records,
1,970 image uses and 626 regenerated images on the same browser/GPU
stack, not arbitrary rasterizers.

The casebank verifier checks 476,760 serialized rows across 14 shards,
regenerates every ground truth and reconstructs baseline state chains.
Browser checks cover desktop and mobile, nonblank scenes, camera
interaction, input/truth isolation and export. Additional development
responses are replayed offline and are not retroactively included in
older browser-audit counts. Reproduction shares pinned Node dependencies;
it is not an independently installed operating system or a second person's
training experiment.

\section{Candidate Controls}
For the initial pose probes, all candidate structures are legal,
use identical part identities, yaw and height, and differ in horizontal
position. Correct labels are balanced across the four selected scenes.
Repeating a question and permuting its candidates are distinct interventions.
The follow-up contract compares permutation mismatch to same-order
repeat mismatch within each source/model, with temporal order balanced
across source groups. Source-level bootstrap intervals describe only this
selected development sample; they do not establish population coverage
or stable model rankings.

\subsection{Renderer-Aware Analysis by Synthesis}
To test whether candidate locations contain usable image signal, a
post-hoc deterministic baseline consumes only public BOM, candidate
poses and RGB views. For the two-piece blue-on-gray domain, the supplied
positive query height and support rules imply a grounded gray piece.
Its horizontal positions and both distinct yaw footprints are enumerated
under minimum-corner and contact constraints, not obtained from ground truth.
Every legal candidate scene is rendered with the public renderer.

We threshold blue chroma ($B>80$, $B>1.25R$, $B>1.1G$) inside image
rows 32--447, excluding title/footer and neutral grid/text. A candidate
receives the smallest mean mask-IoU distance over its legal hypotheses
in top, front and side views. Equal candidate scores or missing blue
masks cause abstention. No-image inputs abstain without rendering.
The thresholds and enumeration are fixed in code before this run, but
the method was designed after the preceding development experiments.

\section{Finite-Grammar Ambiguity Contract}
The new extension is versioned separately from v2. A fixed shell
encloses a $2\times W$ unknown layer tiled by identical red
1-by-2 bricks. All other layers and blue query poses are fixed.
Widths 2, 4, and 6 and three stack heights yield nine parameterized
families, not independently collected semantic objects. Every possible
query pair is retained, not selected according to model outcomes.
The two conditions share exactly the same query and family:
the exterior condition withholds the internal layer, while support
disclosure reveals its complete placement list.

\texttt{public.jsonl} supplies the grammar, known geometry, inventory,
query IDs, and (only in the disclosed condition) support poses.
It excludes expected labels, answer sets, and alternative hidden
programs. Known geometry is symbolic, so this is a test of
observation-consistent structural reasoning, not a claim of visual
recognition. The public-input solver enumerates legal hidden tilings,
forms all candidate contact graphs, and returns a definite answer
only if every candidate agrees. It receives no evaluator target.

horizontal and vertical domino placements. Independent recurrence
counts validate enumeration completeness for the finite grammar.
Every candidate passes both geometry implementations. Independent
contact-edge intersections validate shared-support labels.
The exact answer set is not claimed exhaustive over arbitrary
brick programs or non-grid connectors.

False certainty counts definite yes/no on an undetermined input;
unnecessary abstention counts undetermined on a determinate input.
Malformed responses have zero exact success and separate format failure.
Neither conditional rate has a denominator on inapplicable cases.
Because answer classes are unbalanced, overall accuracy, source-macro
accuracy, and class-balanced accuracy must all be reported.

\paragraph{Pixel audit.}
All 60 layout states are rendered in four fixed views with the separate
high-resolution paper renderer, for 240 frames. Thirty-six serve as
the first-layout reference of their family/view, leaving 204 alternative
comparisons. All alternative pixels match, with no tolerance.
This does not certify equality under a different renderer, transparent
parts, changed cameras, or actual photography. It also does not
establish human agreement on the grammar or instructions.

\paragraph{Figure integrity.}
Thirty actual 3D renders form four new figure plates. Gallery examples
are selected by median part count and deterministic group hash.
Task examples preserve original geometry, colors, and evaluator IDs;
all oracle targets are scored before rendering. Execution snapshots
are verified legal prefixes, while the greedy dead end is checked
against the original insertion rule. Fixed framing prevents camera
rescaling from masquerading as a change in part pose.
Exploded layers are explicitly display-only and are never substituted
for ordinary model observations. Nonblank pixels, uncut framing,
render recipes, and file hashes are recorded in
\texttt{structure-evidence.json}.

\subsection{Independent Main Evaluation}

sources and 16,256 calls for four models with four arms each.
This is a conservative planning bound, not an acquired dataset,
a guaranteed future effect, or a universal required sample size.
Stratified/variance-based designs require their own frozen assumptions.

\subsection{Candidate Robustness and Debiasing}
Table~\ref{tab:future-order} compares original, repeated, and permuted
actual pose selections on independent sources. Correct label balance
and request ordering must be frozen. Missing responses reduce paired
coverage, not the denominator of service availability. Report
complete-pair effects alongside worst-case bounds: with $N$ frozen
sources, $n$ complete pairs, and observed effect sum $s$, the
all-source effect lies in $[(s-(N-n))/N,(s+(N-n))/N]$.
This is a missing-outcome bound, not a confidence interval.
For uniform independent random $K$-way choice, accuracy is $1/K$;
repeat and permutation mismatch expectations are both $1-1/K$,
so expected excess mismatch is zero. These are analytic controls,
not empirical model results.

An option-debiasing baseline is motivated by existing selection-bias
work and must be fitted on development data only. API conditions that
do not expose token probabilities require a declared compatible
alternative; one must not silently substitute a different method.
