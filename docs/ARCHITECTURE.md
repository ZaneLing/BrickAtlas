# 架构与数据契约

## 数据流

```text
固定版本 MPD + 官方零件库
  -> 来源哈希校验
  -> MPD 虚拟文件表 + 依赖闭包 + 逐文件许可门禁
  -> 递归实例展开（身份/颜色/矩阵/源行/子模型/步骤）
  -> Three.js LDrawLoader（BFC/真实材质/条件边线）
  -> 原始世界坐标几何 + 每顶点 instanceIndex
  -> 结构组/材质合批 + 六个 gzip 几何块
  -> Worker 流式下载/哈希校验/解压
  -> BrickModel 领域对象 + Zustand Viewer Store
  -> GPU 状态纹理控制位移/显隐/选中/步骤高亮
```

## 身份与原始坐标

每条模型级叶子零件引用生成一个 `PartInstance`，再映射为独立的 `BrickModel` 数据对象。零件内部的 subpart/primitive 不作为独立物理实例计数。ID 使用确定性的 `brick_000001` 顺序格式，重复构建稳定，不依赖 Three.js 对象 UUID。源文件与源行号保留用于追溯。

原始坐标只在导入边界通过 `diag(0.4, -0.4, -0.4)` 转换为毫米、+Y 朝上。几何构建使用完整 Matrix4，不分解或丢弃镜像、旋转、缩放；镜像时翻转三角形绕序。零件世界坐标几何固化在资产中，0% 的 GPU 位移严格为零。对照脚本另用未展平的源 MPD 验证全部实例矩阵和包围盒。

循环依赖、未知颜色、非法坐标、奇异矩阵、缺件、未知许可和未接入的 TEXMAP 会阻止构建，不静默删件。当前模型不存在贴纸纹理或柔性件专用导入需求；新模型有这些特征时需扩展管线后再发布。

## 爆炸布局

- 0–45%：按 `classification.json` 的语义方向做 smoothstep 插值，车轮按模型左右分离。
- 45–100%：将零件包围盒投影到固定观察平面，以高度稳定排序后 shelf packing；格子间留出间距。
- 相机逐零件计算投影包围盒，平滑适配，100% 接近正交视角，左键转为平移。
- 只有可见集合或画布比例变化时重排 inventory；拖动滑杆只更新状态纹理。
- 减弱动态效果时直接到达目标状态，关闭自动旋转。

布局不是碰撞物理模拟。100% 保持每个零件独立身份，不把相同零件合并成一个库存图标。零件数量较多时可通过缩放、搜索或分组隔离检查微小零件。

## 渲染与拾取

几何分成 mesh、line、conditional 三种 bucket。opaque 几何按组和材质合批；transparent 实例独立 bucket 保留排序能力。GPU Float32 RGBA 纹理三行分别存储位移/显隐、选中态和实例基础色，`instanceIndex` 连接语义身份。条件边的两个端点与两个控制点一起位移，不能仅移动可见端点。边线材质读取实例基础色后适度压暗和透明混合，不再对所有浅色、红色零件叠加统一黑线。

GPU 位移后静态包围球不再准确，因此合批对象禁用静态 frustum culling。CPU 拾取先对可见实例包围盒粗筛，再逆向平移射线进行真实三角形相交。默认优先不透明件；Alt 点击可选择前面的透明件，透明件也可从清单选择。

静止时不重复执行 renderer.render；相机阻尼、爆炸、步骤入位、用户交互或状态变化使渲染变脏。DPR 支持自动、1x、3x、4x；截图可独立渲染 Full HD、4K、8K 或 12K，不依赖屏幕分辨率。积木表面使用带 clearcoat 的物理塑料材质、环境光和柔和地面阴影。

## 状态规则

Zustand `ViewerStore` 是视图状态来源，保存选择、逐块隐藏、隔离、拆解、X-Ray、质量和当前步骤，并按模型持久化拼装进度。可见集合为结构开关、逐块隐藏、isolation 与已完成步骤集合的交集。

原生 `<dialog>` 管理桌面模态焦点。模型上的所有选择操作也有搜索清单路径，避免只有鼠标能访问。

## 资产格式

manifest JSON 描述语义和每块的属性偏移。每个 `.bin` 实际是 gzip 压缩的 Float32 连续属性，不是 glTF。块中每个 bucket 描述 position、normal/conditional controls、instanceIndex 的字节范围。Worker 校验压缩体 SHA-256 后解压，主线程用 typed array view 创建 BufferAttribute。

不使用有损减面或浮点量化，保证基线几何一致。初次进入先显示车身，再逐组到达其余模型。所有资产同源，无运行时 LDraw DAT 递归网络请求。

## 步骤与说明书

源 MPD 含 STEP 时保留作者步骤和子装配层级。不含 STEP 时按顶层子装配分别进行局部自底向上构建；机场、车站等场景先构建飞机、车辆和人物等独立总成，再构建跑道或建筑，最后通过单独的放置步骤把总成移动到最终坐标。

中央视图对每一步的新增零件执行错峰入位动画，并聚焦到最终连接区域。右侧说明页使用独立离屏 renderer 生成无地面阴影的聚焦帧序列，循环展示同一步的入位过程；材料清单只统计新增零件，总成放置步骤则明确显示为整体移动。

PDF 导出逐步骤调用 Three.js 独立构图，生成封面和横向 A4 步骤页。每页包含步骤号、本步新增零件、数量、拼装定格图与来源声明。导出使用与交互视图相同的 manifest，不维护第二份步骤数据。

## 新增模型

模型由 `atlas.config.ts` 的目录驱动。新增项目时：

1. 把许可明确的模型放进 `assets-source/set-original/`，更新来源哈希与下载脚本。
2. 在 `atlas.config.ts` 增加标识、名称、来源、固定哈希与许可。
3. 按领域检查通用结构分组，必要时增加可审查的模型专用分类。
4. 重跑素材与几何管线，检查所有逐文件许可、步骤覆盖和实例身份。
5. 复核 Credits 文本、HTML 元信息和模型特有完整性说明；完成独立查看器对照后发布。

`/create` 支持两条本地路径：任意 LDraw 文件预检，以及单张图片生成彩色体素浮雕。图片路径在浏览器中完成背景估算、色板量化、深度分层、标准砖合并、步骤和 BOM 生成，并提供独立的实例化 Three.js 场景。它不上传图片，也不把单视图浮雕标注为完整三维重建。完整体积模型需要独立 GPU 服务完成图生 3D、网格修复、体素化、砖块优化和结构验证，接口边界见 `docs/IMAGE_TO_BRICKS.md`。
