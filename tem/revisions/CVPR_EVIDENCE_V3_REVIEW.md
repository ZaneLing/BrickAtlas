## 1. 总体判断

**模拟推荐：Borderline，当前略偏 Weak Reject（5/10）。置信度：3/5。**

这是对研究贡献和证据解释的判断，不是对代码质量的评分，也不是接收概率或 CVPR 官方量表。与上一版相比，实现质量与测量自洽性有实质进步；本轮核查范围内，没有复现新的、可在当前单观察输入协议下满分作答的严重捷径。但“工程上基本做对”尚不足以自动给 Weak Accept。

现在最重要的问题已经不是继续修复同一批漏洞，而是：

1. 补充非常接近的近期工作比较，证明独立科学增量；
2. 区分“使用了图像”“识别了属性”与“正确利用了指定对象的视觉证据”；

4. 将同一 provider 的三个模型所得结论准确限定；
5. 把论文从“漏洞修复说明”改为“一个重要的视觉测量发现”。

**仍遵循作者要求：假设计划中的模型实验已经完成。** 不因当前目录中没有真实模型分数而扣分，也不把“完成实验”假设成“实验结果必然支持论文”。由于具体效应、错误分布和人审结果不可见，推荐只能是条件性的。如果真实结果展示了上述控制下有意义、可复核的诊断发现，补好定位后可以达到 Weak Accept；仅有完整结果表或模型分数不同还不够。

## 2. 先纠正上轮审稿中的过强结论

上轮最终报告写过：“解出 A，再按 first-non-A 规则，可以在不看 B 图时得到 67/67 Both。”**这需要额外拥有 A 侧答案及配对信息，不能直接认定为实际 runner 下可实现的攻击。**

当前论文 §4.4（`main.tex:314–321`）明确两侧独立调用，另一端不作为会话历史；`run.py:26–38,77–92` 按单个 observation 构造独立请求。B 请求不包含 A 答案、pair membership 或 A 图像。上轮核查并未证明模型可以通过合法的 B 输入获得这些额外信息。

正确结论分为三层：

- **已确认的合法单观察先验**：v2 B 侧固定选 A 命中 57/67。这确实无需额外信息。
- **额外给定 A gold 的条件规则审计**：v2 first-non-A 命中 67/67，说明生成规律高度可预测；它不是协议内满分攻击的证明。
- **尚未证明的实际利用**：不能由上面两条推出某个模型真的利用了跨臂信息或生成规则。

这项更正也适用于论文当前引言 `main.tex:106–108` 的“permitting perfect Both without reading B”：建议明确加上“when supplied with the correct A answer”，与 Table 2 的 oracle 注释一致。不需要为我上轮过强的说法继续增加实验成本。

此外，oracle 规则的准确率不是视觉模型的成绩上限。模型超过 34%、40% 或 44% 不是可疑证据；不能据此判定泄漏，也不能用它们设置录用门槛。

## 3. 本轮认可的实质改进

### 3.1 Part-type 的旧分布偏差已修复

依据 `visual-manifest.json` 与 `answer-prior-audit.json`，本轮重新核算得到：

| 项目 | evidence-v2 | evidence-v3 |
|---|---:|---:|
| A 侧 gold 分布 A/B/C/D | 10/23/16/18 | 16/17/17/17 |
| B 侧 gold 分布 A/B/C/D | 57/10/0/0 | 17/17/17/16 |
| 固定 A 的 B 侧命中 | 57/67 | 17/67 |
| oracle-A first-alternative 命中 | 67/67 | 23/67 |

v3 的 4×4 转移矩阵对角线为 0，其余每格 5 或 6。仅使用 A choice 的全局确定性映射，在这组冻结数据上的最大命中率是 24/67，即 35.82%。这个限制**仅适用于该受限特征类**，不覆盖额外的几何、标签或图片特征。`priors.py:80–98` 实际执行 Part-type 的全量设计约束。

两侧 Part-type 的观察和渲染已更新，不能迁移旧人审和旧模型响应。这是实质修复，不是改名。

### 3.2 完整模型集合已被冻结

`model-roster.json` 实际列出 GPT-4.1、GPT-4o、GPT-4o mini 三个固定快照。每个模型有 visual、no-image、graph 三种条件，**合计 9 个 run，而不是 3×9 个 run**。

`roster.py:63–101` 验证配置哈希、固定条件及 expected run set；`analyze.py:205–260` 要求所有计划 run 完整进入分析。旧版只有未冻结候选，不应描述为“违反六模型承诺”或“事后从六模型削减至三模型”。

### 3.3 跨臂人审暴露已在指派层消除

`qa.py:32–71` 验证同一 reviewer 不看同一 parent 的其他 arm 或 auxiliary panel。冻结指派为 6 位初审者，分别 115、116、114、115、115、119 条，共 694 份计划原始判断，覆盖 347 个 observation，每个两份。

`private-mapping.json` 报告 cross-arm/auxiliary exposure 为 0；代码有相应断言和测试。这里只认可指派规则，不把它等同于已观察到高人际一致性。

### 3.4 来源依赖和失败分母处理有进步

论文 §5.3 及补充 §5.3 列出 24 个源、18 个 primary-author groups、17 个 contributor-connected groups，使用作者/贡献者聚类与逐作者剔除敏感性分析。

模型失败、拒答、格式非法和显式关闭的未调用项仍保留在计划分母；`run.py:108–125` 区分未尝试和已尝试但未收到回执的中断项。单次调用估计不声称跨调用稳定性，边界合理。

### 3.5 图挑战维持窄而准确的定位

12 个 strong-change pairs 来自 8 个源，仍是 six-cycle / two-triangles 加孤立点的单一构造。论文 §6 明确它是 hypothetical graph 的方法学演示，不是物理连接发现，也不是新的 1-WL 不可能性定理。

**已承认且与证据一致的范围限制，不再单独作为新的 MAJOR 反复扣分。** 只有最终把该结果推广为一般结构推理能力时才构成过度声明。

python3 -m unittest discover -s benchmark/suite/ldraw-evidence-v3 -p 'test*.py' -v

## 4. 问题一：最接近的近期工作未进入定位，科学增量仍需说清楚

**严重度：MAJOR；当前最影响录用的部分。**

### 证据与影响

论文 §2 已覆盖 VQA v2、contrast sets、Winoground 及积木领域工作，但未覆盖本轮查到的 VisualFLIP。其 arXiv 页面显示首次提交于 2026-06-05，摘要与正文提出同题图像干预、确定性答案翻转、两侧独立调用、双侧正确率，以及区分单侧正确与答案不更新的行为指标；还单独研究顺序会话。它直接重叠于本稿“答对不等于使用了关键证据”的动机与核心评估设置。这里依据的是预印本，并不声称它已经获得会议录用。<RichMediaReference>["https://arxiv.org/abs/2606.07872","https://arxiv.org/html/2606.07872v1"]</RichMediaReference>

这不是说 BrickAtlas 与其完全相同，更不是抄袭判断。可成立的差异包括：**源 CAD 可追溯的 display-reference 契约、受限规则类上的全局题目分配、每个 exact observation 的人审与请求绑定、来源/作者依赖控制。** 但这些必须产生原有配对评测无法提供的具体诊断信息，不能只形成更长的工程检查清单。

### 具体做法

1. 在 Related Work 新增直接近邻对比，至少比较任务对象、干预语义、oracle 权限、配对指标、人工可判定性、先验控制与推断单元。
2. 明确已有基础：pairing、Both、答案随关键证据改变，本身不作为首创。
3. 从本稿已有数据中展示一个可复核的“增量”：例如控制答案分布、显示指向歧义或来源依赖后，普通评价会误读哪些行为。实际结果无此现象时如实收窄，不制造案例。
4. 将工程贡献与科学发现分开：哈希与完整日志保证可审计；它们不能单独证明新的视觉能力构念。
5. 不要求把 VisualFLIP 全量重跑后才可投稿，但不能仅在参考文献末尾加一条而不改变贡献讨论。

**验收**：读者可以明确回答“为何在已有 paired visual evidence benchmarks 之外仍需要 BrickAtlas”，且答案不是仅仅“换成积木、增加更多检查”。

## 5. 问题二：图像依赖与正确指代依赖还没有完全分离

**严重度：MAJOR；可通过准确定位加一个有针对性的控制处理，不要求全面扩题。**

### 5.1 Color 实际是单对象感知任务

全量检查 `visual-manifest.json` 的 146 个 Color endpoints：每个 `render_spec.render_operands` 长度均为 1，`labels` 也均为 1。主文 Figure 1 与渲染契约一致。

因此，忽略题目中的 B 编号，识别图中唯一积木的颜色，也能符合解题目标。Color 可以是干净的 rendered-appearance 感知与图像依赖测试，**但不能单独证明多对象间的编号绑定或 reference selection 能力**。这不是答案泄漏；简单感知本来就允许简单方法。

建议增加一个合法单图的低复杂度颜色基线，或 label-blind 控制，量化实际难度。我没有跑该程序，不能写成“已满分”或断言模型采用这种策略。

### 5.2 no-image 的 Both 下降部分来自题目结构

`run.py:26–38` 删除图像、保留文字。本轮逐条核对 140 个 pair 的真实 wire：**删除图片后，每对 A/B 的 messages 完全相同**，而两侧 gold 不同。

因此，对于同一输入产生同一输出的确定性系统：

- no-image 的两侧预测相同；
- 不可能同时命中两个不同 gold，故每对 Both 为 0；
- 对称端点准确率每对最多为 1/2。

这是条件性数学结果，不是声称托管 API 完全确定，也不是实测某个模型分数。

于是，visual 相对 no-image 的 Both 增益能说明图像带来了有用信息，但**不能仅凭这个增益证明系统读的是被指定对象的关键证据**。移除整图还会改变模型是否愿意回答、格式有效性等；正文已有失败拆分，解释时要保留这条边界。

### 具体做法

推荐最小路径：

1. 将 Color 明确标为 appearance / image-dependency sanity track；主要的 reference-grounding 结论由 Part-type 承担。
2. Part-type 增加一个当前版本的 answer-preserving 对照：交换两个非正确候选的标签，匹配改动区域及标签数量，正确目标标签保持不变。与当前“正确候选参与交换、gold 改变”对照。
3. 保持模型单侧独立调用，分别报告应改变时的正确率、应保持时的正确率及错误改变率，而不是只看答案有没有变。
4. 新控制有新 wire/hash/QA；不能直接套用旧版本的 camera 或 ID permutation 响应。
5. 若不增加控制，则把结论限定为“在这些确定干预下的 paired correctness”，不扩大为一般证据选择或稳健指代能力。

辅助 panel 已改变空间布局和可见性，论文对此声明正确；它不能独自替代上述针对性控制。

## 6. 问题三：QA 筛选后，先验基线与模型分数可能不再同口径

**严重度：MAJOR（分析覆盖缺口）；不是已发生的数值错误。**

### 精确位置

- `analyze.py:69–78`：模型结果同时计算 full 和 `qa_both_decidable` 子集。
- `analyze.py:275`：`answer_position_baselines` 直接加载全量 `answer-prior-audit.json`。
- `priors.py:80–98`：边际、转移矩阵及 .30/.40 约束检查的是全体 67 个 Part-type pairs。

QA 子集可能改变 gold 分布、A→B 转移、来源组成及来源权重。**全量题库的 17/17/17/16 分布和规则上界，不能自动用于筛选后的子集。** 目前没有实际 QA 结果，不能说已经出现失衡，但代码尚未为最终读者给出相同子集的先验对照。

### 具体做法

1. 在 QA 冻结后，按同一 `pair_id` 集合筛选合法先验与 oracle 审计的 `per_pair` 记录。
2. 对 full / both-decidable 两套数据，各自重算 A/B marginals、转移矩阵、fixed-choice、text-only 及 oracle-A 规则。
3. 所有模型和基线使用相同的 source 集合、同一 equal-source 权重定义。明确哪些是合法模型输入基线，哪些是额外权限的构造审计。
4. 在两套模型表中放各自的对应基线；空子集或无 eligible source 保留 null，不填零。
5. 加一个测试 fixture：QA 恰好剔除某些答案位置后，报告应呈现新的不平衡，而不是继续宣称原来的全量约束成立。
6. 不要为了让筛选后结果更好看再调整 QA，也不应强迫筛选后继续满足旧 .40 设计门。报告变化及其影响即可。

**验收**：每个 published model number 都能找到同一 denominator、同一 weighting 的 baseline 和 coverage。

## 7. 问题四：三个同 provider 快照的代表性有限

**严重度：范围限制；若推广到通用 VLM 能力则为 MAJOR。**

论文 §5.4 与 roster 已明确：三款 OpenAI 快照、同一 transport，不是跨 provider 或最新模型榜单。这种选择可以控制接口差异，不应继续按“没有冻结模型名单”扣分。

但它不能充分支持关于广泛 VLM 群体、开源/闭源模型或 provider-independent benchmark behavior 的结论。不能未经证据将其差异归因于参数规模；闭源具体规模不是本审稿已核验事实。

### 具体做法

- 最省成本：保持既有名单，将所有主要结论限定到这三个快照及当前解码/视觉接口；重点讲清可重复的错误结构，不用“大多数先进 VLM”等泛化措辞。
- 若希望强调广泛适用性：增加一款独立模型家族的代表，建立单独的新研究版本或预先冻结的扩展协议，不能偷偷追加到已经锁定的三模型结果中。
- 不要求凑到六个模型，更不要求强制跨 provider 统一不支持的参数。披露模型输入、图像处理、推理预算和解析差异。
- 若主要差异由 timeout/refusal/invalid 主导，应作为接口/服务结果报告，不能包装成纯视觉理解差异。

## 8. 问题五：论文依然偏“修复过程叙事”，独立价值没有占据中心

**严重度：MAJOR（研究呈现），不是要求再加一轮工程门。**

### 具体证据

主文摘要突出 prior shortcut、review assignment、frozen roster；引言 `106–112` 从“earlier Part-type assignment”切入；§4.3 用较多篇幅写求解器、整数成本和检查门。它们重要，但第一次读这篇论文的审稿人不了解历史版本，未必关心作者修好了什么。

即使所有模型指标已填上，若结论仍是“做了一个语义明确且没有已知明显漏洞的题库”，贡献力度仍然偏弱。图部分已经明确是单模板的 supporting audit，不能代替核心视觉发现。

### 具体做法

1. 摘要和引言先写科学问题及真实发现；版本修复历史移到 supplement / artifact change log。
2. 主文保留三类核心证据：两个视觉族各自的 paired behavior、同口径的基线/控制、一个来自真实回执的诊断案例。只填实际观察到的内容。
3. 方法正文保留“为什么这个设计能排除某类替代解释”，把实现 checksum、冻结流程、求解器成本等细节下移。
4. Figure 1 的 Part-type 裁剪省略了被交换的远端候选，图注已诚实说明。建议增加一个小的全视图 inset，让读者看见两条绑定如何互换；这提升可理解性，不意味着当前模型输入缺候选。
5. 不用模型排名翻转作为成功标准。排名相同而错误类别、难度分层或改进策略显著不同，同样可能有诊断价值；反之，少量样本造成排名反转也不自动有价值。

**验收**：删去版本历史、文件哈希和工程测试数量后，论文仍然能够用一段话说明对视觉研究者的新认识及其用途。

## 9. 哪些事情不应继续要求作者返工

### 9.1 Color 的 43.84% 不是拒稿阈值

Color 中 last-alternative / cyclic-previous 各命中 32/73（43.84%）。这是特定 oracle-A 规则的表现，不是视觉模型可达到的上限。全局“仅以 A choice 为输入”的最佳确定性映射实际上是 33/73（45.21%）；两者也都不是通用无图攻击的上界。

论文已在 §4.3、Table 2 和补充材料公开这些数值，并注明 Color 未优化。Part-type 的 .40 是特定设计合同，不是所有任务必须统一遵守的科学标准。因此本审稿**不因 Color 超过 .40 就要求重新渲染、重新人审、重新跑所有模型**。是否增加 Color 转移平衡，应由研究主张与新控制需求决定。

### 9.2 无需为了接收制造 rank reversal

不能要求 Both 与 AAcc 必须异序，更不能把相关系数等于某个值作为拒稿开关。重要的是有无可解释、可信且对研究有用的新增诊断。

### 9.3 不使用无依据的排除率或错误率门槛

不设置“invalid 必须低于 10%”“QA 排除超过 30% 就拒稿”之类数字。应看排除原因、有效覆盖、结论对排除是否敏感，以及任务到底在测语义能力还是接口可靠性。

### 9.4 正确处理置信区间

同题配对比较应分析**配对差值区间**；不要求两套独立区间完全不重叠才可判断差异。多重比较目前标为探索性，若要做确认性主要结论，则预先限定比较或采用适当多重比较处理。小样本不意味着 source bootstrap 固定以 1/24 为数值步长。

### 9.5 不用“文件多”证明可复现

sealed manifest 包含哪些文件，与第三方在干净路径实际可运行是两件事。论文源码 ZIP 只承诺编译论文，不应被当作 benchmark 全包；反过来，源码 ZIP 不含题集也不是整个项目不可复现的证据。

## 10. 假设模型实验完成后，如何决定是否接收

### 支持 Weak Accept 的情况

- 与直接近邻工作的差异有明确证据，而不仅是素材换域或工程记录更完整。
- Part-type 的结果在合法单侧基线、可判定子集、来源/作者敏感性下仍显示具体诊断价值。
- 图像撤回的影响与失败格式被区分；如声称正确 reference selection，有相应而非泛泛的控制支持。
- 与主题一致的范围足够清楚：Color 感知控制、Part-type reference test、graph 方法学演示不混成总分。
- 正面或负面发现都可以成立。没有预设必须哪个模型领先、必须多高的准确率或必须出现排名反转。

### 仍倾向 Weak Reject 的情况

- 主要贡献仍是已有的 paired-answer evaluation，未讲清当前近邻之外的增量。
- 把 no-image Both 接近零直接当成“模型正确读取被指对象”的证明。
- 把全量先验平衡保证用于另一个 QA 子集，混淆比较分母。
- 把三个同系列快照外推为普遍 VLM 结论，或把单模板文本图任务外推为装配智能。

因此，本轮不是“又发现一个必须推翻题库的致命 bug”，而是**从实现修补阶段进入科学定位与可识别性论证阶段**。不要继续无限扩大 benchmark；先把这两件事讲透。

## 13. 补充复现检查：当前仓库通过，不等于独立环境回放

### 13.1 论文源码 ZIP 与重新生成论文资产是两条路径

`benchmark/paper/evidence-v3/BUILD.md:68–72` 明确承诺：解压论文源码包后，通过已准备好的图表和参考文献编译 main/supplement。检查 ZIP 条目可见 `figures/given-order-replay.pdf`、`references.bib` 和其他预生成材料。因此，不能因为它没有全部 benchmark 数据而说论文源码包不完整。

但是，`publication.py:77–80` 重新生成资产时会读取 `benchmark/paper/evidence-v1/figures/given-order-replay.pdf`；`publication.py:204–206` 会读取 v1 的 `references.bib`，再拼接当前 `additions.bib`。这两个旧版路径存在于作者完整仓库，却没有直接列入本次905文件的 delivery manifest。BUILD.md 另提及历史 preservation lock 与归档，故仍需明确告诉第三方如何恢复这些传递依赖，不能把新文件清单误当自包含的全项目。

**特别校准**：本轮字节级核对确认，当前 v3 `references.bib` 恰好等于“v1 bib + 换行 + v3 additions.bib”。因此两版 bib 不同是显式生成逻辑的结果，不能仅凭内容不同就认定为误读旧参考文献或数据损坏。

### 13.2 建议的最小修复

1. 在 BUILD.md 分开写清：仅编译论文源码包、读取冻结刺激做离线请求校验、从源记录重建全部资产，各自需要哪些文件和依赖。
2. 对旧版图和 bib，选择显式随包提供，或列出可访问的历史归档、哈希及恢复命令；不要依赖作者目录里碰巧存在。
3. 补可移植的依赖规格与安装说明。无需捆绑整套虚拟环境、Node二进制或 node_modules；作者机器的本地路径不能单独充当安装说明。
4. 在新的临时目录仅恢复声明过的材料，使用文档化环境，跑论文编译与无凭证离线验证。记录实际执行结果和不能复现的部分。
5. localhost HTTP 200 只能证明本机路由可访问；若论文承诺公开下载，需另验公开入口，而不是把本机地址当发布链接。
