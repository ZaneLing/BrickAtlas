## 问题一：核心贡献仍是“修复与交付系统”，没有围绕一个正面的视觉研究问题组织

**优先级：最高研究优先级。不是要求再改一次题库，而是让工程成果服务一个可检验的研究问题。**

### 证据与影响

- PDF 第1页摘要与贡献段，`main-v2.tex:61–77`：以修复上一版 shortcut、白名单、oracle、快照和审阅工作流作为重要贡献。
- §6，`main-v2.tex:395–416`：多次强调尚不证明诊断、整合、物理结论。这些边界正确，但正文缺少相应清晰的正面回答。
- 主论文的四幅图只有 `\plateid`、没有标准 caption，见 `main-v2.tex:39–42、216–225、288–291、303–309`。配对图在第5页主体较小，读者难以独立判断三个条件的差异。

**审稿人的疑问**：即使不关心你们 v1 的开发历史，这篇论文让我学到了什么？为什么这套真实装配和统一实例身份是回答问题所需要的？

### 具体步骤与做法

**步骤1：冻结一个主问题和两个支撑问题。**

推荐的主问题是：

> 对真实装配中的同一零件实例，模型回答是否会正确跟随任务相关视觉证据的改变，并在不改变语义的标签、视角和颜色扰动下保持稳定？

这是**研究问题**，不是“模型确实存在某类失败”的预定结论。主范围限定为已有 Color / Part-type；S/G/E 是可审计的模块化对照，不被解释为同一道题的完整推理链。

支撑问题限定为：
1. 同相机的 full-scene / background-mask 比较，背景可见性对答案有何影响？
2. 在移除图的简单先验后，模型是否仍能随关系结构而非输入表面统计作答？

先写一页 `research-story.md`（拟新增，建议放在新的修订目录），包含：问题、已存在的条件、主要估计量、潜在反证、能支持的最大主张。不要先挑某个表现漂亮的模型决定主线。

**步骤2：锁定证据到主张的映射，不靠换词制造贡献。**

- 视觉证据跟随：使用问题三的“当前图像答案命中率”和“双正确率”，不能只用错误率上升。
- 身份鲁棒性：使用已有 `operand-only` / `id-permutation`，分别报告正确保持与一致错误，不把“输出没变”全算优点。
- 背景影响：使用已有 `full-scene` / `background-mask`。固定相机、尺度、光照和标签位置；明确非目标物体隐藏也可能暴露遮挡部分，测量的是该访问干预的总效应，不直接称为纯注意力效应。
- 视图访问：`operand-only` / `multi-view`，保持当前协议的“固定双视图”称呼，不写成主动工具探索。
- 图证据：采用问题二、三中超越节点先验的配对结果。

如进一步分析目标投影大小、遮挡、近同型干扰，先定义可复算字段。没有对象 mask 时不要从截图肉眼估一个遮挡百分比；可以使用已有人工审核标签，但须注明标签形成方式。看过模型结果后才设计的分层应标为探索性分析。

**步骤3：调整章节职责，而不是再堆章节。**

- Introduction：实际问题 → 现有评测的具体缺口（问题五核验）→ 本文设计 → 有依据的发现。
- Benchmark：源与实例身份、观测契约、任务范围、真实场景与局部问题的关系。
- Measurement validity：简要交代已修复捷径、简单先验基线、独立验证和视觉可判定性。
- Experiments：按研究问题排列，而非按脚本执行顺序排列；主要内容为视觉证据跟随、背景/视图访问、结构证据跟随。
- Discussion：将结论限定在实际源和契约内，不重复整篇工程防护声明。
- Supplement：详细 v1→v2 变更、请求/路径安全、所有 oracle 测试、源码哈希、完整题库。

“修复自己的旧生成器”保留透明记录，但从主要创新改为测量质量控制。若想把测量修复本身做成研究贡献，则须额外证明其方法或发现能推广到其他真实基准；这不是本轮最小路线的要求。

**步骤4：按内容重做图的职责与图注。**

- Figure 1：不只是装配拼图。用一个真实实例说明图像、记录、图和编辑如何对齐；明确“不同任务共享身份，不是单题跨模块链路”。
- Figure 2：若保留六步展示，标注(a)–(f)和“given-order visibility replay”；不要让恒定程序占据主要科学发现的位置。
- Figure 3：保留答案先验作为测量质量图，来源限定ID的低重复率与语义类别的多数率分开，不画成可直接排名的同一指标。
- Figure 4：显式标注 Full / Mask / Crop；展示足够大的同区域局部放大，并保留全景说明。放大窗属于论文说明层，不得回写模型输入。标题与 caption 说明控制变量、变化变量及不支持的解释。
- 四图均改为正常 `\caption{...}\label{...}`，去掉对应 `\plateid` 调用，避免双重计数。检查交叉引用更新。

**步骤5：等问题二至五的证据齐备后，再写发现。**

每条发现按“对象和条件 → 指标和估计值 → 不确定性 → 结论边界”写。若结果不支持原假设，报告该范围内未获支持，不通过换分母、换模型或只展示个案强行保住主线。

### 是否需要补实验

- 章节重组、图注、导入已有结果：不需要模型调用。
- 已有条件有完整响应：先按问题三重算。
- 想解释新的机制但现有条件不能隔离：再增加单独的验证条件，不能把探索分析改称预注册。

## 问题二：Graph deletion 的整数回答仍被“节点数减一”强先验支配

**优先级：最高测量优先级。先加基线和分层，再决定是否扩展图题；不撤销已正确完成的整数格式修复。**

### 证据与影响

- PDF 第4页 §4.1 明确记录：63/73题正确答案等于最大合法连通分量数。
- `questions.ts:80–117`：从目标邻居和少量干扰点构建局部图；删除目标后经常不再有存活边。
- 上一轮已从真实保存的 `request-snapshots/standard` 全量核验：仅输出 `len(set(input.nodes))-1`、完全不读取边，可答对63/73，Micro为86.30%，24源Source-macro为83.75%。这是已复算的非模型基线，不是模型分数。

**影响**：整数输出去除了“第二小选项”捷径，但没有使高图分数自动成为结构推理证据。不能继续只报60.27%的“总猜4”基线而不报更强的节点条件先验。

### 具体步骤与做法

**步骤1：保留73题，建立节点条件基线。**

拟新增 `node-prior-audit.py`，其预测函数只能接收模型侧节点列表；之后另开评分阶段读取参考答案。不要把完整带答案对象传入预测函数。

```python
# 预测阶段：不允许读取 edges 或参考答案。
def predict_without_edges(public_input):
    return {"value": len(set(public_input["nodes"])) - 1}
```

每题保存：task_id、source_id、request_hash、预测、gold、是否命中。汇总 Micro、Source-macro、每源成功数、失败题清单。将该基线加入实际图结果表。与模型比较时使用相同73题和相同源聚合。

**步骤2：分析阶段按结构分层，但不要筛掉容易题。**

从无向去重边图计算：
- `n_before`、`m_before`；
- 删除目标后的 `n_after`、`m_after`、`component_count`；
- `deficit = n_after - component_count`；
- 原图连通分量数与目标度数。

至少报告：
- `deficit = 0`：节点数基线必对；
- `deficit > 0`：必须处理存活边才可靠；当前分母为10题，需要显示小样本限制。

这些字段仅供分析/分层，不发给模型。保留整体结果，不能把节点数基线答不对的10题选择性当作新的主测试集而隐藏其余题。

**步骤3：先利用已有图干预计算双正确率。**

当前 `conditions.ts:33–43` 添加一条连接两个存活分量的边，正确答案下降1，节点列表不变。它足以直接检验节点数基线在成对问题上的失败，但还不是全面的结构难度覆盖。按问题三计算原图和干预图均正确的比例；同样计算节点数基线的双正确率。

**步骤4：新增独立的结构匹配扩展，而非改写原CAD。**

仅在现有10题和单向干预不足以支持结论时实施：
1. 原始任务不变，派生题保存 `parent_task_id`、变换类型、生成种子和新哈希。
2. 优先匹配相同节点集合和相同边数、但删除后分量数不同的图；进一步可匹配目标度和存活度数序列。
3. 同时包含答案增大、减小、不变的变体，方向可行性由独立oracle确定；不能每题恒定“答案减一”。无法生成某类变体就报告覆盖缺口，不补造原始连接。
4. 原图、派生图打乱试次顺序、独立会话作答，不告诉模型变换名称或答案方向。
5. 非源实际连接的图明确标为 `hypothetical-evidence`，仅检验给定图推理。它们不能用来证明真实CAD物理连接，也不能增加真实源计数。
6. 每个源、每个原题的派生数预先限制并记录；更多变体不构成更多独立样本。

**独立单元测试示例（合成测试夹具，不是真实题库数据）：**

使用目标 `t` 加六个存活节点 `a..f`，两图均包含 `t` 到六节点的星形边。
- 图A额外有六节点环 `ab,bc,cd,de,ef,fa`，删`t`后为1个分量。
- 图B额外有两个三角形 `ab,bc,ca,de,ef,fd`，删`t`后为2个分量。

两图节点数、边数、目标度和存活度数序列相同，但答案不同。这个夹具验证算法和“仅数节点/边/度数”的不足，不应冒充原始装配样例。

**步骤5：同时展示自然分布与挑战分布。**

原73题保留自然分布结果；匹配图作为独立受控挑战集。先冻结生成规则再看新模型响应。若受控图不符合自然连接分布，应报告这一限制，而不是将二者直接合并计算更好看的总分。

- 原图/已有graph-intervention双正确率：若响应齐全，无需API。
- 新的匹配图：需要新增题目核验和对应推理，不能从旧结果估算。

## 问题三：干预分析没有明确区分“跟随新证据”与“单纯被扰乱”

**优先级：高。主要是新增离线分析层，不应破坏已有评分结果。**

### 证据与影响

- §5.2以准确率差和correct-to-wrong / wrong-to-correct为主。
- `paired-analysis.py:33–63`只读取各题success，不读取预测语义或替代gold。
- `src/benchmark-v2/render.ts:102–117`已经保存wrong-image的 `alternateChoiceId`。
- `run-model.ts:98–100`仅对graph-intervention重算gold；wrong-image保留原gold用于依赖性分析。这是有意的原协议，不是评分bug。
- `experiments.ts:27–41`正确使用 `operand-only` 对比 wrong-image、ID置换、相机与颜色扰动，保留这些对照，不重新混入旧standard渲染差异。

**影响**：wrong-image的原gold准确率下降，可能是正确跟随新图片，也可能是完全混乱；graph-intervention前后准确率差为零，也可能意味着两次都正确。

### 具体步骤与做法

**步骤1：新增“证据适应分析”，保留旧scores.json不变。**

拟新增 `evidence-adaptation.py`，输出新分析文件。读取原始 `submissions.json` / receipts、运行manifest、两条件真实请求，以及配对gold。仅scores.json的0/1信息不足以支持wrong-image跟随分析。

每一对必须绑定：
- pair_id、parent_task_id、source_id；
- model_revision、adapter_hash、prompt_hash、analysis_version；
- condition_A/B、request_hash_A/B、规范化预测_A/B；
- gold_A/B、gold来源和哈希；
- `truth_policy`（事实改变 / 语义不变 / 信息撤回）与错误原因。

原始choice字母只有在ID语义映射一致时才能比较。集合先去序但不能悄悄移除非法重复；动作仍由执行契约判断。缺失、超时、非法JSON不删除，按原预注册分母计失败。

**步骤2：明确三类干预的评分语义。**

- **事实改变**：wrong-image与graph-intervention。A、B各自有证据对应的gold，两个gold应不同。wrong-image保留原gold分数作为辅助字段，另报新图gold分数。
- **语义不变**：ID置换（映射回规范身份）、选项展示顺序、边序，以及已证明保持目标可判定性的视觉扰动。比较正确保持和一致错误。
- **信息撤回**：无图、无边。保留原任务gold用于比较，但明确它可能已无法由现有输入确定；下降不是新证据跟随率。

**步骤3：wrong-image新增四类结果与两个核心指标。**

设一对证据对应答案为 `yA != yB`，模型输出为 `pA,pB`。对所有N对：

```text
new_evidence_accuracy = sum[pB == yB] / N
paired_both_correct   = sum[(pA == yA) and (pB == yB)] / N
```

B输出分成互斥四类：新证据答案 `yB` / 沿用旧答案 `yA` / 其他合法答案 / 非法或缺失。四类数量必须合计N。

可选条件指标：

```text
adaptation_given_A_correct = sum[(pA == yA) and (pB == yB)] / sum[pA == yA]
```

条件分母为0时返回 `null`，不能返回0；必须同时展示分母和无条件指标，不能只报条件成功率。

逐条用 `paired-renders.json` 中的 `mismatch.alternateChoiceId` 生成gold_B，并核对该标签在B请求中确实指向预期视觉内容。Color错图可能替换了零件形状，结论只能是“跟随新视觉证据”，不能直接解释为只对颜色干预的因果效应。

**步骤4：graph-intervention新增配对双正确率和语义变化检查。**

- 双正确率：A与B分别按各自图oracle判断，两个都正确才成功。
- 无条件输出变化率只能辅助显示；两次随便换答案也会变化，不是推理成功。
- Neighbors的set比较必须按候选语义而不是数组顺序。
- 为node-count-only、固定答案和真正图算法也计算相同指标，建立可解释参照。
- 对原图—干预图的双正确率低但平均准确率高的模型，明确指出不具备稳定结构证据跟随的证据。

**步骤5：语义不变条件新增“正确一致 / 错误一致”。**

至少区分：双正确、A对B错、A错B对、双错误但同一语义答案、双错误且答案不同。不要把总consistency直接称为鲁棒性；恒定错误模型可以非常一致。

ID置换当前把标签改成较长的新编号；若要解释为“纯身份绑定”，需补同长度双射且尽量保持文字框布局的对照。否则表述为“编号命名与显示扰动下的稳定性”，不把token长度和版面变化排除在外。

**步骤6：实现统计与单元测试。**

- 沿用源聚类。若一原题有多个变体，先在原题内平均，再源内平均，最后跨源；不能让派生多的题占更大权重。
- 双正确率与模型—基线差值均给配对source-cluster区间，保留源数。重复推理不增加源数。
- 必测夹具：两次全对但delta=0；始终旧答案；随机其他答案；全部非法；A全错导致条件分母0；不同模型/数据版本错配被拒绝；重复pair被拒绝；缺失B不能默默取交集后缩小分母。
- 明确核对运行manifest中的condition、模型版本、adapter和数据哈希。不能仅task_id重合就配对。

### 是否需要补实验

若已有原始输出、真实请求和替代gold，大部分可离线完成；只有缺失原始响应、缺失条件或新增同长度编号对照时才需补跑。不能从success=0推测模型究竟选了哪个错误答案。

### 验收标准与失败处理

- [ ] wrong-image沿用旧gold的原评分保留，新增新证据gold评分不覆盖它。
- [ ] 四类错图输出严格合计N；无条件/条件指标分母显式可见。
- [ ] 两次全对的模型会得到双正确率1，而非因delta=0被误判“没使用图”。
- [ ] 单独图/渲染oracle只说明gold正确，不被当成模型已跟随证据。
- [ ] 若只能观察到输出被扰乱，论文只写“敏感性”，不升级为正确证据使用或认知模块归因。

## 问题四：任务定位清楚了，但总体排名仍混合视觉能力、基础控制与恒定输出

**优先级：高。先改报告，不为追求高分删题，也不把简单任务全部判为无价值。**

### 证据与影响

Table 2已经标出恒答与查表任务，但Table 5仍有覆盖所有617题的Micro/Macro。§3.2和§6承认24个Evidence limit恒答、17个Step sequence恒程序。按当前任务数据复算：41道恒定控制、140道直接视觉题。

仅按源macro不能解决不同构念混合：它改变源权重，不改变任务的科学含义。

### 具体步骤与做法

**步骤1：给任务增加“报告角色”，不改变原gold。**

建议采用下列报告分组，作为新分析版本，而非宣称现有数据已经这样分组：

- **核心视觉能力**：Color 73、Part-type 67，合计140。两族仍各自报告，不以低难颜色任务掩盖类型对应问题。
- **结构证据运算**：Neighbors 73、Graph deletion 73，合计146。后者必须带问题二基线及配对指标。
- **非恒定基础控制**：Distance 73、Interface 87、Coverage 17、Step lookup 55、Restoration 58，合计290。
- **恒定输出控制**：Evidence limit 24、Step sequence 17，合计41。

全部617题仍留在完整报告。286个核心/结构候选题不能直接被称为已经验证过的“核心推理集”，必须继续满足视觉可判定性和结构基线要求。

**步骤2：重排主结果表，不发明新的综合权重。**

主文第一张结果表按Color、Part-type及必要视觉干预展开；第二张按Neighbors、Graph deletion及其简单基线/双正确率展开。控制项用独立表展示接口遵循、基础查找与失败原因。

完整617题Micro/Macro保留在附录或以“all-task descriptive score”明确标注；不要以它命名最佳综合装配模型。若确需一个总分，必须先定义用户使用场景与权重来源，而不是看结果后调权重。本轮推荐不新增总分。

**步骤3：固定每族分母和质量排除规则。**

- 一个源缺该族题目，不能记0分；只平均有该族题的源，同时列源数与题数。
- 题目无效/视觉无法判定只能根据与模型成绩独立的QA规则处理，保留原始题、排除理由和重跑清单。
- 对实际模型输入尺寸的人审才与模型评价可比。不能用原始高分辨率/额外视角人审通过，证明压缩后单图可解。
- 同一任务在主条件和配对条件中均可判定时才进入相关准确率比较；不满足则单列信息不足/访问差异，不能默默删掉模型失败样本。
- 对API错误、超时、拒答、非法JSON分别记录原因；总体分母不变。格式有效率与条件语义准确率只作辅助，不把无效输出排除后抬高主分数。

**步骤4：从真实运行产物到论文数字形成一条可验证路径。**

当前 `publication.py:59–72` 读取计划并把 `modelResults` / `humanResults` 写为None；`verify-publication.py:53–61` 强制所有结果值为None。

修改时要一起做：
1. 保留不可变的实验计划；新增结果索引，按 `model_revision + condition + dataset_hash + analysis_version` 指向真实manifest与分析结果。
2. 让论文生成器从完成回执/新分析层生成模型数字，而非把数字手写进TeX。
3. 校验器分开验证未运行和已完成记录：未运行允许null；已完成记录须可追溯到回执、样本数、失败数及重算指标。
4. 取消“必须全部null”的旧开发断言，改为状态驱动校验；不要简单删掉所有校验。
5. 取消固定617/14条件等与版本变更不相容的硬编码时，用选定manifest作为权威计数，不改成不检查。
6. 改分析规则后重新生成所有相关表、补充材料和发布清单；保留旧分析版本。

### 是否需要补实验

- 分组、重算与表格生成：通常不需要API。
- QA判定某题无效或输入有变：仅重跑受影响的题/条件，并明确新版本；原成绩不能直接迁移。
- 统一模型条件不能只写相同参数名。需保留精确模型/服务版本、实际图片字节与工具权限；不支持的参数明确报错或记录差异，不能静默忽略。

### 验收标准与失败处理

- [ ] 四组互斥且并集为当前全部题；以上v2计数由数据重算为140+146+290+41=617。
- [ ] 恒定控制不会决定主要能力排名；基础任务没有被删除或藏起来。
- [ ] 所有模型同一比较使用同一eligible集合与格式规则。

## 问题五：Related Work只完成了高层主题对照，尚未证明本文的独特价值

**优先级：高。这里需要的是精读与协议对齐，不是增加引用数量。**

### 证据与影响

PDF第3页Table 1及 `main-v2.tex:79–129` 多次写 `Public abstract checked` / `to verify`。这些是合理的内部研究状态，不能作为完成稿的最终新颖性论证。

**关键问题**：实例ID、真实LDraw和图数据都有相关先例；你需要说明它们在本工作中支持了什么不同的研究问题，而不是暗示邻近工作缺少你尚未核验的能力。

**步骤2：建立协议级证据表。**

## 收尾检查：不新增第六个研究问题

1. **版本保护**：冻结当前数据、模型请求、原响应、评分与代码/图像哈希；不得用旧v1重新生成覆盖v2。
2. **先离线后补跑**：问题二基线、问题三指标、问题四分组尽量从现有数据完成；只有新请求才开新实验。
3. **科学结论以数据为准**：原先已看过的结果再分析属于post-hoc，应明确说明；新挑战集可提前冻结规则，不能倒填“预注册”。
4. **每题可追溯**：参与新结论的每道题都需身份、观测、gold、预测、条件、排除原因与版本一致；每源均有覆盖摘要。指标正确不代表所有视觉题均已可判定。
5. **源与图证据分离**：人为修改边的控制集不被标成原始CAD事实；不改原始几何来美化数据。
6. **只读/帮助命令也要先看实现**：现有 `experiments.ts` 默认会覆盖计划文件，`publication.py` 默认会改图表，`verify-publication.py` 会写检查产物。当前 `BUILD-v2.md` 不能不加判断地整段重跑。
7. **生成与校验同步**：模型结果不再全null时，更新生成器、结果索引、校验器和显示文本，不只修改TeX。
8. **最终PDF回读**：用当前投稿年份官方格式确认页数/匿名要求；逐页检查所有图注、面板、公式、引用和文字。代码、数据与文稿有冲突时先找根因，不能默认代码一定正确。
