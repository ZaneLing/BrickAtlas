# BrickAtlas：面向 CVPR 的研究与全步骤可视化计划

状态：待确认的研究计划；不是已完成实验，也不是录取承诺。
本次只增加本地计划文档，不改变评测逻辑、不调用付费模型、不自动公开投稿意向。
范围：计算机视觉、多模态结构建模、数字装配；不涉及机器人、机械手或VLA控制。

## 1. 评审依据与当前判断

参考已核验的 CVPR 2026 官方作者和评审指南；具体投稿届次的规则必须在提交前重新核验。
不能把2026年的页数、链接、日期或匿名规定直接当成未来届次的已确认规则。
官方关注技术可靠性、知识增量、原创性、潜在影响、可复现性、数据归因与伦理。
官方没有“至少N个样本/模型”“必须新网络”“必须打败SOTA”的通用配额。
若宣称数据集释放为贡献，须能按目标届次要求公开该贡献。

当前系统是工程Pilot，而非已达到投稿成熟度的研究：

| 维度 | 当前状态 | 投稿前需要的证据 |
| --- | --- | --- |
| 数据 | 552配色样本、138几何组、8程序模板、25标准砖板 | 多样而非重复的数据、复杂连接、来源/许可、独立数据审计 |
| 视觉 | 零件图像和逐层检查图；部分任务直接给结构 | 自然多视图/遮挡条件，视觉与符号输入控制，视觉无效或泄漏的诊断 |
| 生成 | 文字+完整占用体积约束 | 真正文本条件生成、约束生成分轨，语义与几何评价分离 |
| 编辑 | 改色、顶部复制、删件 | 相对空间编辑、子装配替换、尺寸/对称修改及非目标区域保持 |
| 连接 | 整数网格stud接触；相对坐标程序 | 可靠连接类型/位姿，区分表示parent与实际连接边 |
| 实验 | 两个低成本模型，每任务两例 | 代表性模型、专用方法、训练对照、重复试验、分层难度与统计 |
| 可视化 | 输入图、最终JSON、收据 | 每次模型调用/工具调用/执行步骤/评分证据可核查，所有case可访问 |
| 主张 | 八任务已跑通 | 哪些能力不等价、如何迁移、哪些差异由视觉/表示/工具造成 |

因此，下一阶段不能只“扩充模板和多调用几个API”。

## 2. 当前测的是模型还是 Harness

Harness是包裹模型的输入组织、提示、解析、工具、执行、反馈、记忆和停止策略。
任何评测都有最小Harness。所谓“模型主榜”是固定最小Harness后的条件化比较，而非脱离协议的纯能力。

| 当前入口 | 模型调用与权限 | 正确解释 |
| --- | --- | --- |
| suite one-shot | 输入固定，一次completion，输出答案/完整结构/顺序，离线评分 | 固定最小Harness下的模型表现；没有自主工具循环 |
| suite validator-once | 一次输出 -> 脚本固定生成合法性信息 -> 第二次输出 | 固定反馈Harness；不是模型自主决定何时检查，也不是完整agent |
| CARE-mini | 每轮截图/状态 -> look/detach/build等动作 -> 环境反馈；可多轮 | 模型+agent循环的系统表现；脚本还负责阶段、记忆交接与故障 |

代码证据：

- suite/runner.ts:83-95：一次调用与固定第二次调用。
- suite/score.ts:11-17：反馈主要适用于结构合法性，QA/规划只得到通用格式提示。
- ../run.ts:105-124：旧系统的多轮观察、动作、反馈循环。
- suite/web/main.tsx:161-164：现页面主要显示最后一次答案，不是逐步执行播放器。

当前辅助反馈对不同任务帮助强度不一致，不能用辅助总分下降推导“验证器无用”。
下一版应提供任务适配、与目标无关的验证工具，并报告各工具的能力边界。

## 3. 建议的论文主线

暂定研究定位：

> A unified benchmark for cross-modal, compositional and executable brick-structure reasoning.

保留八个能力族；用“同一对象的多模态对应与跨任务一致性”统一，而不是把八种问答拼成菜单。
主要研究问题：

H1：识别或重建得分高，是否真的预测后续编辑、补全与规划能力？
H2：换成相同信息量的连接表示后，性能改善有多少来自表示而非模型容量？
H3：在未见几何组合/结构族上，多任务训练是否帮助迁移，或只记住了生成模板？
H4（次级）：在同预算、同输入下，验证工具改善了什么，哪些错误仍无法纠正？

这些是待检验问题，不能预先写成结论；允许结果不支持原假设。
相关性不当作因果性；多任务增益需排除更多数据、更多tokens和训练时间的影响。

拟定贡献包：

1. 有清晰来源、分组划分及丰富跨模态/跨任务标注的结构数据资源。
2. 多解与对称性鲁棒的八任务评测协议，以及可执行过程/失败归因评估。
3. 对主流模型、专用方法、不同表示与训练配方的实证研究。
4. 可审计的全步骤可视化/运行发布工具，作为可复现性贡献，不单独冒充算法创新。

新模型并非CVPR强制要求；本项目若沿用BrickNet式“数据+表示+模型”的贡献路线，
建议至少训练统一多任务基线，并验证它的作用。若数据与评价创新已足够强，
也可以选择benchmark主导论文，但应据实调整贡献，不为凑方法强行发明网络。

## 4. 与已有工作如何区分

| 最近邻 | 已有贡献 | 我们需要补充的不同证据 |
| --- | --- | --- |
| BrickGPT | 文本生成、稳定结构数据、拒绝采样/回滚 | 重建/理解/编辑/规划之间的能力关系，不能仅重做稳定生成 |
| BrickNet | 大规模人工结构、类型化连接图、生成模型 | 同对象多模态多任务标注、受控泛化和过程评价；不是简单相对坐标换名 |
| LTRON / InstructioNet | 拆解重建、显式说明书记忆 | 静态与交互能力的解耦评测，不把主动拆解或保存记忆声称为首次 |
| LEGO-Puzzles / BC-Bench | 空间问答/选件与位姿评测 | 不仅答题；验证完整结构、多解编辑及跨任务迁移 |
| AssemblyBench / RoCo / CHAIN | 轨迹/恢复/互锁交互 | 不声称数字动作或可视化新颖；按本研究的多任务目标限定贡献 |

补充检索需围绕数据、表示、任务、泛化、过程验证逐列核对全文和公开实现。
“前人没把这些放在一个网页里”不是研究空白。
如复用BrickNet数据/代码或LDraw连接注释，必须注明归属并核验可再分发权限。

## 5. 三层评测协议

### M：固定最小Harness，论文主表

- 一次提交，统一输入格式和公开目录。视觉任务只给许可图像，不注入目标程序。
- 符号输入作为独立诊断条件，不与视觉输入混在一个“视觉推理”分数。
- 固定解码设置、输出额度、版本和种子；原文与解析结果都保留。
- 结构集合任务不按输出顺序惩罚；只有计划/顺序任务评执行顺序。

### H：工具辅助，论文次表

- 同一组基础模型、同一题、固定工具能力和预算。
- 能力矩阵拆为：几何目录查询、无目标碰撞/连接检查、局部编辑、视角选择。
- 模型自主选择工具才称为agent/tool-use；脚本固定插入反馈仍称固定Harness。
- 禁止工具返回隐藏目标坐标、完整可行方案、真实错误位置或评分差分，除非另设oracle工具上界。
- 对比无工具、固定反馈、自主工具；对首次输出做冻结配对，必要时从同一初始响应分叉，
  以区分第二轮采样差异与反馈价值。
- 一样的尝试次数不等于一样的成本：报告tokens、工具次数、墙钟时间和预算-成功曲线。
- 部分批量操作成功/失败语义固定，非法请求计入预算，工具返回的信息可被审计。

### O：Oracle与传统算法，只作诊断/上界

- 真值感知、正确子图、正确计划分别作为条件化实验，不能混进主模型成绩。
- 随机、copy-input、检索、传统图/约束规划器作为有效基线；oracle不叫学习模型。
- 不要求BrickGPT等方法输出其从未支持的任务；不适用单元记N/A，适配器开销与信息公开。

每个模型/agent会话在正式独立任务之间清空状态，同对象的前一道答案不能泄漏给后一道。
明确研究跨任务记忆时，单独设定条件，并披露其额外信息。

## 6. 全步骤可视化：先保证真实性

用户要求“所有model步骤可视化”落实为每个样本、每个模型、每个已记录事件均可访问，
不是只展示成功案例。不保证或声称观察到模型不可访问的内部思考。

### 四层事件来源

| 层 | 事件 | 可视化原则 |
| --- | --- | --- |
| Model | 请求、输入图片、实际响应、显式工具请求 | 原样记录。无内部推理日志时显示不可用，不生成解释冒充思维链 |
| Harness | 格式解析、坐标转换、确定性编译、反馈注入 | 明确标记系统行为，不算成模型推理或模型自行调用 |
| Environment | 已接受动作、拒绝动作、状态变化 | 来自真实执行记录；保留失败请求及错误反馈 |
| Evaluator | 匹配、几何/连接错误、最终指标 | 提交结束后的裁判视图，不能提前暴露给模型 |

one-shot输出一个零件集合时，可以逐件“展开结构”，但不能把数组顺序叫模型的可执行装配计划。
如果由规划器重排成合法顺序，标记为“系统生成的演示顺序”，并禁止给模型补记计划成功。
若输出的是plan，按原始plan执行并停在非法步骤，不偷偷调换顺序让动画看起来成功。
对旧日志补做回放，注明“事后确定性重建”；缺失时间戳、未捕获流式chunk或未存反馈不能伪造。

### 页面布局

1. 运行筛选：model、task、split、输入条件、Harness、预算、成功/失败。
2. 左侧：原始输入图像/文字/BOM，以及模型当时真正可见的信息。
3. 中部：输入结构、模型输出、参考目标并排；相机同步，可切连接图和差分。
4. 下方：按事件编号而非伪造时间的时间轴；前进、后退、暂停、跳错误点、批次内展开。
5. 右侧：本步原始JSON、解码后的操作、参数、是否合法、调用费用、反馈与状态哈希。
6. 裁判叠层：缺件、多件、错色、错向、碰撞、错误连接；每项能追溯到具体指标。
7. 导出：运行JSONL、独立回放包、图表、视频。投稿补充视频与匿名包在冻结截止前生成。

主视角只能显示模型当时许可的信息；完整目标与X-ray仅在标明的裁判/分析视角开启。

### 八任务对应

| 任务 | 最低可视化交付 |
| --- | --- |
| parts | 查询图、模型选件、标准件、连接点/对称轴、逐字段正确性 |
| relations | 高亮查询两件、方向箭头、真实/预测连接、相关子图 |
| reconstruct | 原图、预测完整模型、参考模型、匹配与未匹配零件，不伪造建造顺序 |
| generate | 输入描述/约束、生成结构、违规体积/连接、合法前缀（仅序列任务适用） |
| complete | 已给结构锁定，新增部分逐件展开，突出遗漏及擅自修改 |
| edit | 修改前后对照、目标区域与误改区域、模型提供的编辑程序或推导差分标签 |
| plan | 每个原始操作、前后状态、遮挡/通道、首个失败点和未完成集合 |
| repair | 错误声明、修复结果、正常样本误报；有真实交互才显示诊断动作 |

## 7. 数据与八任务升级

### 数据两层

A层：有授权的人类设计结构或足够丰富的结构生成语法，作为语义和视觉主数据。
B层：受控程序化对照，精确改变连接、遮挡、朝向、局部编辑与错误，用于解释失败原因。

工作目标（不是CVPR最低要求）：

- 先做300-500个独立结构的质量验证，确认合法性与标注成本。
- 若质量与许可允许，主集争取5,000-20,000个去重几何组，覆盖几十种结构/子装配机制。
- 先覆盖100-300种经过核验的零件，并按任务需要扩展；优先提高机制多样性而非凑类型数。
- 试验以每主要任务/条件数百例为起点，通过先导方差、效应量和组级相关性确定最终样本量。
- 报告独立源模型、几何组、子模型、配色、描述和派生任务的不同计数。

完整记录来源文件、作者、来源URL、许可、获取版本、源哈希和派生关系。
在提取子模型、配色、渲染、生成说明和派生任务之前按来源家族划分，
避免同一套装/作者复用子结构落入训练与测试。
使用几何、连接子图和近重复检索共同审计，不仅依赖精确文件hash。
旋转等价与镜像/手性结构要区别，不能把不等价结构错误合并。
新增零件泛化必须真正留出零件或连接配置；当前known-part题不能承担这个主张。

### 视觉有效性

- 主条件：普通多视图RGB，标准化镜头与元数据，不给隐藏零件位姿。
- 辅助条件：RGB+BOM、分层/爆炸图；明确其额外信息。
- Oracle条件：真值结构输入，用于定位推理与感知瓶颈。
- single-view有不可辨识时改为可见部分/多解评分，或允许有限主动观察；不能强迫猜唯一内部布局。
- 干预图像移除、视角减少、背景变化、相机变化、目录ID重命名，检测模型是否真在用图像。
- 候选训练与评分语义模型不能无审计地由同一VLM垄断，以防描述和评测偏好互相强化。

### 任务深度

- parts：长尾、相似件、遮挡、连接器配对。
- relations：视图中的位置与连接、长程路径、子装配层级；符号版留作对照。
- reconstruct：复杂组合、多视图一致性、对称/等价匹配。
- generate：自由文本与硬约束两轨；语义满足与几何合法分开。
- complete：不同缺失模式，保留约束与多个合理补全。
- edit：跨部件相对关系、子装配替换、尺寸变化；不能只有属性改色。
- plan：非唯一顺序、不同插入方向、局部拆解后再装配；限定可靠几何域。
- repair：轻微偏移、错误连接、遮挡错误与正常负例；声明证据不可见时的不可判定状态。

数据错误、求解器不确定和真正无解应区别标注，不能混作模型失败。

## 8. 验证器与人工审核

在任务范围内扩展连接器语义、对称群、精确几何碰撞与插入通道；若不模拟力，始终不称“物理稳定”。
名义CAD扣合可能存在允许的接触/形变重叠，不能简单把所有网格穿透判非法。
建设正反例测试库：等价件、连接但碰撞、终态合法但序列阻塞、正确另类答案、无故障样本。
独立专家抽检，不能只用与生成器同一套规则的oracle来证明标注无误。
建议首轮分层抽检200-400例，疑难样本双人复核和仲裁；统计一致性与剩余误差，
不要用“抽检零错”声称全库100%正确。
指标至少分解语义、部件、位姿、连接、过程合法性、修改保持和费用。
开放生成/多解任务不使用唯一目标Part-F1作为最终正确性定义。
如引入CLIP/VLM分数，仅用于语义辅助；用人工盲评、反例和跨judge对照验证其有效性。
人类任务测试遵循知情同意、报酬和适用伦理流程，不需要机械手。

## 9. 实验设计

建议代表性模型而非扫所有API：4-6个模型家族、开源/闭源、至少一组大小模型对照，
实际数量按覆盖目标与预算确定；不视为CVPR规定。

| 实验 | 控制 | 回答的问题 |
| --- | --- | --- |
| E1 八任务能力矩阵 | 固定最小Harness、相同输入/样本 | 能力分布，不以单个总分取代细项 |
| E2 RGB / RGB+BOM / 结构oracle | 同模型同对象、信息条件单列 | 视觉还是结构推理构成瓶颈 |
| E3 坐标 / 连接程序 | 语义信息、目录权限、预算尽量对齐 | 表示是否影响可组合性与有效序列 |
| E4 无工具 / 固定反馈 / 自主工具 | 同起点与工具权限、预算曲线 | 模型与Harness的贡献如何分离 |
| E5 零样本 / 单任务SFT / 多任务SFT | 同backbone、训练tokens/步数与数据来源 | 训练是否带来跨任务迁移 |
| E6 留一任务训练、未见结构组合 | 按源几何组留出所有派生数据 | 迁移是否超越模板记忆 |
| E7 原始/人工结构与程序化结构 | 难度、零件词汇与视图条件匹配 | 程序化结论是否能外推 |
| E8 对称、多解、遮挡与负例 | 固定难度与评测器 | 指标是否奖励正确能力 |

专用方法只在支持任务上比较；BrickGPT/BrickNet与我们的生成轨在可比零件子集和输入条件下比较，
不强迫其解视觉问答、不把转换失败隐去、不直接搬不同数据集上的论文数字横比。
加入检索、图/约束规划、简单程序基线；若简单求解器就解决全部题，需重新解释测量价值。
统一训练基线优先使用现成开源多模态backbone+标准SFT/LoRA，不以新模型结构为前置障碍。
至少对关键随机设置重复3次，记录不确定性；按源对象/家族分组bootstrap，
做配对比较，避免把同模型十个配色当十个独立样本。
同任务ID跨阶段必须锁定数据版本与oracle版本。正式test只在设计冻结后评测，
当前公开Pilot专供开发，不能调好提示词后再叫未见测试。

## 10. 工作包与顺序

下列周期为估计，假设2-3名研究/工程成员及可用训练GPU，不是截止日期承诺。
单人、许可审批或硬件受限时需要相应延长；不为赶某届deadline牺牲证据。

| WP | 优先级/建议周期 | 工作与产物 | 依赖与验收 |
| --- | --- | --- | --- |
| R0 定题与主张 | P0 / 3-5天 | 最近邻全文矩阵、假设、实验预注册、指标合同 | 一页说清为什么不是BrickNet/BC-Bench复刻；不能仅“8任务” |
| R1 全步骤可视化 | P0 / 1-2周 | Event IR、70-case迁移、输出3D/差分、所有调用与执行回放 | 不花模型费用迁移旧日志；来源标记清楚，终态分数一致 |
| R2 数据可行性 | P0 / 1-2周 | 许可清单、300-500独立结构试生产、schema与split | 许可可发布；剔除坏数据并报告覆盖率；无已发现跨源泄漏 |
| R3 可信标注/验证 | P0 / 2-4周 | 连接与几何、对称、多解、正反例、人工审计 | 独立审核与反例测试通过；不确定域显式限制 |
| R4 八任务研究版 | P0 / 2-3周 | 自然RGB条件、更深编辑/补全/生成/规划、诊断条件 | 每题可解释可评分；无解/不可辨识不强迫唯一答案 |
| R5 训练与基线 | P1 / 3-5周 | 统一基线、单/多任务、专用方法适配、模型矩阵 | 使用正确split；权重、配置、训练日志与计算成本存在 |
| R6 冻结实验与分析 | P0 / 2-3周 | E1-E8必要子集、重复、统计、失败归因 | 不挑结果；对正反假设均报告；模型与Harness分榜 |
| R7 论文与复现包 | P0 / 2周 | 主文、补充、匿名视频、数据/代码、复现说明 | 另一成员从干净环境复算；素材不依赖外链和在线服务 |

关键路径：R0 -> R2 -> R3 -> R4 -> R5 -> R6 -> R7。
R1与R2可并行，R3后继续扩数据；R5可以在冻结的高质量子集上先启动。
整个研究按约13-20周安排工作量更现实，实际投稿届次取决于官方截止与完成情况。
若R2无法获得足够可发布资产，转为“受控构造与度量有效性”贡献路线，而不是硬称大规模数据集。

## 11. 投稿前自检门槛

以下是内部go/no-go，不是CVPR官方硬性门槛：

- 能具体指出最近邻未测清的能力或数据/评价缺陷，并展示本工作如何量化解决。
- 多任务之间存在统一的对象、表示与研究问题，不是互相独立的玩具题集合。
- 自然视觉条件占重要部分，符号输入的强基线明确；证明输入图像有作用或如实报告相反结果。
- 数据可发布、许可逐项记录、训练测试隔离含所有派生资产。
- 所有论文主指标经独立反例或人工审核；复杂几何的物理声明不超过验证器范围。
- 有足够独立结构组和代表性方法支持主张；没有任何预设“模型必须排序分开”的要求。
- 训练若被列为贡献，必须完成真实训练及对照；不把SFT文件生成当模型训练。
- 全部实验有原始响应、配置、图像、事件、结果哈希与费用；所有失败保留。
- 关键实验有重复和合适统计；多任务训练比较控制数据量/tokens。
- 任一结果可在干净环境复算；界面/视频的“模型动作”和“系统演示”没有混淆。

主表不必每项超过SOTA，结论不必正向；清晰、可靠的新发现比人为拉开排行榜更重要。

## 13. 算力与费用

现有小额费用限制适用于先导验证，不可默认扩为数千样本、多模型、多种子的大规模调用授权。
先测每任务平均输入图像数、tokens、调用次数与失败重试成本，然后据公式估算：

总API成本 = 各任务样本数 * 模型数 * 重复数 * 每轮预估费用 * Harness轮数（分项求和）。

训练成本单列为GPU类型、小时、次数、存储与人工标注。开源本地推理不等于零成本。
进入R5/R6前确认预算与算力；现有账本不删除、不重置。不能把每次重试看成免费。
本轮计划制定没有新增模型调用费用。
