A.4 Evaluation Implementation Details Because Collapse Rate compares whether two independent generations produce the same answer, the evaluation pipeline runs under a single uniform protocol so that per-model parsing choices do not become a confound for CR. We document the choices below. API and decoding. All models are queried through OpenRouter under one configuration: temperature=0 (greedy), max_tokens=4096 , no top_p or seed parameters. Reasoning models that expose an explicit thinking budget (GPT-5-mini and Grok 4.3 in our suite) are run under full reasoning via OpenRouter’s reasoning={"effort":...} parameter; all other models use the default low effort. Evaluations were conducted in May 2026. Prompt. A single answer-first prompt is used for every image and every model: Inspect the image carefully and answer the question. Think internally if needed, but do NOT write your reasoning. Your first line must be: <answer>...</answer> Put only the final answer inside the tags. If options are given, answer with the option letter; if it is a number, color, shape, or word, give only that value. Question: {question} The two images of a pair are sent in independent calls under this exact prompt, with no cross-image context. Answer extraction. Responses are parsed in a fixed priority order: (1) <answer>...</answer> ; (2) \boxed{...} ; (3) “Final Answer: X” or “Answer: X” patterns; (4) “Panel X” or “Panel (X)” anywhere in the response; (5) bracketed [X] (non-LaTeX); (6) a fallback that returns the last integer found. The inner text from each rule is routed through a small letter-extraction routine that collapses “Panel (C)”, “C.”, and “C” into the same canonical token C . Truncation handling. If a response hits max_tokens ( finish_reason=length ), we switch to a strict extractor that trusts only an explicit <answer>...</answer> or \boxed{...} tag. This prevents a cut-off reasoning trace from leaking an intermediate number into the answer slot, which would otherwise contaminate both per-image accuracy and the Collapse Rate. Normalization for “same answer”. The CR test compares norm ⁡ ( y ^ o ) = norm ⁡ ( y ^ e ) \mathrm{norm}(\hat{y}_{o})=\mathrm{norm}(\hat{y}_{e}) with norm ⁡ ( s ) = s.strip().upper() \mathrm{norm}(s)=\texttt{s.strip().upper()} . An empty extraction on either side is treated as a non-match, so a model that returns "" on one side cannot collapse with anything on the other. “Same answer” therefore depends only on the canonicalised extracted token, not on the surrounding prose. Invalid responses. An invalid response (extractor returns "" , typically a truncated reasoning trace with no <answer> tag) is neither correct nor a collapse. It still consumes a pair and reduces the model’s competent denominator, so models with elevated truncation rates have a downward-biased CR.
