\paragraph{Binding.}
Each pair retains pair, parent and source IDs; source and dataset
hashes; model revision, adapter and prompt hashes; condition A/B;
both exact requests; canonical predictions; both golds and provenance;
truth policy; and explicit failure reasons. A result pair cannot be
formed merely because two files share a task ID. A missing response
becomes a failed observation; it never shrinks the denominator.

\paragraph{Fact change.}
Wrong-image binds gold B to the stored
\texttt{mismatch.alternateChoiceId} and verifies its relation to the B
request. Graph-intervention recomputes gold from each supplied graph.
The original source-gold wrong-image score is preserved in a separate
field. The primary new-gold rate and both-correct rate use every
declared pair. Conditional adaptation has an explicitly displayed
A-correct denominator and is null if that denominator is zero.
The B response partition is new gold / old gold / another legal answer /
invalid or missing, with counts summing to the fixed N.

\paragraph{Invariance.}
ID-renamed answers are mapped to canonical identities. Choice letters
are only comparable after mapping to their option meanings. Exact sets
ignore order while retaining duplicate-invalid status; action success
uses legal execution. The five transitions are both correct, A-only
correct, B-only correct, both wrong with the same semantic answer, and
both wrong otherwise. Missing or invalid answers are explicitly
identified and cannot count as valid semantic agreement.

\paragraph{Withdrawal and access.}
Removing images or edges can make a task underdetermined. Scores
retain original gold only as dependency measurements. Full/Mask
measures a total access effect, and fixed two-view access is not active
exploration. Semantic invariance under camera or color changes does
not prove visual decidability.

\paragraph{Weighting and uncertainty.}
First average variants within each original parent, then parents
within source, then sources equally. Micro and parent-macro rates are
auxiliary. Report items, parents and sources for every family and QA
stratum. Resample source clusters with replacement 10,000 times
(seed 20260919), using percentile 95\% intervals. Calculate
model-minus-baseline differences on the same records before
resampling. No equivalence claim follows from an interval including
zero. Subgroups chosen after inspecting model performance must be
marked exploratory.

\paragraph{Challenge rules.}
The extension version is \texttt{ldraw2-matched-graphs-v1}, seed
20260919. Each parent contributes three hypothetical observations;
the maximum per source is 15. A target-to-survivors star is combined
with either a six-cycle/two-triangle pair (at least six survivors)
or a four-node path/three-node triangle pair (four or five survivors).
Other survivors are isolated after target deletion. The third
observation permutes survivor labels in the anchor graph.
Seeded parent ordering alternates the direction of the answer change.

The \EvChallengeObs{} observations produce \EvChallengePairs{}
pairs: \EvChallengeUp{} increases, \EvChallengeDown{} decreases and
\EvChallengeSame{} unchanged answers. All match node set, unique edge
count and target degree. \EvDegreeMatched{} changed pairs also match survivor
degree sequences; \EvDegreeGaps{} do not, and the manifest records that gap.
Edge counts need not match the original natural graph. Natural,
single-edge intervention and hypothetical challenge results remain
separate. Opaque request IDs and independent requests do not expose
pair membership or transformation direction to the model.

\paragraph{Independent checks.}
BFS and union-find agree on every original, original-intervention and
challenge graph. Python and the frozen TypeScript intervention yield
identical original-intervention edge lists. A synthetic six-cycle
versus two-triangle fixture verifies that node/edge counts and every
survivor degree can agree while the component count differs.
Duplicate, reversed and isolated-edge cases are included.
Synthetic fixtures are software tests, never counted as real sources.

\section{Related-work Evidence at Protocol Level}
All comparisons use pinned full papers, read including appendices:
BrickNet, CVPR 2026 proceedings, ten PDF pages;
LEGO-Puzzles arXiv:2503.19990v3, June 20, 2025, eleven pages;
PhyBlock arXiv:2506.08708v2, November 21, 2025, forty pages.
Page numbers below refer to PDF pages. Official code snapshots are
separately identified and are not substituted for the papers'
experimental recipes.

\subsection{BrickNet}
BrickNet~\cite{kulits2026bricknet} evaluates unconditional and
caption-conditioned object/build-sequence generation and held-out
sequence perplexity (pp.~5--7, Sec.~5). Conditional generation receives
a caption; unconditional generation receives a start token.
Graph-backed part/connector programs reconstruct poses
(pp.~3--4, Sec.~3.4). Eight views are used for captioning (p.~4),
and render--text agreement evaluates generated objects (p.~7).

Its placed-part graph vertices and letter-named spanning-tree
programs distinguish repeated instances (pp.~3--4, Fig.~4).
Connector annotations combine procedural and manual authoring and
are reviewed; collision geometry uses inset meshes with caveats
about non-watertight surfaces and deformation (pp.~3--4).
The paper uses human-authored online LDraw sources, reporting
320,808 samples and 9,743 variants, with 512 held-out single-object
evaluation files (pp.~2,4--5).

Graph/pose representation, sampling, scale and training ablations
are reported (pp.~5--7). Same-target answer-changing and answer-preserving
VQA with the two semantic adaptation measures is not reported.
This does not imply the assets could not support that experiment.
The code snapshot at commit
\path{b09a689c4929bd27f59c9bb9446237967aa332c9} (August 19, 2026)
preserves instance/connector identity through \texttt{core.Graph},
\texttt{core.Edge} and \texttt{tree.id2i}.
\texttt{score.score\_text} returns action count, first invalid action
and collision indices; \texttt{score.check\_tree} decodes placements.
The paper regenerates unparseable caption-conditioned outputs before
perceptual scoring (p.~7), unlike our fixed-denominator failure rule.
Later \texttt{DATA.md} training splits and packing lengths differ
from the paper; those recipes are not merged in our comparison.

\subsection{LEGO-Puzzles}
LEGO-Puzzles~\cite{tang2025legopuzzles} v3 has 1,100 questions from
407 building instructions across eleven families (pp.~3--4).
Task-dependent inputs include current/target states, next pieces
and candidate states (Fig.~1, p.~2; Sec.~3.2, p.~4).
Height/Adjacency use arrows, while states and choices use letters.
Unified source naming is described (p.~4), but a stable scene-instance
identifier shared across image, record, graph and action contracts is
not reported in this version. Several tasks integrate multiple image
sources; describing them all as independent single-image lookups
would be incorrect.

Studio fixes cameras across steps, and type, number, color, position
and viewpoint can be edited during construction (p.~4).
Duplicate/image checks and three-annotator verification resolve or
remove ambiguous items (p.~4). VQA scoring combines rule-based
extraction with a ChatGPT fallback; five experts rate image generation
(pp.~5,7). Next-k-Step uses $k=1,\ldots,5$ and compares CoT conditions
(pp.~7--8); the version has up to seven intermediate stages (pp.~3--4).
We do not import counts from a later OpenReview revision.

Official code at commit
\path{1413d2c236879573cc0afff646bae5e3d04023bd} (June 20, 2025)
uses \path{LEGO.split_LEGO} to interleave image tokens and
\path{build_prompt_sort} for ordered letters.
These builders supply images and text, not curation CAD records.
\path{extract_answer_from_item} calls \path{can_infer_lego};
an enabled judge can retry three times and fall back to a random
option after exhausted matching. This is a code-snapshot observation,
not a rerun score. The same-target new-gold and both-correct estimand is
not reported in v3, although the assets are reusable.

\subsection{PhyBlock}
PhyBlock~\cite{ma2025phyblock} v2 separates 400 assembly tasks from
2,200 physical VQA questions across sixteen categories (pp.~5--6).
Planning uses target and candidate-block images; interactive planning
adds observations and history (pp.~7--8,25--27).
The output selects reusable candidate IDs in order without rotation;
exact pose prediction is deferred (pp.~39--40).
The evaluator uses AOV dependencies and target poses.

Scene records have unique \texttt{order}, type, color, dependencies,
position and orientation (pp.~17--18). Candidate IDs are different:
the prompt explicitly permits the same block index multiple times
(pp.~25--26). Planning jointly involves candidate matching and legal
ordering (pp.~22--23), while VQA separately probes attributes,
relations, scenes and dynamics (pp.~5--6).
Eight geometries and five colors are used with Genesis, manual scene
annotation and augmentation (pp.~6,15--17).

AOV evaluation matches unused legal reference blocks and counts
TP/FP/FN (Algorithm~1, pp.~22--23). Static VQA uses human-verified
LLM generation; dynamic VQA uses simulated perturbations, frames and
human checks (p.~19). The paper reports topology/pose scoring,
full/stepwise planning, views/backgrounds and physical perturbations
(pp.~8,19,22--28), with no real-robot evaluation (p.~40).
Our specific paired visual estimand is not reported.

The official commit
\path{da81ed9cad8184509aadb6f01af83d53e5c9d6fa} (August 20, 2025)
predates v2. Its sample \texttt{000.json} confirms
\texttt{order/depend/euler} scene fields.
\texttt{are\_blocks\_equal} compares type/color/euler in protocol A
and type/color in B. \path{validate_block_placement} assigns the
earliest unused legal reference instance.
\path{extract_blocks_sequence} filters invalid candidate indices.
\texttt{BlockEnv.move\_cube} selects a candidate using a target
position/euler and \texttt{step} renders feedback. This is not
continuous pose/control synthesis. The top-level evaluator does not
separately emit all four paper error types.

\paragraph{What the additional assets establish.}
IDs and templates can support attribute lookup on these prior assets.
Our additional unit is a bound pair: canonical target, exact visible
evidence, both golds, truth policy, raw predictions and conditional
answerability decisions. It allows testing correct adaptation instead
of mere score change. The natural graph audit demonstrates why this
distinction matters for the present distribution; the analogous
visual finding remains a research objective. No exclusivity,
firstness or cross-benchmark percentage comparison is asserted.

\section{Quality, Failure Handling and Software Validation}
The required queue contains \EvVisual{} visual items and
\EvOtherPending{} other flagged items.
The physical queue contains \EvPhysicalPending{} intersection
candidates without recognized mating interfaces. Intended mating,
approximate mesh overlap, source defects and unresolved cases require
separate decisions. All are pending human adjudication; an automated
image or graph check does not resolve them.

Exact-wire visual review records task, condition, request hash,
image hashes/dimensions, reviewer, date, native-size/blinding
attestations and reason. A browser review export shows actual wire
pixels without references. Pending/failed QA is reported and cannot
silently delete an unfavorable model result. Changing the input or
gold requires a new version and affected runs; old scores cannot be
ported without verification.

The adaptation test suite covers perfect adaptation with zero accuracy
difference, persistent old answers, other legal answers, invalid
outputs, a zero conditional denominator, mismatched models/data,
duplicate pairs and missing B observations. Raw-receipt fixtures
exercise all eleven families, including executable actions.
Tampered request bindings, numeric metrics, counts, states and hashes
are rejected. Synthetic receipts are explicitly labeled and rejected
by production ingestion. These passing tests demonstrate analysis
behavior, not model performance or human agreement.

Missing, timed-out, refused, invalid-JSON and invalid-format responses
retain distinct reasons and count as failures in the primary
denominator. Format validity and semantic accuracy conditional on
valid format are auxiliary. No hidden retries or answer repair
inflate the main rate. Unknown cost remains null.

\section{Reproduction, Preservation and Figure Provenance}
The pre-revision archive preserves \EvFrozenFiles{} actual file entries, including
previously untracked content. Its baseline lock checks all four guide
fingerprints and the earlier 2,131-file v1 freeze. The new namespace
contains analysis code, result indices, paired gold bindings and the
hypothetical extension; no original source, v1/v2 request, response,
gold, score or manuscript is rewritten.

The publication generator reads hash-checked frozen inputs, produces
numeric macros and imports the state-driven tables. It records every
source render and paper crop. The official CVPR 2026 style is copied
unchanged and used in anonymous review mode with a nonregistered draft
ID. Source archives include TeX, bibliography, figure PDFs, complete
dossiers and hashes. Local build/verification instructions are supplied
with the release; machine-specific paths are not part of this PDF.

All figure images are derivatives of real source geometry renders.
Paper-only crop rectangles and zooms never change model inputs.

effects, not physical motion. Six-step images use one shared rectangle
from unchanged saved frames. Full/Mask share the exact camera,
projection and crop window; Crop reframes operands. No additional
artwork substitutes for a source model.
