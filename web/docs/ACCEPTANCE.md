## 本地性能基线

`assets-built/performance-report.json` 保存 9 次生产构建冷浏览器上下文的采样数据，覆盖 5867、10213、10214 和 10220。环境：本机 macOS arm64、headless Chrome、1440×900、localhost。

- 最大压力样本为 10214 Tower Bridge：4,281 实例、1.88M 三角面。
- 四个样本的装配态动画 P50 均约 58–60 FPS。
- 100% 陈列并完成相机稳定约 1.7–1.9 秒。
- Tower Bridge 100% 陈列渲染调用采样 P95 为 3.1 ms，全部实例保持在画面内。
- JS heap 约 40 MB；不是整个 GPU 或浏览器进程内存。
- 全部几何解码就绪 P50 从 131 ms（5867）到 534 ms（10214）。
- 装配态渲染调用采样 P95 从 1.7 ms（5867）到 3.8 ms（10214）。

这些时间从场景初始化起计，不包含生产 DNS、网络 RTT 或真实首屏绘制时间；渲染调用耗时是 CPU 提交采样，不是 GPU 计时，少量样本不能作为公网性能承诺。脚本可通过 `npm run benchmark` 重跑，具体数字以最新 JSON 为准。

## 已披露限制

- 步骤来源以各模型 manifest 的 instructions.provenance 为准，所有步骤均不宣称为官方纸质说明书。
- Compose 的位置与高度检测不是连接/承重求解器；角色预设和程序化单砖仍有简化，组件内部逐砖拼装、拾取和 PDF 等尚未与模型工作台完全对齐。
- DIY 的底板随视野延伸，单项目上限 5000 砖；支撑/占位校验不代表承重与物理稳定性认证，程序化形状不包含完整底部管柱几何。
- manifest 实例数不宣称等于包装库存、备用件或同套装其他搭建形态。
- 六个功能组为编辑规则。原始七个子模型的身份和路径全部保留。
- 完全陈列是非重叠布局，不是精确机械碰撞拆装模拟。
- 数百零件同时陈列时需缩放、搜索或分组隔离；没有把全部几何强行放大并保持全屏可见。
- 当前压缩为 gzip、Float32 几何，不采用有损 LOD。该规模的实测不支持提前引入减面。
- 逐实例拾取网格保留原始三角形，先做包围盒粗筛；千级高复杂模型应再次实测 BVH/LOD 的收益。
