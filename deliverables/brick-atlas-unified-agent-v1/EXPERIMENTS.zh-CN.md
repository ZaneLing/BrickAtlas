# 三组实验都保留，主实验固定 agent、只换模型

更新：2026-10-30。

## 1. 三组分别测什么

| 组别 | 给模型什么任务 | 模型做什么 | 主要看什么 | 当前状态 |
|---|---|---|---|---|
| 静态 LLM／MLLM | 一个确定的故障现场、唯一目标、库存 | 判断并输出修复操作；执行器检查操作是否合法、最终是否正确 | 能否理解错误、定位并给出可执行修复；是否误拆好件 | 原静态题和执行器保留；正式对比待跑 |
| 动态 LLM／MLLM 直接控制 | 从题目起点进入连续变化的 Arena | 每轮直接输出一个观察或拆装工具调用，接着看返回再决定 | 能否连续完成、何时看图、事故后能否继续正确操作 | 原 `dynamic_arena.run` 保留；旧结果按原接口版本展示 |
| 动态视觉 agent | 同样的 Arena；增加统一的观察记忆、计划和记事保存 | backbone 自己观察、写计划、选动作、改计划、决定何时完成 | 在同一套 agent 支持下，不同 backbone 的正常拼装、观察、修复和停止能力 | 本次新增并实跑；完整过程见回放和报告 |

这里的“LLM 直接控制”是实验组名称。**收到图片的其实是多模态模型（MLLM/VLM）**。只要模型在循环中调用工具，也已经是最简单的 agent；第三组测的是有明确记忆和计划管理的统一视觉 agent。

不能因为第三组成绩较高就直接说“视觉智能体更强”：如果它比第二组多看了图片、多用了预算，收益也可能来自这些差异。

## 2. 主实验怎样保证一致

本次视觉 agent 的所有 backbone 使用同一配置：

| 项目 | 统一规则 |
|---|---|
| 初始材料 | 当前场景三视图、目标三视图、库存第 1 页；每张场景图 800×600 |
| 新现场 | 装完、拆完**不自动更新图片**；模型自己调用 `observe` |
| 目标保存 | 三张唯一目标图每轮保留，不把说明书的后续步骤当目标 |
| 场景记忆 | 最近两次现场观察；保留原图和拍摄时刻，不用真实状态偷偷刷新 |
| 库存、候选位置、说明书 | 保留最近库存页、最近候选／说明页；一页最多 12 项；其他页自己查 |
| 文字历史 | 最近 8 轮模型输出和工具返回；更早内容可由模型写入记事 |
| 计划和记事 | 模型自己写；计划最多 6 项，每项 160 字符；记事最多 1,200 字符 |
| 动作 | 一次装／拆一块；只能用同一套候选位置；最终正确即可，不强制参考顺序 |
| 物理动作预算 | 最多 16 次安装／拆卸尝试；拒绝的尝试也计入 |
| 主动观察预算 | 最多 24 次观察／候选查询／说明查询／历史回看 |
| 总轮数 | 最多 40 次模型决策；`finish` 不占物理动作预算，但占一轮 |
| 生成预算 | 每轮最多 2,048 个生成 token；每题最多 81,920。服务商报告的推理 token 也计入 |
| 重试与自动帮助 | 不自动重试、不替换服务商、不替模型纠正动作、不偷偷加 GT 提示 |
| 正常前置 | 同题、同 backbone、同 agent 配置、同预算先完成正常版本，才运行事故版本 |
| 事故 | 使用题库原有事故配置；不向模型发送事故时间、名字、位置或评分 |

**不再用“最多两张图”作为新 agent 的规则。** 图片数量由保留了哪些信息决定，并在每轮日志记录。初始是 7 张；后续会根据查询和记忆变化，不是每轮发送所有零件、所有候选位置或完整说明书。

这是一套明确的初始三视图方案，不等于它已经被证明最省图。后续需要用相同题目比较“初始一视图”“初始三视图”“全部按需观察”，同时报告图数、像素和费用。

### 推理预算能统一到什么程度

可统一的是每轮生成 token 上限、总轮数、动作、观察和外部记忆。支持推理档位的 API 请求 `low`。Qwen3.8 使用包含思考和回答的 `max_completion_tokens`，而非只限制回答的 `max_tokens`；其官方接口允许约 10 token 误差，费用预留已包含这部分。不同厂商的 `low`、分词和内部计算量不等价，因此**不声称等算力**。实际生成 token、推理 token、截断和延迟单独记录；截断不能冒充视觉判断错误。正式实验再增加统一关闭可选思考、或相同开销区间的对照。

## 3. 模型与固定 API 路由

| Backbone | 本次模型 ID | 接口 | 凭证变量 |
|---|---|---|---|
| DeepSeek Flash | `deepseek-flash` | DeepSeek 官方 | `DEEPSEEK_API_KEY` |
| Qwen3.8 Flash | `qwen3.8-flash` | 阿里云百炼北京接口 | `ALIYUN_API_KEY` |
| Gemini 2.5 Flash | `google/gemini-2.5-flash` | OpenRouter | `OPENROUTER_API_KEY` |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | OpenRouter | `OPENROUTER_API_KEY` |

Qwen 和 DeepSeek 的路由是用户长期指定的，失败时也不回退到 OpenRouter。模型 ID、当时目录、服务商返回的模型名和调用参数保存在各次运行文件里。DeepSeek 的 `deepseek-flash` 是可更新别名；官方说明当前对应 V4.1-Flash-1017，不能把别名当永久固定权重。

原计划的 `qwen3-vl-235b-a22b-instruct` 实际收到阿里云 404 `model_not_found`，没有生成回答。这条服务失败记录保留。查询阿里云实时目录后，先登记计划变更，再单独补测 `qwen3.8-flash`；两者不会合并成同一模型结果。

官方依据：[DeepSeek 图像输入](https://api-docs.deepseek.com/guides/vision/)、[DeepSeek 模型及价格](https://api-docs.deepseek.com/quick_start/pricing/)、[阿里云兼容接口](https://help.aliyun.com/zh/model-studio/qwen-vl-compatible-with-openai)、[阿里云价格](https://help.aliyun.com/zh/model-studio/model-pricing)、[GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。本次实际部署参数以各次 `provider.json` 和原始请求为准。

阿里云的思考与输出限制依据：[Chat Completions 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。本次费用上限 $1.50，按所有已发调用累计；原生 API 费用按用量估算，人民币另列，并用 1 元占用 $0.20 的保守预算系数。中断运行也计费，不能只统计成功题。

## 4. 什么是公平的对比

### A. 主实验：同一视觉 agent，换 backbone

本次实现并试跑。对相同题目，用上表所有相同规则，只换模型和对应 API 传输适配。报告正常拼装、事故实际触发、正常合格后的恢复、合法动作率、错误提交、动作数、观察数、图片数、token 和开销。

正常和事故是**两次独立自主运行**，不是复制同一条前缀。它能证明“这个模型在同题正常条件下成功过”，不能据此计算事故的纯因果影响。

### B. 次实验：同一 backbone，换 agent 配置

| 对照 | 要控制住的东西 | 状态 |
|---|---|---|
| 直接控制 vs 统一视觉 agent | 同样初始材料、工具、动作／观察／生成预算；只改记忆与计划管理 | 待用新接口做匹配对照；不能直接拿旧 v4 结果减新 agent 结果 |
| 保存目标 vs 按需回看目标 | 相同目标像素和其他预算，记录额外调用及图像负担 | 待跑 |
| 保存前一观察 vs 仅保留最新观察 | 同样拍摄时刻及观察机会，明确图像 token 差异 | 待跑 |
| 自主观察 vs 固定间隔观察 | 同样总观察额度；固定策略也不能额外看到事故标记 | 待跑 |
| 有计划记事 vs 无计划记事 | 同样生成预算；不加入外部总结模型 | 待跑 |

### C. 静态与动态的匹配现场

沿用已实现的同现场检查方法：事故真正发生后，复制当前状态、目标、库存、候选编号、相机和剩余预算。一份带执行历史继续做，一份从该现场重新接手。要给新视觉 agent 接入同样的记忆复制／清空规则，再跑这组对照。

**旧工具接口的配对检查已实现；新视觉 agent 的同现场分叉仍待接入。** 本次正常前置检查不是这个实验的替代品。

## 5. 文字、图片、图文三种输入仍然保留

“静态／动态／视觉 agent”是控制方式；“文字／图片／图文”是输入形式，是两个不同维度。

- T：文字表达零件、颜色、位置和库存，隐藏信息权限必须写清楚。
- I：场景、零件和库存状态都由图片表达；工具名称、编号和 JSON 仍可用文字。
- TI：同一时刻的两种表达一起给。

本次先跑 **RGB＋文字接口与库存状态**。它不是严格的纯图片 I，也不是完整状态都转成文字的 TI。正式的 T/I/TI 适配与匹配事实对照仍按原计划开展，不把未实现的组写成已有成绩。

## 6. 失败要分开看

1. **服务问题**：HTTP 拒绝、限流、超时、缺失用量；不计为模型能力失败。
2. **经费停止**：达到本轮费用上限；不计完整题失败。
3. **生成截断**：回复因 token 上限被截断；列出次数和影响。
4. **接口格式**：不是合法 JSON、字段缺失、数字写成字符串、相机参数超出范围。
5. **动作被拒绝**：碰撞、无连接、拆装通路被挡；保存具体引擎代码。
6. **结果错误**：程序接受了动作，但最终状态不符；可能需要视觉／定位／计划诊断，不能仅凭一次日志断言内部原因。
7. **未触发事故**：没有实际事故，恢复指标不适用。
8. **事故有效但未恢复**：另看是否观察过新现场、做过哪些合法返修、有没有正确提交。

## 7. 本轮不能替代的工作

两种物件的试跑是接口和行为案例，不是 310 个物件的正式排行榜。还需要正常成功覆盖更多物件、更多错误类别和难度；真人盲操作；独立拆装检查；新 agent 的同现场分叉；完整三组和三种输入的匹配实验。
