# 这一轮先把输入和统计说清楚

更新：2026-10-23。这一轮没有调用付费模型，花费 **$0**。

直接看 [输入图示](index.html)；程序检查记录在 [checks.json](checks.json)，12 个模块逐项图量在 [module-image-counts.json](module-image-counts.json)。

## 1. 为什么以前一轮有几十张图？说明书到底要不要给？

以前的模块接口把整本剩余说明书、每块零件的单独图片、当前状态、上一步状态、阶段目标、完整成品参考一起发，每一步又重发。这些图片很多没有变化，目标还容易看混。

**说明书应该让模型随时能查，但不需要每一步都把整本再发一次。** 复杂物件只给最后一个角度，往往连人也无法确定内部结构；我们的社区模块题提供参考步骤，且主体已经搭好，只补 5–12 块。现在模型自己选择要看哪一步，查看后继续拼，不需要人中途提示。

三种任务要分开理解：

| 部分 | 模型要做什么 | 说明书 |
|---|---|---|
| S 静态修复 | 把已有积木修到本题目标 | 目前用三视图目标和候选位置，没有另加说明书 |
| D 从空底板拼装 | 从空底板拼一个简化物件，途中可能遇到干扰 | 目前没有说明书；正常拼装尚未成功的运行，不能用来证明不会修复 |
| M 社区模块 | 主体已经搭好，补装或修复指定局部 | 有，随时按步骤查看；每次只返回所请求的一步 |

说明书中的顺序只是一个可行例子。可以先左后右，也可以反过来；只要每次装拆合法、最后达到本题目标即可。

## 2. 现在每一步发什么？

| 默认内容 | 张数 | 怎么读 |
|---|---:|---|
| 当前／目标对照 | 3 | 斜视、背面、俯视；每张左边是现在，右边是本题唯一 TARGET |
| 上一步之前／现在 | 首轮 0，之后 3 | 每张左边是自己上一步之前，右边是现在；用来核对自己的动作和额外变化 |
| 零件总览 | 模块题 1–3 | 一张图最多十二块，所有零件都可见，包含备用件 |
| 整本说明书、完整成品参考 | 0 | 不再默认发送 |
| 额外查看 | 按需 | 看某一步说明书增加一张；看视角或候选位置按请求返回 |

12 个社区模块原来首轮 **45–87 张**、后续 **48–90 张**。现在首轮 **4–6 张**、常规后续 **7–9 张**；看一步说明书再加一张。S、D 使用同样的三视图对照方式，零件页数随题目而变。

零件仍然全部展示，没有删掉备用件，也没有只留第一页。所有零件都按相同方式排版，不用图片数量提示哪里出错。S、D 查看一个零件仍会返回它的全部候选位置页；这不是默认重发整本说明书。

### 本题只有一个目标

- 名字统一为 **TARGET**。静态模块题右侧就是本阶段要修成的状态，不能多拼后面的步骤。
- 默认不出现另一组“完整成品目标”，也不出现未来说明图。
- 本阶段以内的说明图可以直接查看。想看后续步骤，必须明确要求“未来参考”；图片会标明 **不是本题目标**，原 TARGET 不变。
- 正常静态题本来就没有错误，当前和目标完全相同是正确情况；此时直接提交完成即可。

### 当前和目标放进同一张图

两种对照页都为 **1600×636**；每个场景都是 **800×600**，上方标题为 36 像素。当前、目标使用相同相机、相同取景范围、相同几何比例。分隔线不再盖住场景像素。

因此，服务商收到的是一张同时包含当前和目标的图片，不再分别收到大小不同的目标图和对照图。默认图看不清时可继续查看；模块单独视角和候选预览为 1600×1200。

点击坐标以“现在”这个场景内部计算，不含标题。程序明确提供每个场景的像素范围；真人页面也按这些范围处理点击。当前／目标图中的“现在”在左边，时间对照图中的“现在”在右边，不再套用同一个左右假设。

## 3. 什么情况才能说模型不会修、没发现？

| 实际发生什么 | 现在怎么记 |
|---|---|
| 没拼到能施加干扰的状态 | **未触发**；修复、漏检分数留空 |
| 发生干扰，但对应正常分支也没拼好 | **正常拼装未成功**；不进入主修复成功率 |
| 正常分支拼好，干扰确实发生，两条运行都正常结束 | 可以统计这对运行的修复结果 |
| 干扰发生，但没有同前半程的正常分支 | 保留为单条观察；不能进入主修复结论 |
| 有 403、429 或超时 | 单列接口拒绝、限流、超时；本次运行没有模型能力分数 |
| 返回多个动作、错误 JSON、接口没有的动作 | **输出格式错误**；和图像识别、物理操作失败分开 |
| 动作字段或编号不合法 | **动作请求错误**；单独列出 |
| 位置碰撞、装入路径被挡、接不上 | 按执行器的具体拒绝原因统计；不能仅凭拒绝就说是视觉错误 |

“没发现干扰”还需要：对应观察有有效的异常判断、正常分支无误报、画面有可理解性证据。没有回答不算回答“没有”；只看最后没拼好，也不能判断是没看见还是修复方法错了。

从指定中途状态开始的任务可以另设一组诊断实验，但不能假装是模型自己从空底板拼到了那里。本轮先修好了正常／干扰配对的资格检查，没有把旧失败补写成中途开始的实验。

## 5. 这轮检查了什么，还不能说什么？

- 检查全部 12 个模块：默认只有一个目标；说明书按需读取；未来步骤必须明确请求；查看不改变场景。
- 对正常模块和 D 小汽车做 78 组场景像素一致性检查；也检查相同缩放后仍一致。
- 重新检查三类静态错误在默认分辨率下的可见像素差异；这只是机器检查，不等于人类看得懂。
- 跑通同前半程的正常与干扰分支，并模拟未触发、正常分支失败、403、429、超时，检查资格和空分数。
- 检查真人页面换题、刷新继续、重复点击、旧页面提交和 A/B/C 独立保存；不把测试操作当作真人答卷。

**这些修改排除了已找到的输入问题，仍不能保证以后所有失败都必然是模型能力问题。** 本轮没有做服务商实际预处理的联网 A/B，也没有用新接口重测模型。旧价格估算反映旧版大图量，不能直接给新版套一个省钱比例；后续小规模新接口试跑再测实际 token 和费用。
