# 为什么题量从五千多变成了两千多，以及这次怎么改

## 原因

你记得的数量没错。旧基准的清单有 **5,720 道按 canonical ID 去重的题目**；更早的网页曾展示 5,793 条。它们包含完整物件、指定模块和大量静态局部结构题，版本和去重范围并不完全相同。

上一轮我把新社区模型压成每模型一道静态代表题，并且把旧物件的动态题也只选了几个代表条件。随后把这个 **2,157 题的精选子集** 当成最终题库交付，没有把范围变化讲清楚。这不是“旧题全坏了”，也不是它们全部被删除了，是选题和交付统计做错了。

## 这次修正后的数量

| 项目 | 上一轮精选子集 | 本次当前可运行题库 |
|---|---:|---:|
| 模型 | 310 | 310 |
| 静态题 | 268 | 1601 |
| 动态题 | 1889 | 3091 |
| 合计 | 2157 | 4692 |

- 社区静态题按不同错误保留，通常每物件 4–6 道，含正常对照。少数物件没有那么多可行错误，就保留实际通过检查的数量。
- 旧完整物件取消动态题的代表数量限制，重新检查已有的不同阶段和不同干扰条件。每道题有独立的事件图片，避免同名错误的不同题共用错图。
- 当前复查有 24 道旧题的参考过程没有通过，原因逐条保存。其中 3 道曾进入上一轮精选清单，这次因干扰没有形成已验证的有效错误而退回。其余题目没有因数量限制而删掉。这些题不会被算成模型失败，也不冒充已验证的题。
- 完整旧题仍可检索：新增 [全部题目记录页面](all-questions.html) 和 [机器可读清单](all-questions.jsonl)。当前通过、历史待复查、退回和已停用分别标记。

## 两个数字怎么使用

**写当前已检查题库的规模，使用 4,692 道：静态 1,601、动态 3,091。** 它们对应 310 个完整物件或明确收尾部分。

完整记录目录共有 8,997 条，它包含上述题目，也包含旧结构诊断题、其他模块、待复查题和已停用记录。它是查找历史数据的目录，不能把这个数直接写成“全部验证合格”。目录按旧 canonical ID 合并别名；跨版本相同场景仍可能有不同记录，所以它也不声称是完全去重的物理场景总数。

| 完整目录中的状态 | 记录数 |
|---|---:|
| 此前已停用（来源筛选／人工要求） | 1983 |
| 历史记录，本轮未重新验证 | 2265 |
| 当前程序检查通过 | 4692 |
| 本轮参考回放未通过 | 24 |
| 历史新增候选，待审查 | 33 |

没有调用付费模型。程序检查成功不等于真人已认可，也不等于 API 模型做对。之前的报告保存在 `checks/count-correction/before/`，不会覆盖成仿佛当时就有这些题。
