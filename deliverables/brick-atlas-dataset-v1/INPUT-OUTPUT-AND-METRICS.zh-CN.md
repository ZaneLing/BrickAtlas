# 输入、输出、GT 和评分

## 一、先说清楚模型要干什么

**静态题**：场景已经摆在那里。比较当前状态和本题的验收目标，有问题就修；已经正确就结束。

**动态题**：模型接管一次连续拼装。它自己决定什么时候看、看哪个角度、拿哪块、装在哪里、什么时候拆、什么时候完成。环境可能在一次实际操作后悄悄改变积木；不会停下来告诉模型“现在做一道修复选择题”。

完整拼装从白色凸点底板开始。收尾题则提供已经拼好的主体，模型完成指定区域。主体和操作范围都明确显示，不能把一个模糊裁片当成完整物件。

最终只有一个验收目标。静态题的目标可能是说明书的中途阶段；之后的成品和说明步骤不会替代这个目标。

## 二、动态 Arena 的实际接口

第一次输入包括任务、工具列表、匿名零件与位置编号、预算和规则，**没有自动附图**。模型先请求观察。例如：

```json
{"tool":"observe","args":{"view":"angled","rotateDegrees":0,"show":["current","target","inventory"]}}
```

返回的是当前图、目标图、这一页库存图，以及剩余零件状态。当前图与目标图均为 800 × 600，相机与取景范围相同。库存每页最多 12 个零件；不需要每个零件各发一张图。

`rotateDegrees` 是在当前角度上再旋转多少度，可用 `-90 / 0 / 90 / 180`。`view: "top"` 请求俯视图。`focus: "whole"` 查看全景，默认 `focus: "module"` 聚焦本题区域。

```json
{"tool":"observe","args":{"view":"angled","rotateDegrees":90,"show":["current","target"],"focus":"module"}}
```

模型可以查看某个零件的可选位置。位置图只表示“如果装在这里会怎样”，不标记哪个位置合法或正确。

```json
{"tool":"inspect","args":{"partId":"A00001","page":1}}
```

下面的编号只是格式示例，实际编号以本次任务返回的清单为准：

```json
{"tool":"attach","args":{"partId":"A00001","candidate":"C00001"}}
{"tool":"detach","args":{"partId":"A00001"}}
{"tool":"inspect","args":{"manualStep":3}}
{"tool":"recall","args":{"decision":5}}
{"tool":"finish","args":{}}
```

每次回复只能调用一个工具。一次安装或拆卸只处理一块。动作后返回成功、碰撞、通路受阻、参数错误等反馈；不会自动附一批新图。模型要看新状态，需要再次 `observe`。`recall` 取回以前请求过的图片，不代表那还是当前状态。

说明书按需查看，是一种可行拼法。**不要求照说明书顺序，也不把中间状态和 GT 的第几步硬对齐。** 干扰依据模型实际已安装的零件和动作间隔触发；如果当时找不到合法、可逆、看得见的变化，记录为未触发，不伪造一次事故。

## 三、静态题的输入输出

静态适配器默认给三个角度的“当前／目标”对照图和库存联系表。当前阶段的验收目标始终在右侧；未来说明步骤需主动请求，并标明只是参考。

静态 JSON-lines 接口每次接收一个动作对象：

```json
{"type":"inspect","view":"rear"}
{"type":"inspect","partId":"A00001"}
{"type":"attach","partId":"A00001","candidate":"C00001"}
{"type":"detach","partId":"A00001"}
{"type":"finish"}
```

这些是逐轮发送的示例，不是一次发送的动作列表。当前已正确的 S0 题应当结束；不能默认每道静态题都有错误。

当前实现使用图像观察、必要的文字规则和 JSON 操作。纯文字、纯图、图文三种输入的正式对比实验尚不能由本次数据整理结果代替。

## 四、答案怎么存，怎么判

新社区题的文件在 `private/模型编号/`：

| 文件 | 内容 |
|---|---|
| `certificate.private.json.gz` | 原始零件、预先完成的主体、允许操作的零件与位置、几何检查所需数据 |
| `manual.private.json.gz` | 一条合法的正常拼装过程和对应状态 |
| `cases.private.json.gz` | 每题初始状态、唯一目标、隐藏干扰、参考修复动作和程序回放结果 |
| `check.json` | 原文件一致性、全量回放、替代顺序检查的结果 |

题目列表里的 `id` 对应答案文件中的 `id`。里面的 `initial` 是真实起点，`goal` 是验收目标，`events` 是环境私下使用的事故安排，`referenceActions` 是经过回放的参考操作。

GT 内部零件编号与模型看到的匿名编号由适配器转换。做题模型不能得到 `family`、`events`、`goal` 状态字典或参考动作；它看到的是目标图片、匿名操作编号和必要规则。

成功要求：明确结束，最终零件、颜色和位置符合目标，并满足该任务的连接规则。相同物理零件互换编号可以接受；换一种合法顺序也可以接受。被拒绝的穿模、通路受阻等操作不会改变真实场景。

参考修复已经去除可验证为多余的整组拆装，但**不声称全局最短**。效率指标只能写“相对参考动作数”，不能写“最优路径效率”。

## 五、分别看哪些指标

| 测什么 | 主要指标 | 怎么理解 |
|---|---|---|
| 静态正常对照 S0 | 完成率、误修率 | 已经正确时，是否还进行了不必要的拆装 |
| 静态修复 S1 | 完成率、放置 F1、错误减少比例 | 最后是否完全正确；没完全修好时还差多少 |
| 保护正确部分 | 最终损坏数量／比例 | 原先正确的内容最后有没有被破坏；临时合法拆开再装回不算最终损坏 |
| 正常动态 D0 | 正常完成率、操作数、观察次数 | 没有外部干扰时能否自主完成 |
| 单次动态 D1 | 正常通过后的修复完成率、实际触发率 | 先确认同模型、同任务、同输入和预算的正常分支成功，再统计实际遇到事故后的结果 |
| 多次动态 D2 | 全事故后完成率、每次恢复、恢复保持情况 | 每段恢复窗口在下一次事故发生前结束，不能把下一次事故算成上一次修复造成的损坏 |
| 操作质量 | 合法动作比例、物理拒绝原因、格式错误 | 格式错误、放错位置、碰撞、缺库存分别报告 |
| 观察策略与成本 | 观察／回看次数、决策数、token、美元 | 由实际日志统计，不用截图张数猜成本 |
| 专项库存替代 | 目标体积覆盖、颜色、最终连接 | 使用原来的 QI 专项评分，不强求替代方案与示意图有相同分缝 |

放置 F1 对本题可操作的目标零件计算，不用大面积不变背景把分数抬高。精确完成率要求零件类型、颜色和位置同时正确。

### 哪些不能算成模型能力失败

- 403、429、超时等服务错误：单独报告，能力结果为空。
- 运行器错误或外部停止：单独报告。
- 正常分支没拼成功：不进入主要修复成功率的分母，仍报告正常拼装失败。
- 事故没有触发、只触发了部分事故：分别报告，不叫“漏检”。
- 不能仅凭“没修好”推断“没看见错误”。目前没有足够证据的检测指标保持为空。

Arena 的 `normalQualifiedRecovery` 用于“先通过正常拼装，再看修复”的独立两次运行。它不要求两次随机动作完全一致，也**不作干扰造成多少下降的因果结论**。严格的成对下降指标另外要求真实共享前缀、相同输入图片、动作和预算的证据；不能把这两种统计混起来。

汇总时同时给出题目平均、物件平均、原始来源平均和实际有效运行覆盖率。同一个套装的多个替代造型放在同一来源组；重复条件不能当作额外独立样本。

## 六、怎样运行

以下命令在仓库根目录执行；先使用项目现有 Python 环境安装好几何和渲染依赖。

```bash
PYTHONPATH=benchmark/brickplan-repair benchmark/.runtime/mlx-env/bin/python -m dynamic_arena.server --port 8810
```

只预览，不调用模型：

```bash
PYTHONPATH=benchmark/brickplan-repair benchmark/.runtime/mlx-env/bin/python -m dynamic_arena.run --id SC:2132-1:dynamic:missing --condition preview
```

读取静态题并逐轮提交动作：

```bash
PYTHONPATH=benchmark/brickplan-repair benchmark/.runtime/mlx-env/bin/python -m bench_design.run_episode --id CASE_ID
```

真正调用 API 时，动态题使用 `dynamic_arena.run --condition pair --model PROVIDER_MODEL --cap-usd ...`。这一步会产生费用，本轮没有执行。接口的真实 JSON、图片引用、动作反馈和结果在 Arena 的运行日志中查看。

数据重新生成后必须重新检查；正式加载器会拒绝检查记录缺失、失败或与当前题目文件不一致的版本。
