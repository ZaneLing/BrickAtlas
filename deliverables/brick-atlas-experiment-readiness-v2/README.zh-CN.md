# 实验前的基础问题修复

更新：2026-10-30。实现版本：`brick-atlas-unified-visual-agent/2`。

这次检查的是：题目能不能完成、接口能不能接通、图片有没有发对、输出能不能执行，以及技术中断有没有被错误地算成模型失败。**这轮不是模型能力排名。**

## 1. 发现了什么，怎么改的

| 问题 | 已做的修复 | 后续实验的处理方式 |
|---|---|---|
| 模型只是少写了默认参数，就整轮被拒绝 | `observe` 可省略视角、旋转和查看对象；默认看当前斜视图；接受 `isometric` 别名和整数形式的字符串 | 所有模型用同一规则；原始回复、转换和实际动作同时保存 |
| 短输出额度被思考占满，动作 JSON 没写完 | 每次生成上限从 2,048 提到 8,192；能关闭额外思考的接口关闭，Sol 使用低档 | 仍若遇到 `finish_reason=length`，立即停下，不猜后半句、不执行动作，也不计成拼装失败 |
| 不同模型接口的参数不一样 | 共用一个调用层；按服务商设置支持的参数 | DeepSeek 固定官方 API，Qwen 固定阿里云；没有自动转平台 |
| 403、404、429、超时混在一起 | 分别保存 HTTP 类别、原始回执、请求编号、费用状态 | 不自动重发；超时费用未明时保留预算并阻止该服务商继续调用 |
| 零件图和文字里的库存状态不够一致 | 零件图直接标出零件 ID 和可用／已安装状态，取自同一时刻 | 旧库存仍标拍摄时刻；需要更新时由模型主动查看 |
| 请求错误页码，可能先转了相机才报错 | 先验证页码，再改变视角 | 错误请求返回页数范围，场景和相机保持原状 |
| 固定 16 次物理动作可能不足以完成长题 | 根据公开零件数量和该题本身上限分配动作、观察及轮次预算 | 同一道题、所有 backbone 用相同预算；参考路径必须能在预算内完成 |
| 达到动作预算后，被统计成 JSON 格式错误 | 将资源预算拒绝、JSON 错误、参数错误分别计数 | 保留端到端结果，同时标明是否混有接口错误；不把它直接解释为视觉能力不足 |
| 旧静态／直接模型入口可能绕过新调用规则 | 它们也接到同一 API 调用层 | 截断检查、原生路由和费用回执检查保持一致；统一 Agent 的正式入口还强制运行前检查 |
| 运行器只知道失败，不告诉模型哪里写错 | 返回具体字段、合法值或语法示例 | 示例只有占位 ID，不给该题的正确零件或位置 |

**不会替模型选零件、选安装位置、补完截断 JSON，或纠正非法安装。** 缺少默认参数可以按公布的规则补齐；旋转 35°、错误位置编号、碰撞、无连接等仍会被拒绝。

### 真实 API 检查

使用实际 case 的初始图、目标图、库存图及第二轮历史材料，请模型完成指定观察调用。每次输入 7 张图；未提供 GT，未让它执行拼装动作。这能检查图像和接口兼容性，不能证明它理解了全部几何。

| 模型 | 接口 | 请求数 | 输出 token 合计 | 结果 | 本次费用 |
|---|---|---:|---:|---|---:|
| DeepSeek Flash | 官方；`DEEPSEEK_API_KEY` | 2 | 260 | 通过 | 估算 $0.003978 |
| Qwen3.8 Flash | 阿里云；`ALIYUN_API_KEY` | 2 | 119 | 通过 | 估算 ¥0.012941 |
| Gemini 2.5 Flash | OpenRouter | 2 | 62 | 通过 | 返回扣费 $0.003380 |
| GPT-6.1 Sol | OpenRouter | 2 | 58 | 通过 | 返回扣费 $0.040942 |

**合计保守预算占用约 $0.050889，上限 $0.40。** 阿里云用 ¥1 = $0.20 做预算占用；这是保守预算规则，不是汇率账单。原生服务的金额按返回用量和所记录单价估算，OpenRouter 金额来自回执。没有自动重试，没有未核清的请求。

## 3. 模型实际输入与输出

视觉 Agent 的初始输入保留：**当前三视图＋目标三视图＋第一页零件图**。后续由模型自己调用观察；模型得到的旧图不会悄悄刷新。目标图、最近两次现场观察、最近一次库存和候选／说明页，以及最近八轮文字对话会按统一规则保留。图片数量由这些角色决定，不硬限制为两张。

最简单的合法观察输出：

```json
{"tool":"observe"}
```

含义是查看当前斜视图，不旋转。要旋转 90° 并更新零件库：

```json
{"tool":"observe","args":{"rotateDegrees":90,"show":["current","inventory"]}}
```

安装仍须使用从实际公开页面看到的 ID：

```json
{"tool":"attach","args":{"partId":"PART_ID_FROM_INVENTORY","candidate":"POSITION_ID_FROM_REQUESTED_PAGE"}}
```

`plan` 和 `notes` 可选，不写就保留上次内容。每次只执行一个工具。全部规则见 [工具协议源码](../../benchmark/brickplan-repair/dynamic_arena/contract.py)。

## 4. 以后怎么避免同样的问题

1. **先跑接口小检查。** 同一代码和生成配置，24 小时内的通过记录可复用。代码或参数变化、记录过期，正式运行器会阻止启动。
2. **再检查选中的 case。** 创建新的环境，检查零件／位置 ID、可行参考动作、最终状态、事故触发、动作预算和图片。
3. **先正常拼装。** 同题、同 backbone、同 Agent 配置正常拼好，才允许事故修复分支。
4. **运行时保存证据。** 原始请求和返回、图片哈希、动作、错误类别、token 与费用全部留存。
5. **技术中断单列。** 截断、服务异常、运行器问题及经费停止显示“不适用”；不把它们混进纯拼装能力结论。

运行命令见 [运行说明](RUN.zh-CN.md)。API 间歇性限流和超时无法从本地彻底消除；现在可以识别、停止并保留证据。8 次接口通过也不保证长任务永远不截断，截断率仍需随正式结果报告。
