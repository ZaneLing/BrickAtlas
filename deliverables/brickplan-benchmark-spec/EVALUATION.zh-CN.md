# 静态与动态怎么评：完整方案

## 先用人话说

**静态：原来的错误修好了吗？有没有把本来对的地方改坏？**

**动态：正常能拼完吗？被干扰以后还能拼完吗？修好以后能不能继续保持？**

这几件事分别给分，不把它们加权揉成一个“总智力分数”。本方案没有调用付费模型，没有填入虚构的模型成绩。

当前已实现：最终状态、零件得分、原错改善、最终损坏、动作合法性、格式问题、配对资格、多次干扰资格、恢复窗口、按物件／来源汇总。真实 API 用量采集、来源组置信区间、独立看图检测题和指定中途开始的题单仍需接入或补建。

## 1. 分成六组测

| 组别 | 开始给什么 | 需要做什么 | 最主要看什么 | 当前状态 |
|---|---|---|---|---|
| S0 正常验收 | 已经达到本阶段目标的结构 | 判断无需修改，结束 | 是否乱拆、最后是否仍正确 | 已有 |
| S1 静态修复 | 有错误的当前结构＋本阶段目标 | 合法修复到目标 | 完全修好、剩余错误、最终新损坏 | 已有 |
| D0 正常拼装 | 空底板，或已装好的大物件主体 | 拼完整物件或补齐指定部分 | 正常完成率 | 已有 |
| D1 一次干扰 | 与正常拼装相同 | 中途发生一次变化，修好并继续 | 条件恢复完成率 | 已有 |
| D2 连续干扰 | 与正常拼装相同 | 先后发生两次／三次变化 | 全程完成、每次恢复、后续保持 | 主任务43条；另有4条历史裁切诊断 |
| C 指定中途开始 | 系统预先装到指定状态，再给错误场景 | 修好并完成剩余部分 | 中途开始修复完成率 | 设计完成，独立题单待生成 |

C 组必须明说“前半段是系统装好的”，不能算成模型自己从零装到了那里。C 的成绩也不能代替 D1／D2 的连续拼装成绩。

## 2. 所有组都遵守的判分规则

1. **最终几何、类型、颜色一致即可，安装顺序可以不同。** 不逐步对照某条参考路线。
2. 同形同色的可互换零件不按内部编号判错。普通对称砖的等价朝向按执行器现有对称规则处理；不能把这种对称规则套到印刷件、斜坡、夹扣等零件上。
3. 当前主任务采用已有白底板／主体的坐标系；不另做任意整体平移、旋转对齐。若以后测试“放在哪都算同一物件”，必须另列实验条件。
4. 安装、拆卸由实际执行器检查连接、碰撞和直线装拆路径。被拒绝的尝试不改变场景；之后修对仍可成功，但拒绝次数要记录。
5. 只给**本次可操作的部分**计零件分。补10块屋顶时，不把500块已装墙体算进去抬高成绩。
6. 声明结束且目标正确才算完成。正常耗尽模型动作预算算任务失败；服务超时和评测程序被人为停止另记。
7. 下面所有分母为0的率记为 **N/A**，不填0或100%。唯一例外：比较两个都为空的零件集合，集合 F1 定义为1。

## 3. 静态指标

| 指标 | 人话含义 | 算法／分母 | 用在哪 |
|---|---|---|---|
| **完全修复率 SR ↑** | 一道题最后是否完全对了 | 合法运行中，明确结束且最终等价的题数／有效题数 | S1；按物件、错误类型分别报 |
| **位置零件 F1 ↑** | 没完全拼好时，到底对了多少 | 类型、颜色、位置、等价朝向都匹配才算对；同时惩罚多件和少件 | S1；大物件只计可操作范围 |
| **错误减少率 ER ↑** | 原来的错减少了多少 | `1 − 最终残差 / 开始残差`；开始残差为0时N/A | S1；可以为负，表示越修越错 |
| **新损坏率 DR ↓** | 本来正确的地方，最后被改坏多少 | 最后丢失的原正确位置数／开始正确的位置数 | S1；临时拆下后装回不算最终损坏 |
| **误修率 FR ↓** | 本来就对，却动手乱改 | 起始正确但执行过至少一次成功装／拆的题数／S0有效题数 | S0；另报最后是否仍正确 |
| **原少件补回率 ↑** | 原来缺的目标位置补回多少 | 补回的原缺失目标位置数／原缺失目标位置数 | S1诊断，不能单独代表成功 |
| **原多件清除率 ↑** | 原来的多余件清掉多少 | 原多余位置被清掉的数量／原多余位置数 | S1诊断；挪成另一种错仍可能得分，所以必须同时看SR/F1 |

**例子：** 该放红砖却放了蓝砖：少了正确红砖，多了错误蓝砖，残差记2。只拆掉蓝砖，残差降到1，错误减少率50%，但还没补红砖，完全修复仍是失败。残差数不是人类失误次数，也不是已经证明的最少装拆步骤。

### 静态的几个辅助分数

- **类型＋颜色 F1**：忽略位置，只看是否拿对了零件。它可以是100%，但物件仍然拼错，不能代替完成率。
- **形状＋位置 F1、颜色＋位置 F1**：帮助区分不同属性组合的问题，不把它们叫作独立的视觉识别准确率。
- **连接关系 F1**：计划作为补充项，需对可操作零件及其主体连接做统一匹配，排除大段不变背景；当前统一计分器尚未接入，不填正式表。

## 4. 动态主指标

| 指标 | 人话含义 | 分母和条件 |
|---|---|---|
| **正常完成率 BCR ↑** | 没有外部干扰时，模型能不能正常拼完 | D0所有有效运行 |
| **有干扰运行的原始完成率 ICR ↑** | 给了干扰任务，最后有多少完成 | D1／D2所有有效运行；必须另报触发了几次，不能直接叫修复率 |
| **干扰触发率 TR ↑** | 计划的事故真正发生了多少 | 实际触发次数／计划次数；没触发不等于漏检 |
| **条件恢复完成率 CRR ↑** | 正常能完成，遇到真实干扰后还能完成吗 | 只用正常分支成功、共用前半段、两分支有效、全部事件触发且效果已核实的配对 |
| **干扰造成的完成率变化 ΔSR** | 干扰让完成率下降多少 | 两分支有效、共用前半段、事件完整触发且效果已核实的配对中，平均`正常成功 − 干扰成功`；这里不预先筛掉正常失败的配对 |
| **中途开始修复率 CSR ↑** | 先不会完整拼装的模型，有没有单独修复能力 | C组系统给定中途状态的有效运行；与CRR分开报 |

CRR 要同时列出：计划配对数、有效配对数、正常失败数、未触发数、只触发部分事件数、服务失败数、最终符合资格的配对数。不能只显示一个看似很高的百分比。

### 如何做真正可比较的正常／干扰配对

1. 模型从同一个任务开始，前半程只运行一次。
2. 在干扰前保存状态、对话、已用预算、编号映射和随机种子。
3. 复制成正常与干扰两份，两边继续调用同一个模型；只有一份施加外部变化。
4. 从复制点起，两边允许采取不同合法顺序；不要求它们重新走同一条GT路线。
5. 每个模型／条件只运行一次，不挑最好的一次。正常对照的复用和实际调用次数在费用里分别记录。

**还要检查事故有没有真的制造问题。** 例如模型本来把某块装错了，后台恰好把那块拆掉，不能当成一次标准的“正确结构被破坏”。这类事件记为效果不适用／待核实，不直接记修复成功或失败。

提前封口可能是“放上了一个最终也需要的正确盖件”，问题在于挡住后续通路。它要核实实际堵路效果，不能只根据最终少件数判断事故是否有效。

## 5. 多次干扰与修复过程

| 指标 | 衡量什么 | 注意事项 |
|---|---|---|
| **全部事件后的完成率 ↑** | 所有计划事件触发后，最终仍完成 | 正常配对成功＋全部事件触发＋最终正确；只发生1/2次不进入这个分母 |
| **逐事件恢复率 ↑** | 每次引入的目标缺陷，在下一次事故前是否消除 | 只计实际有效事件；第一场事故未修好与第二场未触发分开 |
| **首次恢复用几轮 ↓** | 事故后，经过多少次模型决策首次恢复 | 查看、错误请求也占决策轮数；不把恢复动作当作模型“口头检测到了” |
| **恢复后保持率 ↑** | 修好以后，后续是否又把同一部分弄坏 | 观察到复发直接记未保持；仍正确但恢复后不足2次决策记N/A，并列样本数 |
| **单次事件 Repair@k ↑** | 事故后k轮内是否恢复 | 预先选k=2/4/8；只在有足够观察窗口的单事件或C组用。服务中断、下一次事故提前到来等截断另报 |

**恢复不等于回到原来的中间图。** 只要丢失的正确位置恢复、新增的错误位置消失，就算消除了该事件的缺陷；模型同时继续装上其他正确零件也没问题。

提前封口这类过程错误可能没有“新目标缺陷位置”，其修复延迟不记为0；主要看它是否完成、实际是否需要返工。合法的其他解决办法也接受。

技术定义：用与目标相同的类型、颜色、对称等价姿态组成零件多重集合。设事故前为B、事故后为A、最终目标为G。恢复只要求补回事故损失的原正确位置`(B∩G)−A`，并清除事故新引入的额外位置`(A−G)−(B−G)`，不要求当前集合等于B。因此允许边修边继续正确拼装。此前已经存在的模型自身错误单独记录。

逐事件恢复和保持的窗口截止于下一次外部干扰前，避免把第二次事故造成的损坏算到第一次修复头上。首次恢复的中位轮数只在成功恢复者中报告，旁边必须列出未恢复比例，不能把它单独当总体效率。

## 6. “检测到了没有”怎么测

**当前连续拼装不强迫模型中途回答“是否出错”。所以不能把没修好直接写成漏检。** 它也可能看见了，却不知道怎么拆、选错位置或提前结束。

如果论文需要独立的检测结论，另设一组固定画面判断题：

- 正常样本、真实变化样本都要有，并核对可见性；输入图和动作负担预先固定。
- 测“是否有异常”的精确率、召回率、F1和正常场景误报率。
- 如需定位，再单独评错误位置集合F1；多处错误不能只问一个单选题。
- 错误类型可以多标签，不要求同时发生的多错只选一个类别。
- 本组不插入D1／D2的连续拼装中，也不把程序参考修复动作当作检测标签。

当前这组题和统一定位评分仍需实现。M／E7现有动作输出没有直接的检测声明，正式检测率应留空。

## 7. 动作、格式、成本：全部单列

| 项目 | 怎么算 |
|---|---|
| 合法动作率 ↑ | 成功装／拆次数／字段正确的装／拆尝试次数 |
| 物理拒绝原因 | 分别报碰撞、不连接、通路被挡、已经安装等反馈 |
| 格式错误 | 不能解析成动作对象的回复数；不算视觉错误 |
| 字段／编号错误 | 已解析，但动作字段不合法、缺编号、编号无效等；与物理通路问题分开 |
| 操作次数 ↓ | 成功动作、全部装拆尝试、查看次数、总决策轮数分别报 |
| 相对参考路线的操作量 ↓ | 全部装拆尝试数／可行参考路线长度；可能小于1，说明比参考路线更省，不判错 |
| 费用与速度 ↓ | 请求数、输入／输出token、实际图片数量与尺寸、总美元、每题美元、每成功题美元、响应时间 |

参考路线没有证明最短，所以不能把相对参考路线的比值叫“最优效率”或SPL。正常验收参考动作长度为0时，比值N/A，改看误修率。

费用包括失败请求和重试的已收费用；计分按实际成功落到环境里的动作。服务重试不能从头重做一局、再只保留成功结果。

## 8. 什么进分母，什么不进

| 情况 | 能力完成率 | 修复率 | 另外报什么 |
|---|---|---|---|
| 正常结束但拼错 | 失败 | 符合配对资格时失败 | 终态残差、动作等 |
| 模型规定的决策预算用完 | 失败 | 符合资格时失败 | 预算耗尽 |
| 本来能修，但模型提前finish | 失败 | 符合资格时失败 | 提前结束 |
| 没到事故位置／没有合法事故可施加 | 可统计任务原始完成情况 | N/A | 未触发及原因 |
| 计划两次，只发生一次 | 原始完成情况照报 | “全部事故恢复”N/A | 触发1/2；已发生那次可作单独过程记录 |
| 正常配对分支都失败 | 照报正常和干扰完成情况 | CRR N/A | 正常能力不足、覆盖率 |
| 最终服务失败：403/429/超时等 | N/A | N/A | 服务失败、成本、有效运行覆盖率 |
| 服务短暂失败后在同一决策恢复 | 最终正常结束则照计 | 符合条件则照计 | 重试和已收费用；不能因为出现过一次错误就抹掉整局 |
| 评测程序错误／人工停止 | N/A | N/A | 数据或程序问题／外部停止 |

总览同时给**有效运行覆盖率**和**实际完成／计划运行数**。后者是系统可用性与能力合在一起的运行结果，不能把服务失败解释成模型不会拼。

## 9. 怎么汇总，才不会让重复题和简单物件淹没结果

1. 静态、完整物件动态、收尾模块动态、结构诊断分表；不拿一个全库平均分替代它们。
2. 先去重。同形同色换编号的题不加权成新题；不同配对条件中的正常对照仍保留，但共享任务权重。
3. 每个物件内部先平均，再平均物件。另给按原始套装／设计家族平均的结果，避免一个物件生成200题就占200倍权重。
4. 同时报逐题平均作参考，并按错误类别、B/R/T分组展示。多标签错误表要说明同一题可能出现多次，不能把各行题数直接相加。
5. 正常对照单独给分，不混入错误修复题来抬高SR。
6. 将来计算95%置信区间时，按原始来源组整组重采样；同一套装的静态、动态、换色变体不能当独立样本。每题只测一次不能证明模型重复运行稳定性。
7. 已经用于展示、调提示的来源统一作开发材料；新来源测试必须在调试前定好，不能用本轮展示过的3个小物件声称新来源泛化。

比较模型时使用事先确定的同一题单，不因服务失败换成别的题。缺失成绩留空，报告有效覆盖率；可另给各模型共同有效子集的对照，但必须说明子集和样本量。

## 10. 输入与输出对照实验

| 对照 | 实际改变什么 | 可否直接混分 |
|---|---|---|
| RGB图＋中性任务文字 | 当前默认：图给几何，文字讲规则和匿名操作编号 | 主组 |
| 文字状态 | 明确提供零件、位置、方向等状态 | 单列；它可能提供原本被遮挡的信息，不能叫等信息纯文字对照 |
| RGB＋文字状态 | 给图，再加显式状态 | 单列状态辅助组，观察额外状态帮助多少 |
| 位置编号 vs 自由坐标 | 后者需要自己给位置和方向 | 动作负担不同，单列定位实验 |
| 一视图／三视图；有无历史图；说明书可查看／不可查看 | 可见信息、记忆和查询机会改变 | 每项固定其他条件，先核对画面是否仍可解 |

文字状态和自由坐标的统一题单尚未补齐。新统一入口用“一次一个直接动作对象”，S／D不用再套外层`action`，M／E7／O也是同一层；旧输入包保留历史格式，旧成绩不能冒充新接口成绩。

## 11. 预留结果表

主文优先放前四张；其余用于诊断或补充。未跑的格子写“—”，不填估计成绩。

1. 静态主表：模型、物件宏平均SR、位置F1、ER、DR、FR、有效N。
2. 动态主表：模型、BCR、ICR、CRR、ΔSR、配对有效N、触发／计划次数、服务失败。
3. 逐错误类别表：E01–E07、过程错误、同时多错分开。
4. 长度／返工／事故次数表：B1–B3、R0–R3、T0–T3，分别报告当前样本量。
5. 多次干扰表：两次／三次，全程完成、逐事件恢复、恢复后保持。
6. C组：指定中途开始的修复率和Repair@k。
7. 输入模态与状态辅助对照。
8. 说明书、历史图、分辨率、反馈等输入对照。
9. 编号与坐标输出对照。
10. 独立检测／定位题；实施后才填。
11. 同一输入下的真人可读性与操作结果。
12. 费用、耗时、格式／字段／物理拒绝和服务状态表。

### 基线和模型如何安排

- 先跑确定性的“直接finish”与正常参考路线，检查S0／S1是否分清、正常拼装是否能完成。
- 加一组“照说明走、不根据新状态返修”的基线，检查中途观察是否有实际价值。
- 本轮已验证的隐藏信息参考路线只作为执行器检查／调试上界，不能把它当成和视觉模型公平比较的成绩。
- 正式模型沿用论文已有候选名单。每个模型／条件一次，主表先用同一视觉接口、候选位置接口、说明书权限和动作预算；再做输入／策略对照，不同时改多个因素。
- 同一道题对所有模型给相同预算。不同轨、不同安装量可以有预先声明的不同预算，但不能因此把跨轨成绩直接混成一个总分。
- API模型与本地开放模型都记录精确版本、服务商或权重版本、图像处理方式、解码参数、上下文、最大输出、硬件和精度。正式开跑前核对图像支持和端点；本轮没有替它们填任何成绩。

## 12. 实现入口和仍要补的记录

- 计分函数：[metrics.py](../../benchmark/brickplan-repair/bench_design/metrics.py)。
- 回归用例：[test_metrics.py](../../benchmark/brickplan-repair/bench_design/test_metrics.py)，覆盖替换同形件、临时拆装、非唯一中途路径、服务失败、多次事件资格、格式问题和去重权重。
- 新接口：[run_episode.py](../../benchmark/brickplan-repair/bench_design/run_episode.py)。只运行本地环境，不调用任何模型。
- 接 API 时逐轮记录实际输入版本、图像哈希、原始回复、解析结果、反馈、内部前后状态和事故时间；内部状态只进评估记录，不回传给模型。
- 配对分支还要保存共用前缀证明、实际事件效果、是否触发、最终状态。若这些字段缺失，保留原始完成结果，主CRR留空。
- 汇总结果每行须有`model、inputVersion、conditionId、canonicalTaskId、objectId、sourceGroup、track、taskType、terminalStatus、success`。正常与修复按taskType分组，不能自动混在同一轨的平均数里。完成的运行必须显式给布尔success；缺失结果不能默认为失败。
- 事件窗口、独立检测、来源组置信区间、实际API费用统计还需接到正式批量评测入口；函数或方案存在不等于已经有实验成绩。

## 参考的原始论文

我们借鉴了“完全完成之外还看零件质量”和“修好原错、改坏原对分别统计”的思路，没有照抄不适合我们动作空间的分数。[Break and Make，§3.3](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136880089.pdf)、[SCANet，§V-C](https://arxiv.org/html/2403.18195v1#S5.SS3)。

它们的配准、三维输入或任务范围与我们不同，因此上面的公式和分母以本文件为准，不能把我们的分数和论文表格直接横比。
