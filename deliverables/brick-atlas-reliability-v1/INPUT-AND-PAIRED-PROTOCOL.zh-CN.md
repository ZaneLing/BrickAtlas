# 当前公开输入、输出和同现场比较

协议：`brick-atlas-tool-arena/4`。静态和动态使用同一套工具、匿名零件编号、候选编号、相机和观察分页规则。旧版整包图像结果仍可追溯，但不是新版协议的成绩。

## 公开输入边界

每轮输入包括任务名称、唯一目标约定、当前第几次决策、工具调用上限、相机、零件编号与候选数量、说明书／库存总页数、工具参数、上次工具反馈，以及此前动作与反馈的文字记录。默认没有图片；图片只来自模型上一步主动请求的观察、位置页、说明书页或历史图。

不包含：错误类型、被改动的零件、事故发生时间、裁判状态、参考修复路线、正确候选标签。可见目标是本阶段唯一验收目标。说明书有单独的 `referenceOnly` 标记，不产生第二个验收目标。

匿名编号是对物理零件／注册位置的操作指代，不是选择题答案。候选位置图只是“放到这里会是什么样”，不提前告诉模型这个动作是否合法。每次安装或拆卸只移动一个实体零件。合法顺序可以不同；明确允许等价拼法的题按其等价目标规则评分。

## 输出例子

```json
{"tool":"observe","args":{"view":"angled","rotateDegrees":0,"show":["current","target"]}}
```

返回 `OBSERVED` 和一张 1600×636 的对照图：左右面板分别是 800×600，顶部 36 像素为标题。两边同相机、同几何尺度、同画布。只请求当前或目标时是单独的 800×600 图；实验需要严格比较两个状态时应请求同一对照图。相同故障现场的分支在相同观察调用下核对实际图片哈希。

```json
{"tool":"observe","args":{"view":"angled","rotateDegrees":90,"show":["current","target","inventory"],"inventoryPage":2}}
{"tool":"inspect","args":{"partId":"A001","page":2}}
{"tool":"inspect","args":{"manualStep":3}}
{"tool":"attach","args":{"partId":"A001","candidate":"C00001"}}
{"tool":"detach","args":{"partId":"A001"}}
{"tool":"recall","args":{"decision":2}}
{"tool":"finish","args":{}}
```

以上每行是**独立一轮**，实际编号以当前题为准。`rotateDegrees` 是相对于上一次相机转动，可选 −90／0／90／180；`view` 为 `angled` 或 `top`；`focus` 可选 `module`（默认）或 `whole`。说明书不存在时 `manualSteps=0`，不能请求虚构步骤。

库存页最多 12 件，返回同页的 `available`／`installed`／`unavailable` 状态。候选页最多 12 个位置，不自动发送其余页。超过页数的请求返回 `INVALID_SENSOR_REQUEST`，不改变积木状态，也不偷偷给正确页。它属于接口参数错误，不混入视觉识别失败。

解析错误、合法 JSON 中的参数／工具错误、物理动作拒绝、模型预算耗尽、服务错误、运行程序错误分别保留。服务错误时不计算失败修复率。事故没发生时，事故恢复指标为不适用；目标完成情况仍按实际状态单独记录。

## 输入负担的记录

每轮记录图片 SHA256、数量、像素、请求结构哈希和序列化请求字节数。汇总字段 `inputMetrics` 包含 `imageCounts`、`totalImages`、`imagePixels`、`serializedRequestBytes`。字节包含 base64，**不是模型 token 数**；token 与费用只能来自真实服务商收据。

同一轮最多 2 张图，但不能仅用“图片数量少”推断 token 成本低：还要看分辨率、模型服务商的图像缩放策略和观察次数。该上限也没有裁剪目标内容或暗中选出错误位置。

## 同现场比较的实现约定

`reliability.paired.fork` 接收一个**刚刚发生有效事故的真实执行会话**。复制时核对每次动作的前状态、动作后／事故前状态、事故后状态、反馈和事件索引，然后核对完整状态合同：

- 故障后的现场、目标、零件身份与编号；
- 有限库存的可用状态、候选位置和碰撞／连接证据；
- 工具、相机、观察协议；
- 剩余决策次数；两边未来事故都关闭。

两边当前公开请求完全相同。持续分支额外保留此前文字历史；旧图片可用 `recall` 的 `scope:"prefix"` 重新请求。新分支没有这些旧历史。两分支新的观察编号从 1 开始，普通 `recall` 默认只查本分支，避免与旧观察重号。

比较后计算 `completionDifference = continuing - fresh`，同时提供各自的原始指标。任一分支服务失败、运行失败或尚未完成评估时，`valid=false`，差值为 `null`。一次配对只是一对证据，不能直接解释某类内部认知机制，更不能冒充总体统计。

## 三种证据不能混用

1. **参考路线回放成功**：证明在定义的引擎和接口下有解，不能证明人或模型看得懂。
2. **不看答案的真人实际完成**：证明该人能从公开信息完成该题，不能证明全库无错。
3. **独立几何／实物复核**：检查具体拆装是否合法，与“能看懂题”是两件事。共享网格的第二算法仍不等于完全独立物理真值。

日志明确标记 `scripted-validation`、`human-operation`、`external-policy` 或真实 `api-model`。本轮新增结果属于脚本检查与自动页面测试，真人证据等待提交，真实模型结果等待新版实验。
