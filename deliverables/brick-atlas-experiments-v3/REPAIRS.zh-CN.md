# 本批实验前修正的设计和执行问题

本批使用 `brick-atlas-unified-visual-agent/4`。此前实验的输入、原始返回和分数保留，不用新规则改写旧结果。

| 问题 | 本批怎么处理 | 仍需注意 |
|---|---|---|
| 静态题的阶段目标与全套说明书混淆 | 只开放到本题目标阶段；明确“已经相同就提交，库存可以剩余” | 不能保证模型一定理解；要用新结果核对 |
| 候选位置小图不便辨认 | 可请求单个候选的1600×636当前/预览对照，也可指定正斜、后斜或俯视 | 预览是假设状态，不提供是否正确或是否合法 |
| 图上的件难以对应匿名编号 | 可以点选当前图，获取最前方可见件编号和轮廓 | 不返回被遮挡的件，不查询目标或故障答案 |
| 说明书零件与库存编号难对应 | 说明书返回所画零件的公开操作编号 | 不返回目标位置编号，不规定必须按参考顺序 |
| 合法JSON前有解释就整轮作废 | 统一接受代码围栏或前置解释之后的唯一完整JSON | 多个对象、重复键、缺损JSON仍拒绝；截断绝不执行 |
| 每轮预留8192输出token，加重TPM压力 | 统一改为2048；动作JSON和简短记事仍有空间 | 输出到上限仍会停止并单列截断，不猜动作 |
| hello通过但正式图片请求失败 | 预检增加书架较大图片包及长历史 | 小请求可用不代表接入点TPM够用 |
| 一次429直接终止整题 | 对明确未生成内容的429，最多等待重试3次；保存每次请求 | 不重试已生成的模型答案；403和计费不确定请求不盲重试 |
| 接入点可能指向另一个模型 | 核对API实际返回的模型版本 | 版本不符的返回不执行动作 |
| 拼对但没主动finish，与拼错混为一谈 | 同时报“结构达标率”和“提交完成率” | 完整日志保留停止原因 |
| 技术中断被误当作能力失败 | 服务、截断、程序、费用停止与模型预算耗尽分开 | 模型预算耗尽仍计端到端未完成 |
| 回放页把有回答的输入标成“未收到回答” | 根据真实模型返回判断标签 | 完整原始请求/返回仍可核对 |

## 共同设置

- 初始仍是当前三视图、目标三视图和库存第一页，共7张图。没有强制缩减成两张，也没有降低原图分辨率。
- 动作之后不自动送新现场。模型自己选择观察、转视角、查库存或说明书。
- 相同题目给所有backbone相同工具、记忆和动作/观察/决策预算。
- 只读参考路线不进入模型输入；不自动替模型修好、不偷偷选择正确位置。
- 静态题本批也使用同一视觉Agent。一次性静态问答、纯文本/纯图片消融不在本批完成范围内。
