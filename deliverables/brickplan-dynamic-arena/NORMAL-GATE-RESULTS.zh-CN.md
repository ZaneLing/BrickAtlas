# 动态题先正常拼：规则与 API 小规模结果

2026-10-28。这里的「正常」指模型从空白白色凸点底板接管整个物件，**没有中途干扰**。模型自己调用 `observe` 看当前、目标或零件盒，自己决定安装、拆卸和结束。每步只移动一块；最终按实际结构评分，不要求某个固定拼装顺序。

## 全题库的前序规则

当前题库有 2,115 道动态题；按真人意见移除 52 道所属的旧物件题后，**当前有效动态题 2,063 道**：181 道无干扰 D0、1,841 道单次干扰 D1、41 道多次干扰 D2，覆盖 89 个「题型轨道 × 物件」组合。每道有效动态题的控制条件已经写入 [逐题清单](../brickplan-benchmark-spec/normal-gate.json)。

对每道 D1/D2，前序运行使用**这道题本身**，仅关闭中途事件；起点、目标、库存和操作规则保持一致。判断顺序：

1. 同一模型先跑无干扰分支。接口错误单列；正常拼失败则记为「基础拼装未通过」，该题的修复结论暂不适用。
2. 正常拼成功，再跑含干扰分支。事故未实际触发则记「未触发」；发生后记录最终结构和逐事件修复。
3. 论文若要声称干扰造成了能力下降，还需要两条分支共享**完全相同的前半段模型输入与动作**。下面的试跑是独立开局，只能作探索结果。

此清单完成的是**规则和题目映射**，不是声称 2,063 道题已付费跑完。

## 错误与费用核查

- 正常分支最常见的操作拒绝是 `ENDPOINT_COLLISION`（安装后碰撞）与 `NO_CONNECTION`（没有合法连接）。小汽车的 Sol 运行还出现 `PATH_BLOCKED`（拆装路径被挡）。这些都按物理执行错误单列，最终结构仍由真实状态评分。
- 所有运行从空白凸点底板开始；正常参考顺序仅用于预先证明物件存在合法拼法，**没有发给模型**。Claude 小汽车的正常及干扰分支都能完成，说明这件物件在当前接口下至少存在模型可执行的成功路径。
- 本次 Arena 给每块目标零件登记一个候选安装位置，另外有备用错色件；因此主要测选件、观察、合法顺序与回到目标状态。正式题库里更复杂的候选位置、遮挡和库存替换，不能由本次数字代替。
- [逐请求审计](normal-pilot-audit.json)复核了 19 条运行记录（包含接口调试中断的留档）、332 个有服务商收据的调用、356 张实际发给模型的图、动作重放和事故触发。审核不产生新 API 调用。
- 本轮已确认 API 费用 **$1.74747**；把 7 个没有有效收据的请求按预留上限全算进去，费用上界 **$1.86488**，低于本轮 $3 限额。未确认请求没有被写成 $0 的确定费用。

## 目前能说什么

当前接口已经能区分三种情况：**正常不会拼、正常会拼但这次没修好、正常会拼且干扰后修好**。样本只有 3 件物件与各模型一次运行，且这 3 件是已有设计在新版底板上的 Arena 试验版；这些结果不能代表 2,063 道有效动态题的总体成功率。正式论文还需要在公开题目 ID 上按来源分组抽样、把正常与干扰分支做成同前缀配对、加入更长和更复杂的物件，并给出模型服务错误的独立覆盖率。
