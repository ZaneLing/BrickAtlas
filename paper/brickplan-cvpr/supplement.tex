\section{Artifact Scope and Reproducibility}
The manuscript describes an evidence snapshot dated 21 October 2026.
All earlier models are included through their current versions. Three banks coexist: the 3,292-question white-baseplate static bank,
the 1,872-episode dynamic mechanism bank, and the 96-case community
module suite. Their counts are not independent model populations, and
their experimental results are not interchangeable. The new route study
runs on the community module suite, not on the historical six-part car.
The complete module suite has no formal learned-agent evaluation or
independent human assembly experiment in this snapshot.

The artifact records original model files, source metadata, certificates,
cases, reference manuals, intervention witnesses, and order-regression
checks. Each instruction contains the physical part and the resulting
scene. Image manifests bind the current benchmark renders to their
source states. Paper figure provenance separately records source hashes,
cameras, native render dimensions, and exported figure hashes.
The deterministic study records the four input files for each object
and their SHA-256 digests. Re-execution does not require a model API.

The public object gallery is an author-facing inspection tool: it shows
fault names and correction witnesses. It is not a valid blind agent
input. Evaluation must use the observation adapter, which exposes the
permitted images and action handles while retaining certificates,
intervention labels, event timing, and recovery witnesses privately.
Publishing such annotations supports reproducibility but also makes
these public examples unsuitable as an undisclosed held-out test set.

\paragraph{Views and handles.}
The module interface provides isometric, rear, and top views at
$900\times660$ pixels. Part and candidate handles are randomized by
seed and do not expose target labels. The manual stays accessible
throughout the episode. Current-state images do not include the
paper's error boxes or corrective arrows. Explicit request and response
logs distinguish inspection from manipulation and retain the actual
view delivered to the agent.

\paragraph{One physical action per turn.}
An attach action chooses one rack piece and one catalog candidate. A
detach action removes one installed piece. The executor checks the
resulting configuration and a straight insertion or extraction path.
An invalid physical attempt consumes a manipulation attempt, reports a
legality code, and leaves the world unchanged. Inspection does not
advance construction or trigger an event. Finish requests termination;
success additionally requires the exact permitted geometric endpoint.
The manipulation budget is $4N+12$ for $N$ normal module pieces. The
outer model runner has a separately configured decision cap so repeated
inspection cannot run indefinitely. Both limits must be reported in a
model comparison.

\paragraph{Finite action candidates.}
The action catalog is part of the task definition. This is not unrestricted
six-degree-of-freedom pose prediction. Candidate previews and legality
codes reduce the planning burden and can leak useful physical information,
even though neither states the correction. They must be held constant
across compared agents; an ablation can quantify their contribution.
A symbolic state or expected next-state overlay is privileged information
and should be reported as a separate condition.

\paragraph{Indistinguishable parts.}
Terminal comparison uses physical part geometry, color, and pose rather
than instance identity. Supported rotational equivalences are limited
to plain rectangular parts with the appropriate geometric symmetry.
Decorated, directional, and asymmetric pieces are not assumed invariant
to arbitrary rotations. Identical-part exchanges are tested separately
from sequence exchanges: changing an identifier alone must not create
an apparent alternative physical trajectory.

\section{Intervention Selection and Causal Comparisons}
\paragraph{Deterministic adaptive selection.}
Each community fault condition names one of three mechanisms and an
installed-part threshold. After an accepted manipulation reaches the
threshold, the selector inspects the actual state. For a missing part
or color replacement, it considers older installed normal pieces,
retaining the newest piece to avoid merely undoing the last action.
For an extra layer, it searches compatible exposed positions for the
spare plate. The control and all three fault conditions share the same
inventory and candidate catalog.

An event is admitted only if it changes the state through legal
primitives and has a feasible inverse returning to the pre-event state.
A replacement uses a same-shape alternative-color spare: the environment
removes the original piece and attaches the spare between observations.
These two environment primitives do not allow the agent to submit two
manipulations in one turn. If no suitable event is available, selection
is deferred. At most one event is applied in the current module suite.
The private log records the realized location and its inverse.

\paragraph{What feasibility establishes.}
A legal inverse is a recovery witness, not a proof that it is the shortest
recovery or that the error is visually obvious. Every selected normal
route in the protocol study has a complete replay, so restoring its
pre-event state permits the remaining route to finish. This guarantee
does not extend to an arbitrary agent state that was already incorrect
before the intervention. Likewise, a reference event's RGB check does
not certify visibility at every location an adaptive selector can reach.
New trajectories require their own observation-level audit.

\paragraph{Matched-prefix controls.}
For a causal recovery comparison, execute a normal prefix once, save
the environment and conversation, and branch it into control and fault
continuations. The two branches have identical history before the event.
Keep the target, action vocabulary, inventory, renderer, budgets, and
model settings fixed. Report both completion and whether the fault
actually occurred. A run that finishes correctly without encountering
its scheduled fault is a completion, not a successful repair trial.

A conditional recovery rate excludes untriggered episodes from its
denominator, so it must be accompanied by exposure coverage and the
number of stalled prefixes. Even with the same input seed, two fresh
API runs are not necessarily matched-prefix controls: their actions may
diverge before the event. Adaptive location selection also creates
trajectory-dependent fault difficulty. Stratify by the realized edit
and report the reference-location subset separately when appropriate.

\paragraph{Exact-prefix opportunity.}
The comparison inspects the otherwise normal physical trajectory for
equality with the reference checkpoint. This avoids confounding trigger
eligibility with a different repair policy. It yields 36/36 eligible
reference-route fault trials and 9/36 alternative-route trials. The
actual-state selector applies an event in all 36 trials in each group.
A separate comparator requiring every intermediate state to match the
manual accepts 12/12 reference routes and 0/12 alternatives. The terminal
comparator accepts all 24 normal routes. These numbers establish
counterexamples to an overly restrictive contract, not a learned-agent
performance improvement.

The blind policy follows its normal route after any change. It completes
24/24 controls and 0/72 fault trials. The privileged policy uses the
recorded inverse immediately after the event and then continues; it
completes 96/96 trials. No model API is involved. A privileged repair
trace tests solvability and logging, not visual detection, reasoning,
or human-level assembly skill.

\paragraph{Machine visibility screens.}
Pixel differences use a maximum RGB-channel change of at least 24.
The reference mechanism audit retains 1,553 interventions as primary
machine candidates with at least 2,000 contrast pixels in an available
view. Another 136 interventions are classified as action cancellation,
and 23 have low contrast; there are no duplicate event states. A visible
change in pixel space is not proof that a person can identify the
incorrect part or infer a valid correction. Re-rendering and rechecking
the realized event is necessary when a different route changes its
location or occlusion.

The community reference snapshots use a separate minimum of 128 changed
pixels in at least one fixed module view. All 36 reference fault
snapshots pass that machine screen. Its lower threshold is an engineering
admission criterion, not an experimentally calibrated human perceptual
threshold. The two visual admission rules must not be pooled as one
validated population.

\paragraph{Splits and difficulty.}
The mechanism bank groups sources into 43 families for development and
evaluation separation. Its balanced development subset has 108 faults
(nine per family) and 42 controls; the evaluation subset has 168 faults
(fourteen per family) and 72 controls, where ``family'' in these counts
means an error mechanism. Source-family separation applies within this
bank, not across every artifact in the repository. The community suite
is a public development collection and has no undisclosed held-out
source-object evaluation in the current report.

Part count, prerequisite depth, access obstruction, and the amount of
reconstruction needed after a fault describe different dimensions of
difficulty. Neither source-file size nor the labels ``roof'' and ``car''
justify an easy/medium/hard ranking without performance evidence.
Figure~\ref{fig:distributions} reports case coverage without making that
inference.

\section{Planned Experiments and Reserved Result Tables}
\label{sec:plans}
All dashes in Tables~\ref{tab:errorresults}--\ref{tab:efficiencyresults} are
uncollected measurements. They are neither zero scores nor executor
results. The artifact contains machine-readable case assignments,
participant schedules, and a results template whose empty values are
\texttt{null}. These define the planned experiment; they are not an
implementation claim for the paired API runner or human study.

\paragraph{Models and primary samples.}
Use three commercial visual-model families (V1--V3) and two accessible
open-weight sizes (V4--V5). Record exact checkpoint/provider identifiers,
revision/date, image budget, prompt, and decoding settings before
execution. Apply seeds 41, 42, and 43 to handle randomization and repeated
runs; a provider seed is recorded only when supported. The S test list
contains 467 question IDs from 20 source groups. Migration changed the
source of some questions; 151 stale assignments are repaired while
retaining the existing source-group allocation. The corrected current
split contains 2,286 train, 539 development, and 467 test questions. D uses its existing
168-fault/72-control evaluation definitions, with fourteen faults per
mechanism. M uses all 48 static cases, 36 dynamic fault definitions,
and twelve dynamic controls; it remains a public development panel.
The full-bank secondary report covers every model configuration and
retains separate track/source averages. No joint tuning may use a source
later presented as unseen in another track.

\paragraph{Prerequisites and budgets.}
Complete image rendering and blind readability review before S visual
scoring. Verify the observation adapter, trajectory saving, actual-event
logging, and both cloned continuations on deterministic smoke tests
before paid trials. For this planned comparison, use a decision cap
$\max(40,6N+20)$ for every track, with $N$ target pieces; retain M's
additional $4N+12$ manipulation cap. Repeated inspection and malformed
outputs consume decisions. S's feasibility witnesses remain reference
costs, not optimality claims. Store input images, actual actions,
accepted/rejected moves, termination reason, and service errors. Retry
transient transport failures at most twice with the same request; do
not retry semantically incorrect model answers into success.

\paragraph{Pair construction and exposure.}
At the first admissible fault opportunity, save the environment and
visible conversation once. Continue a control copy without an edit and
a fault copy with the prescribed actual-state edit. A separate control
run with the same seed is not this pair. D's 72 control definitions are
additional construction controls; each of its 168 fault jobs still needs
its own cloned control continuation. Keep scheduled faults with no
admissible prefix in the exposure denominator, and report their stopping
reasons. Count every API call in both continuations. The base plan has
7,725 static attempts and 4,320 dynamic shared-prefix or normal jobs
across five models and three seeds (12,045 work units, not API calls).
There are 3,060 fault jobs, each requiring two continuations when the
prefix is reached. Ablations, the human-comparison panel, visual
admission, and full-bank coverage are additional work.

\section{Rendering, Attribution, and Physical Limits}
\paragraph{Publication images.}
All brick scenes in the paper are rendered from original geometry at
$3200\times2400$ pixels, with $2\times$ supersampling in each dimension
before downsampling. Composite figure exports use 600 dpi. PDF and SVG
retain vector labels, arrows, tables, and process boxes. The paper's
larger renders do not replace the $900\times660$ images received by the
current community interface. Orange boxes and manual highlights are
presentation annotations and are disclosed in the relevant captions.
They are not supplied as automatic fault detections.

\paragraph{Sources and licensing.}
The original LDraw OMR files retain their author headers, set identifiers,
source links, and license metadata. Derived figures retain source-file
provenance. The accompanying source manifest identifies the applicable
Creative Commons Attribution or LDraw library license metadata rather
than assigning new authorship to community models. Redistributed model
and part assets remain subject to those original terms. LEGO is a
trademark of its owner; the benchmark has no claimed affiliation.

\paragraph{Physical scope.}
The environment checks rigid geometry, supported connections, and
straight manipulation paths. Unsupported surrounding parts are retained
as conservative collision bounds rather than deleted, which can reject
some motions that a more precise mesh would allow. The preassembled
context is fixed. The executor does not model deformation, insertion
force, frictional stability, accidental slipping, articulated mechanics,
or a robot gripper. Consequently, ``legal'' and ``recoverable'' refer
to this geometric contract. Neither the protocol study nor its renders
establish real-robot performance.
