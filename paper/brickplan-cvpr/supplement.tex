\section{Current Artifact and Evidence Boundaries}
This supplement follows the organized dataset and metric specification
of 25 October 2026. It supersedes the 5,260-record paper snapshot and
its old experiment allocations. Historical model traces and the
96-trial route study remain explicitly version-scoped evidence.
Neither supplies formal scores for the current interface.

The artifact's organized catalogue, classification audit, physical replay,
source groups, image examples, and scoring functions are bound by hashes.
The paper records the current dataset in
\path{evidence/current-dataset.json}, the candidate experiment assignments
in \path{evidence/current-experiment-design.json}, and empty results in
\path{evidence/current-results-template.json}. Older evidence files remain
available for provenance, not as current case counts or budgets.

All 5,922 retained execution conditions pass fresh reference replay.
This proves witnessed feasibility under the executor. It does not prove
that every image is unambiguous, every adaptive event is visible, or
that models and humans can solve the tasks. The current release status
is program-checked with human image qualification pending. No paid model
API is called by the paper build, and no new model or human result is
imputed from a reference trajectory.

\section{Error Taxonomy and Structural Descriptors}
\subsection{Physical labels versus human-inspired causes}
E01--E07 denote missing pieces, excess pieces, wrong colors, wrong
parts, position/height offsets, non-equivalent orientations, and swapped
positional relations. Matching is physical rather than instance-based.
A replacement can create both a missing correct placement and an excess
wrong placement. A swap means changed positions, not mirrored physical
geometry. Direction changes equivalent under supported brick symmetries
are not orientation errors.

P01 marks premature covering that can block a later insertion. In a
static stage task, the same cover may simply be premature relative to
that stage target; only continued execution tests the access consequence.
P02 marks a buried defect with reference dismantling of correct layers.
A witness that removes covers does not prove every successful repair
must remove the same covers. Repetition omission remains a missing-piece
error with a process/cause tag. Simultaneous faults can have several
physical labels; they are not repeated temporal events.

T0--T3 record zero to three external interventions. Main D2 includes
43 tasks (37 T2, six T3); the broader catalogue has 47 repeated-event
tasks, including four archived-crop diagnostics. These populations must
not share an unexplained denominator.

Human-inspired tags H01--H11 and H13 are twelve approved categories
motivated by community reports. H12 and H14--H17 are excluded from the
current task selection; H18 remains deferred. The inventory is not a
live remaining-piece count, so no leftover-count reasoning claim is
made. Synthetic category balance is not an estimate of real human
mistake frequency, and online reports are not independently collected
participant trajectories.

\subsection{Migration labels and reference burdens}
The old static migration retained 3,025 source-linked records and replaced
267 incompatible cases. Its raw ledger contains 2,144 direct replays,
834 dismantle/rebuild witnesses, 37 held-component witnesses, ten corrected
board-penetrating starts, and 267 substitutions. This historical ledger
sums to 3,292 raw conditions and precedes the new deduplication.
Replacement-state labels are resolved using qualified candidate kinds
after physical multiset matching; they are not a new error class.
Height-layer cases map to actual displaced poses. No labelled static
error in the organized catalogue is physically equivalent to its target.

Build descriptors count the current target, not unused future pieces.
B1 is at most twelve active pieces, B2 is thirteen to twenty-four, and
B3 is at least twenty-five. R0 is a control. R1 has at most two
reference repair moves and no reference removal of correct covers.
R3 has such a removal or at least seven reference moves. R2 covers
remaining ordinary rework, including three to six moves and relevant
multiple-defect cases. These rules describe the available witness;
optimal repair search has not been proved.

The provisional grade is G3 if B3, T3, or both T2-or-more and R3.
Otherwise it is G2 if B2, R2/R3, or T2; the remaining tasks are G1.
Main counts are 2,577 G1, 2,823 G2, and 52 G3. Empirical model/human
results must validate these descriptors before calling them easy,
medium, and hard. Visibility remains an independent admission field;
invisibility is not merely a higher difficulty grade.

Each matched current/target scene is $800\times600$ pixels on a
$1600\times636$ comparison canvas. Native partial-manual pages can be
$1600\times1040$. Isometric, rear, and top views are available through
supported inspection. Named modules retain full-object context in both
current and target images. A publication crop does not redefine the
input framing. Actual image count, dimensions, hashes, and provider
processing must be logged per request; the number of images is not a
constant cost inferred from the number of scene roles.

The model receives neutral rules and anonymous action handles alongside
RGB. This is not pure image-only input. It does not receive raw pose
maps, error codes, family labels, reference correction actions, task type,
planned accidents, or hidden event times. The first decision identifies
that no prior action exists. Public names and image paths must not encode
the correct candidate. Observations are checked for prohibited fields.

\subsection{Direct actions and finite candidates}
A response is one JSON object. Examples are:
\begin{quote}\small\ttfamily
\{"type":"attach","partId":"A023",\\
\hspace*{1em}"candidate":"C00523"\}\\
\{"type":"detach","partId":"A023"\}\\
\{"type":"inspect","view":"top"\}\\
\{"type":"finish"\}
\end{quote}
These handles illustrate an interface, not universal answers. Attach and
detach each manipulate one physical part. Inspection can request a
supported view, part, preview, inventory page, or manual step. It does
not change geometry or itself trigger an accident. Multiple-action
scripts, hidden state replacement, and unsupported field combinations
are invalid in the default interface. Human participants operate
buttons; they do not type these objects or write explanatory text.

The main action space selects anonymous candidate poses. It is not
unrestricted six-degree-of-freedom prediction. Free coordinates require
another adapter and output-localization experiment. Likewise, text-state
and RGB-plus-state conditions are planned separately. Explicit state can
reveal occluded geometry, so such a comparison measures added state
information rather than equal-information modality alone.

\subsection{Physical checks and budgets}
Attachment checks supported pose/connection, endpoint collision, and a
straight insertion path. Detachment checks extraction. A rejection
changes no geometry; a later correct finish remains successful.
Feedback and candidate previews can aid planning and must be held
constant or ablated explicitly. Plain rectangular brick symmetries
are supported only where justified. Decorated and asymmetric pieces
are not assumed rotationally invariant. Terminal comparison fixes the
construction frame rather than globally aligning arbitrary assemblies.

The proposed comparison cap is $\max(40,6N+20)$ model decisions,
including inspections and malformed outputs. Applicable native caps,
such as the original module manipulation limit $4N+12$, remain
recorded. Native limits are not claimed identical across every engine.
A formal comparison must declare the effective caps per track before
running and use the same caps for every model on the same task.
A reference route is feasible, not necessarily shortest.

\section{Static Metrics in Detail}
Let $I,F,G$ denote initial, final, and target multisets of canonical
shape/color/symmetry-aware poses for movable pieces only. Immutable
context is excluded. The endpoint success indicator requires explicit
\texttt{finish} and $F=G$. A rejected physical request is not accepted
as a state transition; its existence does not invalidate a subsequent
successful completion. Model budget exhaustion is an unsuccessful
attempt, not an implicit finish at a correct intermediate snapshot.

\begin{align}
 \mathrm{TP}&=|F\cap G|,\quad \mathrm{FP}=|F-G|,\quad
 \mathrm{FN}=|G-F|,\\
 \mathrm{F1}_{\rm place}&=\frac{2\mathrm{TP}}{2\mathrm{TP}+\mathrm{FP}+\mathrm{FN}},\\
 E_0&=|G-I|+|I-G|,\quad E_T=|G-F|+|F-G|,\\
 \mathrm{ER}&=1-E_T/E_0,\\
 H&=I\cap G,\qquad \mathrm{DR}=|H-F|/|H|.
\end{align}
Undefined denominators are N/A. F1 of two empty multisets is defined
as one. ER can be negative. If a wrong-color brick is removed but its
correct-color counterpart is not installed, residual falls from two to
one: ER is 50\%, but exact SR is zero. This does not mean that one of
two human mistakes was fixed or that a globally shortest repair was used.

For S0 controls, FR records any accepted attach/detach during an
initially correct task. A remove-and-restore sequence has FR one and
can still finish correctly. DR instead records final damage only;
temporarily removing correct work to access a buried error does not
incur DR if restored. Normal acceptance, unnecessary manipulation,
and fault repair therefore need separate denominators.

Original missing recovery is
$|(F-H)\cap(G-I)|/|G-I|$.
Original excess clearance is
$1-| (F-G)\cap(I-G)|/|I-G|$.
Moving an excess brick to a different wrong pose can clear its original
excess signature while still failing the task; these are diagnostics,
not replacements for SR/F1. Type-plus-color, shape-plus-pose, and
color-plus-pose F1 expose attribute combinations, not independent
visual recognition accuracies. A uniform connection-adjacency F1 is
planned but not implemented in the common scorer.

\section{Dynamic Metrics and Pair Eligibility}
\subsection{Normal building and raw intervention outcomes}
BCR uses valid normal D0 runs. ICR uses valid D1/D2 runs assigned an
intervention, whether or not the event was reached. TR is actual events
over planned events, with per-task exposure counts. An untriggered
correct completion is raw completion, not successful repair. A partial
one-of-two exposure remains visible in the ledger and does not enter
all-event recovery. An empty recovery denominator is N/A.

C denotes future system-built checkpoint continuation. Its CSR measures
repair plus remaining completion from that checkpoint. The prefix must
be described as supplied by the system, not assembled by the model.
There is no independent C bank in this snapshot, and CSR cannot replace
D1/D2 continuous-construction evidence.

\subsection{Shared-prefix construction and incident effect}
Execute the common prefix once. Save environment state, conversation,
images, handle mapping, used budget, and random settings. Clone these
into control and intervention continuations at the admissible incident
opportunity. Keep targets, inventory, action vocabulary, budgets, and
model revision fixed. After branching, allow each continuation its own
legal order. Two separate normal/fault runs with the same nominal seed
are not verified shared-prefix pairs.

The eligible population $Q$ requires valid branches, verified shared
history, all planned events actually applied, and verified incident
effects. An event that removes an already-wrong brick or helps an
incorrect agent cannot automatically support a standard repair claim.
Record pre-existing errors and the realized edit. A correct future cover
can block assembly without adding a target residual; verify access
obstruction through the executor rather than demand a residual increase.
Adaptive event locations can have trajectory-dependent difficulty.

For $c_i,f_i\in\{0,1\}$ on $Q$, CRR is
$\sum_i c_i f_i/\sum_i c_i$. Its denominator excludes failed normal
branches. The signed paired difference is
$\Delta\mathrm{SR}=|Q|^{-1}\sum_i(c_i-f_i)$ and retains all four
outcome cells, including fault-only success. It can be negative.
Report planned pairs, technically valid branches, normal failures,
untriggered pairs, partial exposure, unverified effects, and eligible
counts. A high conditional rate with poor normal-build or exposure
coverage must not be presented alone.

\subsection{Multiple events and recovery while progressing}
For a realized event, let $B$ be the pre-event movable multiset and $A$
the post-event multiset. Relative to full target $G$, obligations are
\begin{equation}
 L=(B\cap G)-A,\qquad X=(A-G)-(B-G).
\end{equation}
At a later state, the lost correct quantities must be restored and the
incremental excess quantities removed. There is no requirement to
return exactly to $B$: legitimate new target placements are permitted.
Pre-existing agent defects remain separate. Windows end immediately
before the next external intervention so a later accident is not counted
as regression from the earlier repair.

Count all decisions, including inspections, invalid outputs, and physical
rejections, toward first-recovery latency. Report latency conditional
on observed recovery together with unrecovered proportion. Also report
window-end recovery and retention over at least two follow-up decisions.
An observed recurrence is a retention failure; a correct short window
is N/A with its sample count. An early-cover process error with no $L,X$
positions must not receive automatic zero latency. Use completion and
verified process measures instead. Repair@2/@4/@8 is reserved for
sufficiently observed single-event or checkpoint windows; next-event
and technical truncation are listed separately.

All-event D2 CRR requires successful normal control, all planned events,
verified effects, and terminal success. Per-event repair reports use
actual effective events and their windows. The two measures must not
be confused when a first repair succeeds but the second event is never
reached. The common metric functions implement eligibility and window
logic; formal batch-runner logging still needs integration.

\subsection{Detection is a separate task}
The continuous agent is not required to state whether it noticed an
anomaly. Failure can arise from perception, action selection, ordering,
or premature stopping. Successful recovery does not prove conscious
or explicit detection either. Independent detection uses fixed normal
and fault snapshots with balanced change/no-change coverage, and reports
precision, recall, F1, false-positive rate, and multilabel location-set
F1. It remains a planned task bank and must not interrupt the primary
assembly episode or manufacture detection labels from GT actions.

\section{Technical Status, Aggregation, and Cost}
\subsection{Ability failures and censored runs}
\texttt{completed} and \texttt{model\_budget\_exhausted} are ability-valid
statuses; the latter is a failure. A premature finish with a wrong target
is also failure. Final \texttt{service\_error}, \texttt{harness\_error},
and \texttt{external\_stop} do not receive ability scores. A transient
service error recovered at the same decision can lead to a valid completed
run; its charge and retry are retained. It is incorrect to censor every
completed attempt merely because one retry occurred.

Parsing failure, parsed-but-invalid schema/handles, and physical rejection
are separate events. Accepted attach/detach over well-formed manipulation
attempts defines legal-action rate. Every attempted request and decision
is retained in cost and failure reporting. Neither a 403/429/timeout nor
JSON-format failure should be relabeled as a visual error.

Report valid-run coverage and completed/planned-attempt operational rate
alongside ability SR. The latter planned denominator combines access
and task ability and must be named accordingly. All compared models
receive the same predeclared task list; service failures do not justify
substituting other tasks. A common-valid-subset analysis can be added
with its scope and N explicitly recorded.

\subsection{Aliases, macro aggregation, and uncertainty}
Group every result by model, input version, track, and task type.
Normalize canonical-task weights so duplicate control conditions and
interchangeable-ID records do not inflate performance. Average within
object and then across objects; additionally report source-macro results
by original set or design family. Task-micro rates are references.
Static S0 and S1, and dynamic normal/intervention tasks, remain separate.
Multilabel error rows cannot be summed as independent task populations.

Source-cluster bootstrap intervals are planned, with 2,000 group
resamples retaining variants and paired branches together. Sparse cells
remain descriptive. One attempt per model/condition does not establish
run-to-run stability. The common scorer implements grouping and macro
weights; source-clustered intervals have not yet been integrated into
formal model reporting.

\subsection{Requests, actions, and financial reporting}
Record accepted moves, all manipulation attempts, inspections, decisions,
requests, actual image count/dimensions, input/output tokens, wall time,
and billed dollars. Divide manipulation attempts by a feasible witness
only when that witness is nonzero. The ratio can be below one and is
not SPL or globally optimal efficiency. Report zero-witness S0 via FR.

Count shared prefixes once, both continuations, and billed retries or
failed calls. USD per successful task is N/A when none succeeds. A
service retry repeats the same request without silently restarting the
episode or selecting a better answer. The old 8,030-work-unit plan and
old budget estimates apply only to the historical snapshot. Current
financial estimates require a small current-interface pilot per selected
model and a declared admitted case list; no current dollar total is
asserted here.

\section{Reference and Historical Diagnostics}
\subsection{Replay and visibility admission}
The current replay audit has 5,922 passes and zero failures, including
aliases and controls. Source and reference hashes are retained. The
three complete LDraw objects have 36 faulty reference conditions and
ten controls. Every checked faulty condition changes at least 128 pixels
by at least 24 RGB levels in one of three $800\times600$ views.
These reference-image thresholds are machine screening, not human
perception guarantees.

Old M and expanded-module image checks used cropped framing. They do
not certify current full-context readability, and new adaptive locations
need their own observation-level check. Legacy low-contrast and
latest-action-cancellation flags are retained separately. A removed
newly installed part can make previous and current scenes equal,
requiring action-outcome monitoring rather than ordinary change detection.
Current-interface human qualification remains pending for all formal
perception claims.

\subsection{Historical alternative-order study}
The original twelve-module study uses two routes and four conditions
per route: control, missing piece, wrong color, and extra plate. Its
96 route--condition trials are not the current 5,720-task dataset.
Alternative routes were found by legal swaps and preferentially selected
to differ at the trigger threshold. Nine modules have a different
physical threshold state; three have a different order but the same
threshold state. This selection demonstrates regression cases, not
the distribution of a learned agent's orders.

Exact-reference triggers have opportunity on 36/36 reference-route and
9/36 alternative-route faults. Actual-state selectors trigger 36/36 in
both groups. Every normal route reaches the correct target, while a
comparator requiring every manual prefix accepts zero of twelve
alternatives. Blind continuation finishes 24/24 controls and 0/72 faults;
a privileged inverse-and-continue policy finishes 96/96. Privileged
state access makes this a reachability check, not a visual baseline.
The recorded source hashes and route indices support reproduction
without a model API.

\subsection{Human operation, efficiency, and failure ledger}
The proposed common panel selects twelve normal/fault pairs in each of
three scopes: static repair, whole-object dynamic, and named-module
dynamic. Its 36 pairs give 72 conditions. Six independent participants
operate 36 conditions each; each condition gets three submissions and
nobody sees both pair members. This is a plan for 216 operations, not
a completed measurement. Current-source case selection and new schedules
must be fixed after qualification; the old schedule is historical.

Humans see the same task information and use graphical actions without
prose or JSON. Train on separate practice scenes, balance normal/fault
assignments, and record completion, exposure, action count, time, and
optional unreadable/unusable buttons. Cluster human analyses by both
source and participant. Report actual independent submissions; verbal
agreement cannot be copied into additional participant rows.

E17 captures image/request/token/time/money and action effort for each
model and condition. E18 holds human and common-model outcomes. E19
retains service, schema, physics, normal-build, exposure, and budget
status. Read each rate with its valid/admitted/planned counts. A pilot
for the current input contract is needed before estimating the price
of full evaluation. No new API cost estimate or measured model rank
is asserted by these empty tables.




\section{Rendering, Attribution, and Remaining Limits}
All publication brick scenes are native $3200\times2400$ renders with
$2\times$ supersampling per dimension before downsampling. Composite
exports use 600 dpi; PDF/SVG labels and process elements remain vector.
The compact filmstrips use seven or eight scenes per row. Native
publication resolution does not replace evaluation input dimensions.
Orange boxes, correctness borders, and paper-only callouts are absent
from blind current-state input. Figure manifests record source hashes,
state/camera provenance, render pixels, and export hashes.

Original LDraw files retain authors, set IDs, URLs, and license headers.
Source-derived assets remain subject to their attribution and library
terms; community authorship is not reassigned. LEGO is a trademark of
its owner, with no claimed affiliation. A future public dataset card
must preserve source licenses and known reuse constraints.

Physical legality refers to the rigid geometric executor. Straight
insertion/extraction, finite candidates, fixed context, and conservative
bounds for unsupported surrounding meshes simplify real manipulation.
Articulated states are rigid poses; hinge motion, clutch forces,
flexibility, stability, slipping, and grippers are outside scope. No
real-robot performance follows from these replays. Only three whole
objects are complete original LDraw files, long community modules are
few, G3 is sparse, and untouched new sources remain to be acquired.

Before empirical claims, finish current-interface image/human admission,
pair-prefix/event-effect logging, repeated-event windows, API cost
collection, and source-clustered intervals. Build the independent C and
detection panels and alternative input/output adapters before filling
their tables. Program checks, metric tests, and a finished paper layout
are not evidence of CVPR acceptance or completed model evaluation.
