# 15 篇相关论文：这次补了什么，还缺什么

核对日期：2026-10-29。读了原论文的任务、实验、评估及相关附录，不只读摘要。下面包括 11 篇积木工作，以及 4 篇装配、交互或空间能力的相关工作；不是把它们全部叫作“积木修复 benchmark”，也不是全部都是 CVPR 论文。

## 一、逐篇对照

| 论文与原文 | 实际给模型什么／模型交什么 | 值得参考的章节或实验 | 我们这次如何采用 |
|---|---|---|---|
| [BrickGPT，ICCV 2025](https://arxiv.org/html/2505.05469) | 文字要求 → 积木结构 | 数据构建、稳定性和有效性、去掉关键组件的对照、人工及机器人装配 | 分开写“能合法执行”和“最终完成”；保留独立装配检查，不能只凭图好看来判断 |
| [BrickNet，CVPR 2026](https://arxiv.org/html/2604.22984) | 无条件或文字条件 → 带连接关系的装配序列 | 表示方法、连接标注、数据来源、随着步骤增加的有效性 | 解释我们的动作接口给了什么帮助；补全过程质量与停止行为分析 E30 |
| [BrickBench，2026 预印本](https://arxiv.org/html/2610.12452) | 文字设计要求 + 工具环境 → 可执行设计 | 环境消融、评分器与真人的一致性、人类设计对照 | 补简单策略、接口帮助和评分检查；不直接搬它的审美评分来判修复 |
| [MEPNet，ECCV 2022](https://arxiv.org/html/2207.12572) | 说明书图 + 当前结构及零件的 3D 表示 → 部件姿态 | 分零件／分步骤／整个物件的评估，镜头参数、完整过程图、素材授权 | 把最终成功、局部修好和完整过程分开；补实际输入输出图和全过程记录 |
| [SCANet，IROS 2024](https://arxiv.org/html/2403.18195) | 说明书图 + 已装部件的几何及姿态 → 正误判断和姿态修正 | 修正率、把原本正确件改坏的比例、混淆分析、输入组件消融 | 同时报告修好多少、改坏多少；动态失败不能直接解释成“没看见” |
| [Break and Make，ECCV 2022](https://arxiv.org/html/2207.13738) | 可交互观察和拆解目标 → 用低层动作重建 | 环境、不同粒度的结构评分、消融、失败例、人类基线、知识产权 | 明确主动观察不是我们的首创；重点放在同一世界中的静态修复到持续恢复 |
| [LEGO-Puzzles，2025](https://arxiv.org/html/2503.19990) | 积木图及问题／规划要求 → 答案、步骤或生成图，依子任务而异 | 分能力层级、质量控制、人类作答、评估提示词 | 题量不等于能力覆盖；人看 GT 和人盲做题必须分开 |
| [PhyBlock，2025](https://arxiv.org/html/2506.08708) | 场景及拼装目标／物理问题 → 计划或问答输出 | 依赖关系允许的多种顺序、局部完成、错误类别、不同背景及人类对照 | 补合法顺序一致性 E24；不要求每个中间状态和唯一 GT 完全一致 |
| [Brick-Composer / BC-Bench，2026](https://arxiv.org/html/2606.05445) | 说明图、候选零件图和装配视图 → 选件与姿态 | 分开评价选件、平移、旋转与联合成功；等价零件及对称性 | 明确有限位置编号减轻了定位负担；坐标接口不能未经匹配直接横比 |
| [WorkBenchMark，2026](https://arxiv.org/html/2606.19358) | 目标结构说明 + 视觉／机器人观测 → 计划和实际操作 | 环境配置、难度层级、成功率、连接准确性、时间、真实机器人 | 明确我们没有机器人抓取和力学模拟；独立检查可接受与不可接受动作 E25 |
| [BrickWright，2026 预印本](https://arxiv.org/html/2610.31651) | 文字或图片要求 + 装配 API／检查器 → 生成结构程序 | 工具对照、检查器误判复核、费用与时间、系统提示词 | 补“工具究竟帮了多少”和检查器误接收／误拒绝；独立核查不能只看成功参考路线 |
| [AssemblyBench，CVPR 2026](https://arxiv.org/html/2605.12845) | 图文说明书 + 部件点云 → 顺序和 6-DoF 运动轨迹 | 轨迹的物理可行性、不同步骤长度、说明书用户研究、视角选择 | 强化能否看清、能否真正拆装两条证据；最终形状正确不自动说明路径合法 |
| [AsgardBench，2026](https://arxiv.org/html/2603.15888) | 场景图、任务及轻量反馈 → 环境动作 | 终止原因、逐轮失败、记忆和当前图的消融、提示词及复现说明 | 补观察延迟 E22；区分旧图、当前图和观看者额外图，分开统计接口与能力失败 |
| [RoboRecover，2026](https://arxiv.org/html/2609.28952) | 不同来源的执行偏差／恢复点 → 继续操作 | 正常与恢复能力、阶段×错误、跨策略恢复、来源分组、置信区间 | 强化正常成功门槛、来源偏差、跨模型恢复 E14 和来源分组统计 E28 |
| [Spatial457，CVPR 2025](https://arxiv.org/html/2502.08636) | 场景图 + 空间问题 → 结构化答案 | 按能力增加难度、属性偏差、符号对照、真实图迁移 | 件数只叫长度，不冒充已验证难度；补属性／来源覆盖和受控输入对照 |

## 二、从这些论文中看到的共性

不是每篇都必须拥有下列所有章节；这是针对我们论文的选择。

| 审稿人会问什么 | 原先薄弱之处 | 这次论文中的处理 | 还要真的做什么 |
|---|---|---|---|
| 你到底在测什么？ | 动态容易看成一串静态题 | Arena 状态转移公式、主动观察、隐藏干扰和信息边界 | 用相同故障状态对比新求解者与持续运行模型，E29 |
| 比已有恢复工作多了什么？ | 容易把交互或修复本身当创新 | Related Work 增加恢复、装配 API 和机器人基准；限定贡献范围 | 靠静态到动态的受控结果证明价值，不靠更大题数 |
| 模型怎样成功、怎样失败？ | 只有程序参考图 | 真实小汽车成功、椅子失败，各配同一现场的 GT 续接 | 之后用当前 Arena v3 的代表性结果替换旧版开发案例 |
| 是模型不行，还是题看不清？ | 重放只能证明程序能执行 | 实际模型输入图；盲做与看 GT 分开；E26 | 独立真人用模型权限看图并操作，记录具体看不清位置 |
| 裁判是不是偏向你的 GT？ | 主要是参考序列通过 | 非唯一顺序、同型件交换、拆后装回等 E24 | 按变换配对检查，不只检查原 GT |
| 物理规则本身靠谱吗？ | 生成与检查共用实现 | E25 同时检查误接收和误拒绝 | 另一个实现或独立熟悉装配的人检查有效和无效动作 |
| 工具给了多少答案？ | 候选编号、说明书的帮助没单独量化 | 简单策略 E20、帮助阶梯 E21、输入／动作消融 | 公平主结果只用普通输入；给答案提示的结果单列 |
| 得分高会不会只是题挑得容易？ | 条件恢复率可能只剩少量简单题 | BCR、入选分母、全体和共同对象结果 | 每个模型公开完整尝试及排除记录，E28 |
| 结果能推广吗？ | 所有当前来源均已参与开发 | 明说来源暴露；E27 新来源实验 | 真正找开发时没用过的来源并先检查题目 |
| 能复现和公开吗？ | 输入、日志、许可容易散落 | 轨迹来源哈希、实际 JSON、数据来源与发布责任 | 确认每个来源可如何再发布；保留版本、模型设置和费用 |

## 三、当前论文主线

**在允许多种合法拼装顺序的积木环境中，测模型从“修好给定错误状态”，到“自己持续拼装、主动查看并在变化后恢复”的能力。**

库存不足、少件、错色、封口、返修和多次干扰是测试这种能力的条件，不分别冒充独立创新。

## 四、论文现在可以写丰富，但不能写成已经证明

- 已有证据：310 个可运行物件、4,685 题、参考重放、图像资产检查、替代顺序检查、脚本 Arena 检查。
- 本次新增实证展示：两条真实旧版 API 日志逐动作复核；对同一干扰现场生成合法 GT 续接；没有新增付费请求。
- 当前仍缺：新版模型主实验、独立真人盲做、独立拆装规则核查，以及未参与开发的新来源测试。
- 空表是待执行的实验设计，不是零分，更不是实验已完成。增加页面和图不能替代这些证据，也不能保证 CVPR 录取。
