## 这版重新写了什么

论文覆盖全部当前静态和动态内容，包含原来的 127 种静态配置和 30 个动态结构；12 个社区模块是新增的一部分。合计 5,260 条当前题目记录，不把重复保留的旧版题数再加一次。

论文围绕一个具体问题展开：同一个物件可以有多种合法拼法，不能因为中间顺序不同就判错，也不能因为没走到指定的参考中间状态就跳过干扰。

任务定义说清楚了：模型拿到什么目标图、说明书、当前图和上一状态图；一步只能操作一个积木；哪些动作会被拒绝；干扰如何根据实际状态发生；最后怎么判断完成、遇到干扰和修复成功。静态题的阶段目标与动态题的最终目标分开说明。

数据按真实范围报告：

| 部分 | 数量 | 已完成的检查 |
|---|---:|---|
| 白色底板静态题 | 3,292 题、160 种配置 | 所有参考修复动作能执行；完整图片题包与逐题人审还没完成 |
| 动态错误机制题 | 1,872 题、68 种结构，其中 42 个简化物件 | 几何重放、正常对照和可修复性检查；还没有正式模型与真人操作实验 |
| LDraw 社区模块题 | 12 个物件、96 题 | 99 步说明书、原始模型来源、接口与替代顺序检查 |

这次实际执行了 **96 个路线与条件组合的程序实验**：每个社区物件用参考路线、另一条合法路线，分别跑正常、拆件、换色和加层。替代路线中，依赖参考中间状态的触发方式只覆盖 9/36 次干扰机会；按实际状态选择干扰能覆盖 36/36。替代路线是特意选出的回归例子，不是随机路线样本，更不是 AI 的成功率。

程序照原路线继续、不处理错误：正常 24/24 完成，错误 0/72 完成。程序能读正确答案并按合法步骤修复：96/96 完成。这证明这些例子确实会受干扰、也确实能修好；不证明模型会发现并修好。

## 实验已经设计到哪一步

正文预留主结果、输入对比两张表；补充材料预留五张分析表。5 个模型各重复 3 次，另有 6 人、216 次独立操作的小面板。所有未测值保持为空。

检查题目分组时，发现静态迁移替换后有 151 个题号仍使用旧来源分组；本次已按当前模型来源修正。现在训练/开发/测试分别为 2,286 / 539 / 467 题。新的分组见 `deliverables/brickplan-static-plate5/splits.json`，旧文件只作历史记录。具体题号、分支规则、错误类别、预算计算及填表位置见上面的实验指南。

## 按什么模板排版

参考此前指定的 BrickNet，采用第一页物件总览、双栏正文、任务定义、构造方法、协议实验、局限的组织方式，文字和图均为本项目重新撰写/生成。

使用未修改的 [CVPR 官方 author kit](https://github.com/cvpr-org/author-kit) 2026 样式，稿件年份暂写 2027、Paper ID 暂写 Draft。[2026 规则](https://cvpr.thecvf.com/Conferences/2026/AuthorGuidelines)要求正文最多 8 页，参考文献可另计。正式投稿前还要核对当届最终模板和规则。排版、高清图和程序检查不能代替审稿，也不能保证录取。

## 重新编译

已有项目 Python 环境时，从仓库根目录执行：

```bash
benchmark/.runtime/mlx-env/bin/python paper/brickplan-cvpr/build.py
```

编译需要 Tectonic；Python 核对依赖见 [requirements-paper.txt](requirements-paper.txt)。脚本优先从 PATH 或环境变量 `TECTONIC` 找编译器，也支持用户目录 `.local/bin/tectonic`。输出正文、补充材料和 Overleaf ZIP。

重新做离线协议实验、重新渲染图：

```bash
benchmark/.runtime/mlx-env/bin/python paper/brickplan-cvpr/build.py --study --refresh-figures
```

后一个命令额外需要项目已有的 BrickNet 连接/碰撞数据、MeshLib、原始 LDraw 零件库和 C 编译器。它不调用模型 API。普通编译直接用仓库里的图，不需要重建这些资源。外部资源和许可证见 [运行依赖说明](RUNTIME-DEPENDENCIES.md)。

上传 Overleaf 时解压 ZIP，选择 `main.tex`；编译补充材料时改选 `supplement.tex`。ZIP 不包含模型密钥、个人审查记录或本地环境。
